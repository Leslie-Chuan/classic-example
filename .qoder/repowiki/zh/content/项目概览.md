## 简介
本项目是一个围绕 Model Context Protocol（MCP）的学习与演示平台，采用 Next.js 构建前端学习站点，并通过独立的 MCP 示例服务（Node/TypeScript）展示如何以 MCP 协议暴露工具、资源与提示词。项目目标包括：
- 帮助初学者理解 MCP 的核心概念（工具、资源、提示词、客户端与服务端交互）。
- 为有经验的开发者提供可运行的最小实现与集成模式。
- 通过“按天”组织的学习内容与交互式 Playground，逐步掌握 MCP 的使用方式。

本项目的关键特性：
- 基于 Next.js App Router 的页面组织，支持按日期查看学习内容。
- 内置 MCP Playground 组件，用于在浏览器中体验 MCP 工具调用。
- 独立 demos 目录包含一个文件系统 MCP 服务端与测试客户端，便于本地运行与调试。
- 使用 Markdown 内容管理每日学习笔记，并提供解析与渲染能力。

## 项目结构
项目采用前后端分离的组织方式：
- 前端：Next.js 应用，负责展示学习内容、交互式 Playground 与进度追踪。
- 演示后端：demos 目录下的 MCP 示例服务，提供文件系统访问等工具。
- 内容层：content 目录存放按日期的 Markdown 笔记，供前端渲染展示。

## 架构总览
整体架构分为三层：
- 表现层（Next.js 前端）：提供用户界面与交互，包括首页、按天学习页与 MCP Playground。
- 业务层（Hook 与库）：封装 MCP 工具调用、内容读取与 Markdown 渲染。
- 数据与演示层（MCP 示例服务）：提供文件系统访问等 MCP 工具，供前端 Playground 调用。

## 性能考量
- 内容加载优化
  - 按日期懒加载 Markdown 内容，避免一次性加载全部笔记。
  - 使用缓存策略减少重复解析开销（可在 markdown.ts 中扩展）。
- 网络与连接
  - 复用 MCP 客户端连接，避免频繁握手。
  - 对工具调用进行超时与重试控制，提升稳定性。
- UI 渲染
  - 将复杂计算放入 Hook 或 Web Worker，避免阻塞主线程。
  - 使用虚拟滚动或分页展示大量工具或历史记录。

## 故障排查指南
- 常见问题
  - MCP 服务未启动或端口不可达：检查 file-system-server.ts 是否正常运行与监听端口。
  - 工具调用失败：确认 useMCPTool.ts 的连接与错误处理逻辑是否正确。
  - 内容无法渲染：检查 content/daily 目录下是否存在对应日期的 Markdown 文件，以及 markdown.ts 的配置。
- 调试建议
  - 使用浏览器开发者工具观察网络请求与错误日志。
  - 在 test-client.ts 中手动调用工具，验证服务端行为。
  - 在 Next.js 控制台查看构建与运行时错误。
