## 1. 使用的系统与工具

仓库采用 **npm**（Node.js 官方包管理器）作为统一的依赖管理方案，并通过 **package-lock.json** 锁定精确版本，确保构建可重现。项目包含两个独立的 npm 包：
- 根目录 `ai-learning-lab`：Next.js 学习仪表盘应用。
- `demos/day1-mcp/mcp-day1`：MCP 协议入门示例的独立子包。

## 2. 关键文件与包

- `package.json`（根）：声明 Next.js 应用的生产/开发依赖，包括 `next@16.3.0`、`react@19.2.8`、`react-dom@19.2.8`、`shiki^3.7.0`、`gray-matter^4.0.3`、`date-fns^4.1.0`，以及 `eslint-config-next@16.3.0`、`tailwindcss^4`、`typescript^5` 等开发依赖。
- `package-lock.json`（根）：lockfileVersion 为 3，记录所有依赖的精确解析结果与 sha512 integrity hash。
- `demos/day1-mcp/package.json`：独立子包，仅依赖 `@modelcontextprotocol/sdk^1.12.1`，通过 `tsx` 运行 TypeScript 脚本。
- `demos/day1-mcp/package-lock.json`：子包的独立锁文件。
- `.gitignore`：排除 `node_modules/`，不提交依赖树。

## 3. 架构与约定

- **多包结构**：主应用与演示代码各自维护独立的 `package.json` 与 `package-lock.json`，互不共享依赖，避免跨包版本冲突。
- **版本范围策略**：生产依赖使用 `^` 语义化版本（如 `shiki^3.7.0`），允许小版本自动升级；框架核心依赖（`next`、`react`、`react-dom`、`eslint-config-next`）使用固定版本号，保证主应用稳定性。
- **Lockfile 强制一致性**：根目录存在 `package-lock.json`，CI/本地安装均基于该锁文件解析，确保依赖图可重现。
- **无 vendoring**：未使用 `vendor/` 或类似目录，依赖全部从 npm 公共注册表下载并缓存至 `node_modules/`。
- **无私有注册表配置**：未发现 `.npmrc`、`pnpm-workspace.yaml`、`yarn.lock` 或自定义 registry 配置，默认使用 npm 官方源。

## 4. 约定与约束

- 新增第三方库需在对应包的 `dependencies` 或 `devDependencies` 中声明，不可直接引入未声明的包。
- 修改依赖后应提交更新后的 `package-lock.json`，以保证团队构建一致。
- 演示子包保持最小依赖（仅 `@modelcontextprotocol/sdk` 与 `tsx`），便于单独运行与测试。
- 根包标记为 `"private": true`，表明该包仅供本地/内部使用，不发布到 npm 公共仓库。
- 通过 `scripts` 中的 `dev`、`build`、`start`、`lint` 命令统一入口，依赖安装由 npm 在首次 `npm install` 时完成。
