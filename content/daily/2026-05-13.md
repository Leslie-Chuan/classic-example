## 核心概念（5 分钟精读）

### 1. ReAct 模式：不只是调用 API，而是「先想后做」

2022 年 Google 提出的 ReAct（Reasoning + Acting）框架，核心发现是：**让 LLM 把思考过程显式输出为文本，再决定执行哪个工具，准确率比直接生成工具调用高 30% 以上**。

传统方式：
```
用户提问 → LLM 直接输出答案（或工具调用 JSON）
```

ReAct 方式：
```
用户提问 → LLM 输出思考过程（Thought）→ 输出工具调用（Action）→
执行工具 → 获得观察结果（Observation）→ LLM 再次思考 → ... → 输出最终答案
```

这个循环就是 **Agent Loop**。

### 2. Agent Loop 的三阶段

| 阶段 | 职责 | 类比前端开发 |
|------|------|-------------|
| **Perceive（感知）** | 接收用户输入 + 工具返回的 Observation | 组件接收 props + 服务端响应 |
| **Think（思考）** | LLM 基于上下文生成 Thought，分析当前状态 | React 的 render 阶段，计算下一个状态 |
| **Act（行动）** | 根据 Thought 决定：调用工具，或输出最终答案 | 执行 effect / 调用 API |

**循环终止条件**：LLM 决定不再调用工具，而是直接回答用户。

### 3. Tool Use / Function Calling 的底层机制

LLM 本身没有「调用函数」的能力。所谓 Tool Use，其实是一个**结构化生成**问题：

1. 你在请求中传入一组工具定义（名称、描述、参数 Schema）
2. LLM 根据当前上下文，生成一段符合 Schema 的 JSON
3. **你的代码**解析这段 JSON，执行对应的本地函数
4. 把执行结果拼接回对话上下文，再次发给 LLM

关键点：**LLM 只负责「决定做什么」，不负责「实际做」**。实际执行发生在你的 Node.js / Python 进程中，这意味着你可以让 Agent 执行任何代码——包括读写文件、调用数据库、操作 Git。

### 4. 为什么前端开发者要特别关注 Agent Loop？

- **AI 编码工具的底层**：Claude Code、Cursor Composer 本质上就是一个持续运行的 Agent Loop，感知当前文件树，思考修改策略，执行文件编辑工具。
- **前端特有的工具集**：组件文档检索、AST 分析、设计 Token 匹配、Lighthouse 性能检测——这些都可以封装成 Agent 的 Tools。
- **流式 UI 的前置知识**：下一模块会讲 Streaming UI，而流式输出的内容通常就是 Agent 的 Thought 过程实时展示。

## 代码实践（15 分钟）

### 目标

实现一个 `MiniReActAgent`：
- 支持注册任意工具（Tool）
- 支持多轮 ReAct 循环
- 使用模拟 LLM 接口（无需真实 API Key，内置简单的规则引擎模拟推理过程）
- 包含两个实用工具：`readFile` 和 `analyzeReactComponent`

### 完整可运行代码

创建一个文件 `mini-react-agent.js`：

```javascript
/**
 * MiniReActAgent —— 150行纯Node.js实现ReAct循环 + Tool Use
 *
 * 运行方式：node mini-react-agent.js
 * 无需API Key，内置模拟LLM用于演示循环机制
 * 核心目标：理解Agent Loop的底层控制流
 */

const fs = require('fs');
const path = require('path');

// ==================== 工具注册表 ====================
class ToolRegistry {
  constructor() {
    this.tools = new Map();
  }

  register(name, description, parameters, fn) {
    this.tools.set(name, { name, description, parameters, fn });
  }

  getSchemas() {
    return Array.from(this.tools.values()).map(({ name, description, parameters }) => ({
      name,
      description,
      parameters,
    }));
  }

  async execute(name, args) {
    const tool = this.tools.get(name);
    if (!tool) throw new Error(`Tool '${name}' not found`);
    return tool.fn(args);
  }
}

// ==================== 模拟LLM（用于演示循环机制）====================
class MockLLM {
  constructor() {
    this.step = 0;
  }

  /**
   * 模拟LLM的推理过程。
   * 真实场景中，这里会调用OpenAI/Claude API，传入system prompt + 历史消息。
   * 我们通过规则引擎模拟ReAct的Thought -> Action -> Observation循环。
   */
  async complete(messages, tools) {
    const userQuery = messages.find(m => m.role === 'user')?.content || '';
    const observations = messages
      .filter(m => m.role === 'observation')
      .map(m => m.content);

    // 模拟推理逻辑：根据用户问题和已有观察结果决定下一步
    if (userQuery.includes('分析') && userQuery.includes('组件') && !observations.length) {
      return {
        thought: '用户要求分析React组件。我需要先读取组件文件的内容，然后分析其props和hooks使用情况。',
        action: { name: 'readFile', arguments: { filePath: './demo-component.jsx' } },
        finish: false,
      };
    }

    if (observations.length === 1 && observations[0].includes('function DemoComponent')) {
      return {
        thought: '我已经读取了组件文件，现在需要使用AST分析工具来提取组件的props定义和hooks调用。',
        action: { name: 'analyzeReactComponent', arguments: { code: observations[0] } },
        finish: false,
      };
    }

    if (observations.length === 2) {
      return {
        thought: '我已经获得了组件的分析结果，可以综合给出回答了。',
        action: null,
        finish: true,
        answer: observations[1], // 直接返回分析结果作为最终答案
      };
    }

    // 默认兜底
    return {
      thought: '我无法判断用户的具体意图，尝试直接回答。',
      action: null,
      finish: true,
      answer: '请提供更明确的指令，例如"分析某个React组件"。',
    };
  }
}

// ==================== Agent核心：ReAct循环 ====================
class MiniReActAgent {
  constructor(llm) {
    this.llm = llm;
    this.tools = new ToolRegistry();
    this.maxIterations = 5; // 安全边界：防止无限循环
    this.registerDefaultTools();
  }

  registerDefaultTools() {
    // Tool 1: 读取文件内容
    this.tools.register(
      'readFile',
      '读取指定路径的文本文件内容。适用于获取代码文件、配置文件等。',
      {
        type: 'object',
        properties: {
          filePath: { type: 'string', description: '相对于当前工作目录的文件路径' },
        },
        required: ['filePath'],
      },
      async ({ filePath }) => {
        const fullPath = path.resolve(filePath);
        // 安全边界：只允许读取当前目录下的文件
        if (!fullPath.startsWith(process.cwd())) {
          throw new Error('Security: 禁止读取工作目录之外的文件');
        }
        try {
          return fs.readFileSync(fullPath, 'utf-8');
        } catch (e) {
          return `Error reading file: ${e.message}`;
        }
      }
    );

    // Tool 2: 分析React组件（简化版AST分析）
    this.tools.register(
      'analyzeReactComponent',
      '分析React组件代码，提取props定义、hooks使用、组件复杂度等指标。',
      {
        type: 'object',
        properties: {
          code: { type: 'string', description: 'React组件的完整源代码' },
        },
        required: ['code'],
      },
      async ({ code }) => {
        const propsMatch = code.match(/function\s+\w+\s*\(\s*\{\s*([^}]+)\s*\}/);
        const props = propsMatch
          ? propsMatch[1].split(',').map(p => p.trim().split(':')[0].split('=')[0].trim()).filter(Boolean)
          : [];

        const hooks = (code.match(/use[A-Z][a-zA-Z]+/g) || []);
        const hasUseEffect = hooks.includes('useEffect');
        const hasUseState = hooks.includes('useState');
        const lines = code.split('\n').length;

        return JSON.stringify({
          props,
          hooks: [...new Set(hooks)],
          hasUseEffect,
          hasUseState,
          lineCount: lines,
          complexity: lines > 50 ? 'medium' : 'low',
          suggestion: hasUseEffect && lines > 60
            ? '建议：该组件包含副作用且代码较长，考虑拆分为容器组件和展示组件。'
            : '组件结构良好。',
        }, null, 2);
      }
    );
  }

  async run(userQuery) {
    const messages = [
      {
        role: 'system',
        content: `你是一个高级前端代码分析助手。你可以使用以下工具：\n${JSON.stringify(
          this.tools.getSchemas(),
          null,
          2
        )}\n\n你必须遵循ReAct格式：先思考（Thought），再决定行动（Action）。`,
      },
      { role: 'user', content: userQuery },
    ];

    console.log('━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━');
    console.log('🚀 Agent Loop 启动');
    console.log(`👤 用户输入：${userQuery}`);
    console.log('━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━\n');

    for (let i = 0; i < this.maxIterations; i++) {
      // Step 1: Think —— LLM 推理
      const response = await this.llm.complete(messages, this.tools.getSchemas());

      console.log(`\n--- 第 ${i + 1} 轮 ---`);
      console.log(`💭 Thought: ${response.thought}`);

      // Step 2: Act —— 执行工具或结束
      if (response.finish || !response.action) {
        console.log(`\n✅ 循环结束，输出最终答案：`);
        console.log(response.answer);
        return response.answer;
      }

      const { name, arguments: args } = response.action;
      console.log(`🔧 Action: 调用工具 "${name}"，参数：${JSON.stringify(args)}`);

      // Step 3: Observe —— 执行工具并观察结果
      const observation = await this.tools.execute(name, args);
      console.log(`👁️  Observation: ${observation.slice(0, 200)}${observation.length > 200 ? '...' : ''}`);

      // 将观察结果加入上下文，驱动下一轮推理
      messages.push(
        { role: 'assistant', content: response.thought },
        { role: 'observation', content: observation }
      );
    }

    throw new Error('达到最大迭代次数，Agent未能完成任务。请检查是否存在循环依赖或工具设计问题。');
  }
}

// ==================== 演示：创建测试组件并运行Agent ====================
function createDemoComponent() {
  const demoCode = `import React, { useState, useEffect } from 'react';

function DemoComponent({ title, items, onItemClick, maxCount = 10 }) {
  const [filtered, setFiltered] = useState([]);

  useEffect(() => {
    const result = items.slice(0, maxCount).filter(item => item.active);
    setFiltered(result);
  }, [items, maxCount]);

  return (
    <div className="demo">
      <h2>{title}</h2>
      <ul>
        {filtered.map(item => (
          <li key={item.id} onClick={() => onItemClick(item)}>
            {item.name}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default DemoComponent;
`;
  fs.writeFileSync('./demo-component.jsx', demoCode);
  console.log('📝 已创建测试组件：./demo-component.jsx\n');
}

// ==================== 主入口 ====================
(async () => {
  // 准备测试环境
  createDemoComponent();

  // 初始化Agent
  const agent = new MiniReActAgent(new MockLLM());

  // 运行Agent
  try {
    await agent.run('请分析当前目录下的 demo-component.jsx 组件，给出结构评估。');
  } catch (err) {
    console.error('❌ Agent执行失败:', err.message);
  }

  // 清理
  fs.unlinkSync('./demo-component.jsx');
  console.log('\n🧹 已清理测试文件');
})();
```

### 关键代码解读

1. **`ToolRegistry`**：工具不是零散函数，而是带有 JSON Schema 描述的注册表。LLM 正是通过 Schema 理解每个工具能做什么、需要什么参数。
2. **安全边界**：`readFile` 工具中检查了 `fullPath.startsWith(process.cwd())`，这是 Agent 安全的第一道防线——**所有工具都必须内置权限校验**。
3. **`maxIterations`**：防止 Agent 陷入死循环。真实产品中，还需要超时控制、Token 预算、用户中断机制。
4. **上下文拼接**：每一轮的 Thought 和 Observation 都追加到 `messages` 数组中。这就是为什么 Agent 能「记得」之前做了什么——**不是 LLM 有记忆，是你的代码在帮它维持记忆**。

## 思考题（5 分钟）

### 问题一：在你的前端工作流中，哪些环节适合嵌入 Agent Loop？

不要泛泛而谈「代码生成」。具体思考：
- **Code Review**：Agent 读取 PR diff → 调用 ESLint / TypeScript 检查工具 → 读取相关文件理解上下文 → 输出 review 意见。这个循环里，Observation 是什么？什么情况下应该终止循环？
- **组件重构**：Agent 分析一个 500 行的旧组件 → 发现它用了 3 个 useEffect → 调用拆分工具生成子组件 → 验证子组件是否能独立运行。如果验证失败，Agent 应该回滚还是重试？

请结合你当前团队的技术栈，列出 **2 个具体的、可以落地的 Agent 应用场景**，并画出它们的 Loop 流程（文字描述即可）。

### 问题二：Tool Use 的权限边界应该如何分层设计？

上面的示例中，`readFile` 只做了路径前缀校验，但这远远不够。假设你正在构建一个给全团队使用的内部 Agent：

- 初级开发者使用 Agent 时，应该允许它修改 `node_modules` 吗？应该允许它执行 `rm -rf` 吗？
- 如果 Agent 有一个 `writeFile` 工具，如何防止它覆盖别人的代码？如何审计它的每一次文件修改？
- 更进一步：如果 Agent 可以调用 Git 命令（`git commit`, `git push`），谁来为它的提交负责？

请设计一个**分层权限模型**（至少三层：只读层、受写层、管理操作层），并说明每一层适合注册哪些工具、需要哪些额外安全措施。
