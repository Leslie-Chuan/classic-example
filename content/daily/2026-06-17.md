## 核心概念（15分钟阅读与理解）

### 1. 为什么需要 RAG？

传统 LLM 有两个核心局限：

- **知识截止日期**：模型训练数据有截止时间，无法获取最新信息
- **幻觉问题**：模型会「编造」看似合理但实际错误的答案

RAG 的解决思路：**不修改模型本身，而是在提问前，先帮模型「查资料」**。

### 2. RAG 的完整流程

```
用户提问
   ↓
【检索阶段】
  1. 将问题转为向量（Embedding）
  2. 在向量数据库中搜索最相似的文档片段
  3. 返回 Top-K 相关文本块
   ↓
【增强阶段】
  4. 将检索结果 + 原始问题 拼接成 Prompt
   ↓
【生成阶段】
  5. LLM 基于「检索到的真实内容」生成回答
   ↓
输出带引用来源的答案
```

> 💡 关键点：RAG 不是替代模型，而是给模型装了一个「外接大脑」——随时查阅、有据可依。

### 3. RAG vs 微调（Fine-tuning）

| 维度 | RAG | 微调 |
|------|-----|------|
| 知识更新 | 实时（改数据库即可） | 需要重新训练 |
| 成本 | 低（查询向量库） | 高（GPU训练） |
| 幻觉控制 | 强（有来源可追溯） | 中等（依赖训练质量） |
| 适用场景 | 知识库问答、客服、文档助手 | 风格迁移、垂直领域能力 |
| 前端角色 | 搭建检索系统 + 渲染结果 | 较少直接参与 |

> 对前端开发者而言，RAG 是更实际、更可控的技术路线。

### 4. 前端视角下的 RAG 架构

```
┌─────────────────────────────────────────┐
│           前端应用层 (React/Vue)          │

│  └────┬────┘  └────┬────┘  └────┬────┘ │
└───────┼────────────┼────────────┼──────┘
        ↓            ↑            ↑
┌───────┴────────────┴────────────┴──────┐
│           API 层 (Node.js/Python)        │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐ │
│  │ 查询路由 │  │ Embedding│  │ LLM调用 │ │

        ↓            ↓            ↑
```

### 5. 评估 RAG 效果的核心指标

- **召回率（Recall）**：相关文档是否被检索到
- **精确率（Precision）**：检索结果中有多少是真正相关的
- **答案相关性（Answer Relevance）**：生成答案与问题的匹配度
- **上下文相关性（Context Relevance）**：检索片段与问题的匹配度
- **忠实度（Faithfulness）**：答案是否忠实于检索到的原文

## 代码实践（10分钟动手）

### 实践任务：用 JavaScript 实现一个最小 RAG 流程

下面是一段可在 Node.js 环境中运行的伪代码，展示了 RAG 的核心逻辑：

```typescript
// === 最小 RAG 实现（概念验证版）===

// 1. 模拟 Embedding 服务（实际调用 OpenAI / 开源模型）
async function embed(text: string): Promise<number[]> {
  // 实际：调用 embedding API（如 text-embedding-3-small）
  // 返回 1536 维向量
  return new Array(1536).fill(0).map(() => Math.random() - 0.5);
}

// 2. 模拟向量数据库（实际用 Pinecone / Milvus / pgvector）
class VectorStore {
  private docs: Array<{ text: string; vector: number[]; source: string }> = [];

  async add(text: string, source: string) {
    const vector = await embed(text);
    this.docs.push({ text, vector, source });
  }

  // 余弦相似度计算
  cosineSimilarity(a: number[], b: number[]): number {
    const dot = a.reduce((sum, val, i) => sum + val * b[i], 0);
    const magA = Math.sqrt(a.reduce((sum, val) => sum + val * val, 0));
    const magB = Math.sqrt(b.reduce((sum, val) => sum + val * val, 0));
    return dot / (magA * magB);
  }

  async search(query: string, topK: number = 3) {
    const queryVector = await embed(query);
    return this.docs
      .map(doc => ({
        ...doc,
        score: this.cosineSimilarity(queryVector, doc.vector)
      }))
      .sort((a, b) => b.score - a.score)
      .slice(0, topK);
  }
}

// 3. RAG 核心流程
class RAGSystem {
  constructor(
    private vectorStore: VectorStore,
    private llmQuery: (prompt: string) => Promise<string>
  ) {}

  async ask(question: string): Promise<{ answer: string; sources: string[] }> {
    // Step 1: 检索
    const retrievedDocs = await this.vectorStore.search(question, 3);
    const context = retrievedDocs.map(d => d.text).join("\n\n---\n\n");
    const sources = [...new Set(retrievedDocs.map(d => d.source))];

    // Step 2: 构建增强 Prompt
    const prompt = `
基于以下参考资料回答问题。如果资料中没有相关信息，请明确说明。

参考资料：
${context}

用户问题：${question}

请给出简洁准确的回答，并在最后列出参考来源。
    `.trim();

    // Step 3: 生成
    const answer = await this.llmQuery(prompt);
    return { answer, sources };
  }
}

// === 使用示例 ===
async function demo() {
  const store = new VectorStore();

  // 录入知识库（实际来自文档解析、网页抓取等）
  await store.add(
    "React Server Components 允许组件在服务器端渲染，减少客户端 JS 体积。",
    "React官方文档"
  );
  await store.add(
    "Next.js 15 已稳定支持 React 19 的 Server Components 和 Actions。",
    "Next.js发布说明"
  );
  await store.add(
    "流式输出（Streaming）可以让 LLM 的响应像打字一样逐字显示。",
    "Vercel AI SDK文档"
  );

  const rag = new RAGSystem(store, async (prompt) => {
    // 实际：调用 OpenAI / Claude / 本地模型 API
    return "[模拟回答] 根据 React 官方文档...";
  });

  const result = await rag.ask("React Server Components 有什么好处？");
  console.log(result.answer);
  console.log("来源:", result.sources);
}
```
