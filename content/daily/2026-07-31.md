## 一、核心概念（约 12 分钟）

### 1. 什么是 AST，为什么前端工程师需要懂它？

AST（Abstract Syntax Tree，抽象语法树）是源代码在编译器内部的数据结构表示。Babel、TypeScript、ESLint、Webpack、Vite 等工具都依赖 AST 完成：

- **转译**：把 JSX / TypeScript / 新语法转换成兼容代码
- **代码检查**：ESLint 规则、代码规范自动化
- **代码生成**：文档自动生成、测试用例自动生成、AI 辅助编码
- **构建优化**：Tree Shaking、代码压缩、按需加载

对于高级前端工程师，AST 是从「使用工具」跨越到「改造工具、理解工具原理」的关键门槛。

### 2. Babel 的编译管线

Babel 本质上做三件事：

```text
源代码（Source）
    ↓
@babel/parser 解析 → AST
    ↓
@babel/traverse 遍历 + plugin 转换 → 新 AST
    ↓
@babel/generator 生成 → 目标代码
```

核心包职责：

| 包名 | 作用 |
|------|------|
| `@babel/parser` | 把 JS/TS/JSX 源码解析成 AST |
| `@babel/traverse` | 遍历 AST，提供 visitor 入口 |
| `@babel/types` | 创建 / 校验 AST 节点 |
| `@babel/generator` | 把 AST 还原成代码字符串 |
| `@babel/template` | 用模板字符串快速生成 AST 片段 |
| `@babel/core` | 整合以上能力，提供 `transformSync` 等 API |

### 3. Visitor 模式

Babel 插件通过 **visitor** 声明对哪些节点感兴趣。例如：

```js
const plugin = {
  visitor: {
    Identifier(path) {
      // 每个 Identifier 节点都会进入这里
      console.log(path.node.name);
    }
  }
};
```

visitor 中的 key 对应 AST 节点类型（如 `CallExpression`、`FunctionDeclaration`、`JSXAttribute`），value 是对节点的处理函数。

### 4. Path vs Node

- **Node**：AST 中的纯对象，包含 `type`、`start`、`end`、`loc` 等属性。
- **Path**：Babel 对 Node 的封装，提供上下文方法：
  - `path.node` 访问当前节点
  - `path.parent` / `path.parentPath` 访问父级
  - `path.replaceWith(newNode)` 替换当前节点
  - `path.remove()` 删除当前节点
  - `path.skip()` 跳过子节点遍历
  - `path.stop()` 完全停止遍历

> 写插件时，90% 的操作都通过 `path` 完成，而不是直接修改 `node`。

## 二、代码实践：写一个 console.log 增强插件（约 18 分钟）

### 目标

开发一个 Babel 插件，自动把所有 `console.log(...)` 调用改造成：

```js
console.log('[src/utils.js:12:4]', '原始参数1', '原始参数2');
```

这样在调试 / 生产日志中，能一眼定位日志来源，减少「日志是哪行打印的」的困扰。

### 环境准备

新建一个临时目录，安装依赖：

```bash
mkdir babel-plugin-demo && cd babel-plugin-demo
npm init -y
npm install @babel/core @babel/parser @babel/traverse @babel/generator @babel/types @babel/template
```

### 插件代码：`plugins/log-enhancer.js`

```js
const { declare } = require('@babel/helper-plugin-utils');
const t = require('@babel/types');

module.exports = declare((api, options) => {
  api.assertVersion(7);

  return {
    name: 'log-enhancer',
    visitor: {
      CallExpression(path, state) {
        const { node } = path;

        // 只处理 console.log(...)
        if (
          !t.isMemberExpression(node.callee) ||
          !t.isIdentifier(node.callee.object, { name: 'console' }) ||
          !t.isIdentifier(node.callee.property, { name: 'log' })
        ) {
          return;
        }

        // 获取文件名与行列号
        const filename = state.filename || state.file.opts.filename || 'unknown';
        const { line, column } = node.loc.start;
        const prefix = `[${filename}:${line}:${column}]`;

        // 在参数列表最前面插入位置前缀
        node.arguments.unshift(t.stringLiteral(prefix));
      }
    }
  };
});
```

### 运行脚本：`run.js`

```js
const fs = require('fs');
const path = require('path');
const babel = require('@babel/core');
const plugin = require('./plugins/log-enhancer');

const code = `
function greet(name) {
  console.log('Hello', name);
  return +name;
}
`;

const result = babel.transformSync(code, {
  filename: 'demo.js',
  plugins: [plugin]
});

console.log(result.code);
```

### 预期输出

```js
function greet(name) {
  console.log('[demo.js:3:2]', 'Hello', name);
  return +name;
}
```

### 进阶挑战（可选）

1. **只对开发环境生效**：通过 `options` 传入 `env`，在 `production` 下跳过转换。
2. **支持所有 console 方法**：不只处理 `console.log`，也处理 `console.warn`、`console.error`。
3. **避免重复增强**：如果参数列表第一个已经是位置前缀，则不再添加，防止多次编译后前缀堆叠。
