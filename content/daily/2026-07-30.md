## 核心概念

### 1. 编译器前端的三阶段

```text
源码字符串
   ↓
Lexer（词法分析） → Token 序列
   ↓
Parser（语法分析） → AST 抽象语法树
   ↓
语义分析 / 转换 / 代码生成
```

Lexer 和 Parser 通常被统称为**编译器前端**，它们不负责"代码跑得快不快"，只负责回答一个问题：**这段代码在语法上是否合法，以及它的结构是什么？**

### 2. Lexer：把字符流变成 Token 流

Lexer 的任务是扫描源代码，按规则切分出最小的有意义的单元：**Token**。

例如 JavaScript 代码：

```js
const count = 42;
```

Lexer 会输出类似：

```text
{ type: 'Keyword',    value: 'const' }
{ type: 'Identifier', value: 'count' }
{ type: 'Punctuator', value: '=' }
{ type: 'Numeric',    value: '42' }
{ type: 'Punctuator', value: ';' }
```

每个 Token 通常包含：类型、原始字符串、起始/结束位置（用于后续错误定位）。

> 前端工具中的应用：Babel 的 `@babel/parser` 在解析前会先进行词法分析；ESLint 的规则也经常依赖 token 信息（如 `context.getTokens()`）。

### 3. Parser：把 Token 流变成 AST

Parser 根据语法规则（通常用上下文无关文法 CFG 描述）把 Token 组织成树形结构。

同样是 `const count = 42;`，AST 大致为：

```json
{
  "type": "VariableDeclaration",
  "kind": "const",
  "declarations": [
    {
      "type": "VariableDeclarator",
      "id": { "type": "Identifier", "name": "count" },
      "init": { "type": "Literal", "value": 42 }
    }
  ]
}
```

AST 是前端工具链的"通用语言"：

- Babel：把 ESNext AST 转换成兼容 AST
- ESLint：遍历 AST 找潜在问题
- TypeScript：在 AST 基础上做类型检查
- Prettier：根据 AST 重新打印代码

### 4. 关键术语速览

| 术语 | 含义 | 前端联系 |
|------|------|----------|
| Token | 词法单元 | `context.getTokens()` |
| AST | 抽象语法树 | Babel plugin 操作对象 |
| CFG | 上下文无关文法 | JS 语法规范的核心形式 |
| 递归下降 | 最常用的手写 Parser 技术 | @babel/parser 早期版本 |
| LR/LL | 自底向上 / 自顶向下分析策略 | yacc/ANTLR 等生成器 |
| Operator Precedence | 运算符优先级 | `1 + 2 * 3` 的树形结构来源 |

## 代码实践

### 目标：手写一个极简表达式 Lexer + Parser

用 15 分钟左右实现一个能解析 `1 + 2 * 3` 这类算术表达式的小工具。

#### Step 1：极简 Lexer

```js
function lexer(input) {
  const tokens = [];
  let i = 0;

  while (i < input.length) {
    const char = input[i];

    if (/\s/.test(char)) {
      i++;
      continue;
    }

    if (/\d/.test(char)) {
      let value = '';
      while (i < input.length && /\d/.test(input[i])) {
        value += input[i];
        i++;
      }
      tokens.push({ type: 'NUMBER', value: Number(value) });
      continue;
    }

    if (['+', '-', '*', '/'].includes(char)) {
      tokens.push({ type: 'OPERATOR', value: char });
      i++;
      continue;
    }

    throw new Error(`Unexpected character: ${char}`);
  }

  return tokens;
}

console.log(lexer('1 + 2 * 3'));
// [
//   { type: 'NUMBER', value: 1 },
//   { type: 'OPERATOR', value: '+' },
//   { type: 'NUMBER', value: 2 },
//   { type: 'OPERATOR', value: '*' },
//   { type: 'NUMBER', value: 3 }
// ]
```

#### Step 2：递归下降 Parser

```js
function parser(tokens) {
  let i = 0;

  function peek() {
    return tokens[i];
  }

  function consume(type, value) {
    const token = tokens[i];
    if (token?.type !== type || (value !== undefined && token.value !== value)) {
      throw new Error(`Expected ${type}${value ? ` ${value}` : ''}, got ${token?.type}`);
    }
    i++;
    return token;
  }

  // expression := term (('+' | '-') term)*
  function expression() {
    let node = term();
    while (peek()?.value === '+' || peek()?.value === '-') {
      const op = consume('OPERATOR');
      node = {
        type: 'BinaryExpression',
        operator: op.value,
        left: node,
        right: term()
      };
    }
    return node;
  }

  // term := factor (('*' | '/') factor)*
  function term() {
    let node = factor();
    while (peek()?.value === '*' || peek()?.value === '/') {
      const op = consume('OPERATOR');
      node = {
        type: 'BinaryExpression',
        operator: op.value,
        left: node,
        right: factor()
      };
    }
    return node;
  }

  // factor := NUMBER
  function factor() {
    return { type: 'Literal', value: consume('NUMBER').value };
  }

  return expression();
}

const ast = parser(lexer('1 + 2 * 3'));
console.log(JSON.stringify(ast, null, 2));
```

输出：

```json
{
  "type": "BinaryExpression",
  "operator": "+",
  "left": { "type": "Literal", "value": 1 },
  "right": {
    "type": "BinaryExpression",
    "operator": "*",
    "left": { "type": "Literal", "value": 2 },
    "right": { "type": "Literal", "value": 3 }
  }
}
```

#### 实践要点

1. **Lexer 只认字符，不认结构**：它不需要知道 `+` 是二元还是一元运算符。
2. **Parser 负责层级关系**：通过 `expression → term → factor` 的层级，自然实现了乘除优先于加减。
3. **错误信息要定位到 Token**：真实编译器会在 Token 上保留行列号，便于报错。

## 思考题

1. **连接工作流**：你最近写的一个 Babel 插件或 ESLint 规则，本质上是在 AST 的哪个节点上做了操作？试着用 `astexplorer.net` 定位一下。
2. **优先级设计**：如果把示例中的 `term` 和 `factor` 层级合并，会发生什么？为什么 Lexer 不能处理运算符优先级？
3. **AI 视角**：当大模型生成代码时，它直接输出的是"Token 序列"（字符串）。如果让它先生成 AST 再反解为代码，会对代码正确率产生什么影响？为什么前端工具更适合用 AST 而不是纯字符串做转换？
4. **扩展挑战**：如果要让上面的 Parser 支持括号 `()`，应该在哪个层级加入什么规则？
