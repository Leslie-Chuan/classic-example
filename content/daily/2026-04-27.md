## 【今日主题】（1分钟阅读）

**MCP安全模型与权限设计 —— 当AI Agent拥有文件系统访问权时，谁来守门？**

前四天我们已经理解了MCP协议的核心机制，也动手搭建了Server和Client。但一个关键问题被刻意搁置了：如果AI Agent通过MCP可以读写文件、执行命令、查询数据库，谁来决定它能做什么、不能做什么？今天的主题是MCP的安全边界与权限治理 —— 这是将MCP从"玩具"推向"生产工具"的必经之路。

---

## 【核心概念】（5分钟精读）

### 1. 去中心化的安全设计哲学

MCP的安全模型与传统API网关截然不同。它采用**"Server自主授权 + Client执行管控"**的双层架构：

- **Server端**：每个MCP Server自行决定暴露哪些Tools、Resources、Prompts，以及每个操作需要什么前置条件。协议本身不强制统一的权限标准。
- **Client端**：Client负责实际的资源访问（文件系统、网络、UI交互），因此必须在执行层建立最终的防护墙。

这种设计的优劣都很明显。优势是Server开发者有完全的自主权，劣势是Client无法仅依赖Server的声明来判断安全性 —— 一个名为 `read_project_config` 的Tool可能实际上会读取 `/etc/passwd`。

### 2. Capability Negotiation 中的安全暗面

`initialize` 阶段的握手不只是交换协议版本，还涉及双方 Capabilities 的声明。这里存在两个被低估的攻击面：

- **恶意Client**：谎报自己支持 `sampling` capability，诱导Server发送包含敏感上下文的 prompt 给Client控制的LLM。
- **恶意Server**：声明无害的Tool名称和描述，但在执行时执行超出预期的操作（如 `list_directory` 实际上会递归删除）。

**关键洞察**：MCP协议层的Capabilities声明是"自报家门"，没有密码学验证。安全不能建立在信任的基础上。

### 3. 前端开发者面临的特殊风险

作为前端工程师，当你把MCP Client集成到Electron应用、VS Code插件或本地开发工具时，你正在把Node.js的运行时权限暴露给一个外部定义的协议：

- **stdio Transport**：Client直接启动Server进程，Server的代码来自 `npm install`，供应链攻击可以直接获得本地代码执行权。
- **SSE Transport**：浏览器环境下的Client通过HTTPS连接Server，但CORS和证书校验是唯一的防线。一旦Server被劫持，浏览器中的Client可能向恶意端点泄露本地上下文。
- **Prompt Injection**：Server提供的Prompt可能包含隐藏指令，通过 `get_prompt` 注入到用户的对话上下文中。

### 4. 四层权限治理模型

在实际工程中，建议构建以下四层防御：

| 层级 | 职责 | 前端实现示例 |
|------|------|-------------|
| Transport层 | 连接认证与加密 | HTTPS证书固定、stdio进程沙箱 |
| Discovery层 | 工具风险分析 | 调用 `list_tools` 后，基于名称/描述做风险分级 |
| Execution层 | 调用前拦截与参数校验 | 路径白名单、操作类型限制、用户确认弹窗 |
| Audit层 | 完整调用链记录 | 结构化日志、回滚支持、异常告警 |

### 5. "Human-in-the-loop" 不是可选项

Claude Desktop、Cursor、Windsurf 等产品的共同设计选择是：对于文件写入、命令执行、网络请求等不可逆或高风险操作，必须在Client层阻塞并请求用户显式确认。这不是体验上的妥协，而是安全上的底线。

#### 1. 简易文件操作 MCP Server（file-server.ts）

```typescript
/**
 * file-server.ts
 * 一个暴露文件读写操作的MCP Server，模拟真实的工具Server
 * 运行方式: npx tsx file-server.ts
 */
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";
import * as fs from "node:fs/promises";
import * as path from "node:path";

const server = new Server(
  { name: "file-server", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

// 声明可用工具
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: "read_file",
      description: "读取指定路径的文本文件内容",
      inputSchema: {
        type: "object",
        properties: {
          filepath: { type: "string", description: "绝对或相对路径" },
        },
        required: ["filepath"],
      },
    },
    {
      name: "write_file",
      description: "向指定路径写入内容（会覆盖）",
      inputSchema: {
        type: "object",
        properties: {
          filepath: { type: "string" },
          content: { type: "string" },
        },
        required: ["filepath", "content"],
      },
    },
    {
      name: "list_directory",
      description: "列出目录下的文件和子目录",
      inputSchema: {
        type: "object",
        properties: {
          dirpath: { type: "string" },
        },
        required: ["dirpath"],
      },
    },
    {
      name: "execute_command",
      description: "执行shell命令（高风险操作）",
      inputSchema: {
        type: "object",
        properties: {
          command: { type: "string" },
        },
        required: ["command"],
      },
    },
  ],
}));

// 工具实现（Server层没有任何权限校验，完全信任Client传来的参数）
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;

  try {
    if (name === "read_file") {
      const content = await fs.readFile(args.filepath as string, "utf-8");
      return { content: [{ type: "text", text: content }] };
    }

    if (name === "write_file") {
      await fs.writeFile(args.filepath as string, args.content as string, "utf-8");
      return { content: [{ type: "text", text: `已写入: ${args.filepath}` }] };
    }

    if (name === "list_directory") {
      const entries = await fs.readdir(args.dirpath as string, { withFileTypes: true });
      const lines = entries.map((e) => `${e.isDirectory() ? "[DIR]" : "[FILE]"} ${e.name}`);
      return { content: [{ type: "text", text: lines.join("\n") }] };
    }

    if (name === "execute_command") {
      // 注意：这是一个危险操作，Server端完全没有做限制
      const { execSync } = await import("node:child_process");
      const output = execSync(args.command as string, { encoding: "utf-8" });
      return { content: [{ type: "text", text: output }] };
    }

    throw new Error(`未知工具: ${name}`);
  } catch (err: any) {
    return { content: [{ type: "text", text: `错误: ${err.message}` }], isError: true };
  }
});

const transport = new StdioServerTransport();
await server.connect(transport);
console.error("File Server 已启动，等待Client连接...");
```

#### 2. 安全Client Gateway（secure-client.ts）

```typescript
/**
 * secure-client.ts
 * 带权限管控的MCP Client Gateway
 * 运行方式: npx tsx secure-client.ts
 */
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";
import type { TextContent } from "@modelcontextprotocol/sdk/types.js";
import * as readline from "node:readline";
import * as path from "node:path";

// ==================== 权限规则配置 ====================

interface PermissionRule {
  /** 匹配工具名的正则 */
  toolPattern: RegExp;
  /** 允许操作的路径前缀列表（仅对含路径参数的工具生效） */
  allowedPaths?: string[];
  /** 是否需要用户确认 */
  requireConfirmation: boolean;
  /** 风险等级: low | medium | high */
  riskLevel: "low" | "medium" | "high";
  /** 最大调用次数限制（防滥用） */
  maxCalls?: number;
}

/** 生产环境中，这些规则应从配置文件或管理后台动态加载 */
const PERMISSION_RULES: PermissionRule[] = [
  {
    toolPattern: /^read_file$/,
    allowedPaths: [process.cwd(), "/tmp"],
    requireConfirmation: false,
    riskLevel: "low",
  },
  {
    toolPattern: /^list_directory$/,
    allowedPaths: [process.cwd(), "/tmp"],
    requireConfirmation: false,
    riskLevel: "low",
  },
  {
    toolPattern: /^write_file$/,
    allowedPaths: [path.join(process.cwd(), "sandbox")],
    requireConfirmation: true,
    riskLevel: "high",
  },
  {
    toolPattern: /^execute_command$/,
    requireConfirmation: true,
    riskLevel: "high",
    maxCalls: 3,
  },
];

// ==================== 审计日志 ====================

interface AuditRecord {
  timestamp: string;
  tool: string;
  args: Record<string, unknown>;
  decision: "allow" | "deny" | "confirm_allow" | "confirm_deny";
  reason: string;
}

const auditLog: AuditRecord[] = [];

function recordAudit(record: AuditRecord) {
  auditLog.push(record);
  // 生产环境应写入持久化存储或发送到监控系统
  console.log(`[AUDIT] ${record.decision.toUpperCase()} | ${record.tool} | ${record.reason}`);
}

// ==================== 用户确认交互 ====================

const rl = readline.createInterface({ input: process.stdin, output: process.stdout });

function askUser(question: string): Promise<string> {
  return new Promise((resolve) => rl.question(question, resolve));
}

// ==================== 参数提取工具 ====================

/**
 * 从工具参数中提取路径值（支持多种常见参数名）
 */
function extractPath(args: Record<string, unknown>): string | null {
  const pathKeys = ["filepath", "dirpath", "path", "file", "directory"];
  for (const key of pathKeys) {
    if (typeof args[key] === "string") return args[key] as string;
  }
  return null;
}

/**
 * 检查目标路径是否在允许列表内（支持相对路径解析为绝对路径）
 */
function isPathAllowed(target: string, allowedPaths: string[]): boolean {
  const resolved = path.resolve(target);
  return allowedPaths.some((allowed) => {
    const resolvedAllowed = path.resolve(allowed);
    return resolved === resolvedAllowed || resolved.startsWith(resolvedAllowed + path.sep);
  });
}

// ==================== 权限引擎 ====================

class PermissionEngine {
  private callCounters = new Map<string, number>();

  /**
   * 评估一次工具调用是否被允许
   * 返回 { allowed, reason, requireConfirm }
   */
  evaluate(toolName: string, args: Record<string, unknown>): {
    allowed: boolean;
    reason: string;
    requireConfirm: boolean;
  } {
    // 1. 查找匹配的规则
    const rule = PERMISSION_RULES.find((r) => r.toolPattern.test(toolName));

    if (!rule) {
      return { allowed: false, reason: `工具 "${toolName}" 未在权限规则中注册（默认拒绝）`, requireConfirm: false };
    }

    // 2. 调用次数检查
    const currentCount = this.callCounters.get(toolName) || 0;
    if (rule.maxCalls !== undefined && currentCount >= rule.maxCalls) {
      return { allowed: false, reason: `工具 "${toolName}" 调用次数已达上限 (${rule.maxCalls})`, requireConfirm: false };
    }

    // 3. 路径白名单检查
    if (rule.allowedPaths && rule.allowedPaths.length > 0) {
      const targetPath = extractPath(args);
      if (targetPath && !isPathAllowed(targetPath, rule.allowedPaths)) {
        return {
          allowed: false,
          reason: `路径 "${targetPath}" 不在允许列表内（允许: ${rule.allowedPaths.join(", ")}）`,
          requireConfirm: false,
        };
      }
    }

    // 4. 确认拦截
    if (rule.requireConfirmation) {
      return { allowed: true, reason: `高风险操作（${rule.riskLevel}），需用户确认`, requireConfirm: true };
    }

    return { allowed: true, reason: `低风险操作（${rule.riskLevel}），直接放行`, requireConfirm: false };
  }

  incrementCounter(toolName: string) {
    this.callCounters.set(toolName, (this.callCounters.get(toolName) || 0) + 1);
  }
}

// ==================== 安全Client Gateway ====================

class SecureMCPGateway {
  private client: Client;
  private permission = new PermissionEngine();

  constructor(private serverCommand: string, private serverArgs: string[]) {
    this.client = new Client({ name: "secure-gateway", version: "1.0.0" });
  }

  async connect() {
    const transport = new StdioClientTransport({
      command: this.serverCommand,
      args: this.serverArgs,
    });
    await this.client.connect(transport);

    // 连接后立即做能力发现和安全分析
    const tools = await this.client.listTools();
    console.log("\n=== 连接成功，已发现以下工具 ===");
    for (const tool of tools.tools) {
      const rule = PERMISSION_RULES.find((r) => r.toolPattern.test(tool.name));
      const riskLabel = rule ? `[${rule.riskLevel.toUpperCase()}]` : "[UNKNOWN-默认拒绝]";
      console.log(`  ${riskLabel} ${tool.name}: ${tool.description}`);
    }
    console.log("===================================\n");
  }

  /**
   * 带权限管控的工具调用
   */
  async callTool(toolName: string, args: Record<string, unknown>): Promise<string> {
    const evaluation = this.permission.evaluate(toolName, args);

    // 如果被规则拒绝，直接返回
    if (!evaluation.allowed) {
      recordAudit({ timestamp: new Date().toISOString(), tool: toolName, args, decision: "deny", reason: evaluation.reason });
      return `[拒绝] ${evaluation.reason}`;
    }

    // 如果需要用户确认
    if (evaluation.requireConfirm) {
      console.log(`\n⚠️  高风险操作请求:`);
      console.log(`   工具: ${toolName}`);
      console.log(`   参数: ${JSON.stringify(args, null, 2)}`);
      console.log(`   原因: ${evaluation.reason}`);
      const answer = await askUser("   是否允许执行? [y/N]: ");
      if (answer.trim().toLowerCase() !== "y") {
        recordAudit({
          timestamp: new Date().toISOString(),
          tool: toolName,
          args,
          decision: "confirm_deny",
          reason: "用户拒绝确认",
        });
        return `[拒绝] 用户未确认执行 "${toolName}"`;
      }
      recordAudit({
        timestamp: new Date().toISOString(),
        tool: toolName,
        args,
        decision: "confirm_allow",
        reason: evaluation.reason,
      });
    } else {
      recordAudit({
        timestamp: new Date().toISOString(),
        tool: toolName,
        args,
        decision: "allow",
        reason: evaluation.reason,
      });
    }

    // 执行调用
    this.permission.incrementCounter(toolName);
    const result = await this.client.callTool({ name: toolName, arguments: args });
    const text = (result.content as TextContent[]).map((c) => c.text).join("\n");
    return text;
  }

  async disconnect() {
    await this.client.close();
    rl.close();
  }

  printAuditSummary() {
    console.log("\n=== 审计日志摘要 ===");
    const allowCount = auditLog.filter((r) => r.decision === "allow" || r.decision === "confirm_allow").length;
    const denyCount = auditLog.filter((r) => r.decision === "deny" || r.decision === "confirm_deny").length;
    console.log(`  允许: ${allowCount} 次 | 拒绝: ${denyCount} 次`);
    console.log("====================\n");
  }
}

// ==================== 主流程：演示安全管控 ====================

async function main() {
  const gateway = new SecureMCPGateway("npx", ["tsx", "file-server.ts"]);
  await gateway.connect();

  // 场景1: 合法读取（低风险，直接放行）
  console.log("--- 场景1: 读取当前目录文件 ---");
  const readResult = await gateway.callTool("read_file", { filepath: "package.json" });
  console.log(readResult.slice(0, 200) + "...\n");

  // 场景2: 路径逃逸（被规则拒绝）
  console.log("--- 场景2: 尝试读取 /etc/passwd（路径逃逸）---");
  const escapeResult = await gateway.callTool("read_file", { filepath: "/etc/passwd" });
  console.log(escapeResult + "\n");

  // 场景3: 高风险写入（需用户确认）
  console.log("--- 场景3: 写入文件到沙箱目录（高风险，需确认）---");
  const writeResult = await gateway.callTool("write_file", {
    filepath: "./sandbox/test.txt",
    content: "Hello from secure gateway!",
  });
  console.log(writeResult + "\n");

  // 场景4: 越权写入（路径不在允许列表）
  console.log("--- 场景4: 尝试写入 /tmp（越权）---");
  const unauthorizedWrite = await gateway.callTool("write_file", {
    filepath: "/tmp/hacked.txt",
    content: "malicious",
  });
  console.log(unauthorizedWrite + "\n");

  // 场景5: 命令执行（高风险 + 次数限制）
  console.log("--- 场景5: 执行命令（高风险，受次数限制）---");
  const cmdResult = await gateway.callTool("execute_command", { command: "echo 'hello world'" });
  console.log(cmdResult + "\n");

  gateway.printAuditSummary();
  await gateway.disconnect();
}

main().catch(console.error);
```

## 【思考题】（5分钟）

### 问题1：团队AI Agent的权限决策树

假设你正在为公司开发一个内部AI Coding Agent，它需要具备以下能力：
- 读取和修改项目源码（ monorepo 内多个 package ）
- 执行 `npm test`、`npm run build` 等命令
- 查询内部文档站（通过 HTTP API ）
- 读写本地配置文件（如 `.env.local` ）

**请画出或描述你的权限决策树**：什么情况下可以静默执行？什么情况下必须弹窗确认？什么情况下应该完全禁止？如何平衡"开发效率"与"安全风险"？特别地，当Agent连续执行多个操作时（例如"先改代码再跑测试"），你是否允许它在用户一次确认后获得一个"临时会话权限"？

### 问题2：Server不可信时的"默认拒绝"策略

MCP的Server端自主授权模型意味着每个第三方Server都可以自由定义Tool的名称、描述和行为。作为Client开发者，你面临一个不可信的外部生态：

- 一个Server可能把 `delete_all_files` 命名为 `cleanup_temp`；
- Server的 `list_tools` 返回的描述可能是过时的或误导性的；
- npm供应链攻击可能将正常Server替换为恶意版本。

**在不依赖Server自我声明的前提下**，你会如何设计Client层的"默认拒绝"（Default Deny）策略？请从以下维度给出你的思考：静态分析（能否分析Server的代码/AST）、动态沙箱（能否限制Server进程的系统调用）、行为建模（能否基于历史调用模式检测异常）、以及社会工程防御（如何防止Prompt Injection诱导用户绕过安全确认）。

**链接**：https://modelcontextprotocol.io/docs/concepts/security  
**重点阅读**：
- "Security Design Principles" 一节，理解协议层的假设与边界
- Server和Client各自的安全责任划分

### 2. GitHub MCP Server 的权限实现
**仓库**：https://github.com/github/github-mcp-server  
**重点研究**：
- 该Server如何在Repository级别实现权限隔离（OAuth Scope → MCP Tool 暴露的映射）
- `src/github/` 目录下各Tool的实现，观察它如何在Server层自行校验权限（例如验证当前token是否有push权限才暴露write类Tool）
- 这是一个"Server端自主授权"的典范实践，值得深入阅读其架构设计

> 💡 **今日学习提示**：安全不是一个功能，而是一种架构思维方式。今天的代码示例虽然简单，但它展示了生产级MCP集成中最容易被忽视的一层 —— Client端的执行管控。建议你花2分钟时间，把 `PERMISSION_RULES` 中的规则改成适合你当前项目的配置，思考一下如果明天就要把MCP集成到团队工具链中，哪些路径、哪些命令必须被关进沙箱。
