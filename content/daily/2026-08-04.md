## 一、核心概念（约 12 分钟）

### 1. TypeScript 编译器能做什么，不只是 `tsc`？

我们平时用 `tsc` 做类型检查和转译，但 TypeScript 本身是一个高度可编程的编译器平台。它的 Compiler API 允许你以代码驱动编译器，完成很多高级工作流：

- **静态分析**：扫描项目中的 API 用法、组件依赖、代码规范。
- **类型推导**：拿到某个变量/表达式在 TS 视角下的真实类型。
- **代码生成**：根据类型信息自动生成类型定义、接口文档、测试桩。
- **重构辅助**：批量重命名、迁移类型、提取公共接口。
- **自定义工具链**：企业内部的组件库文档、低代码平台、IDE 插件。

```text
┌─────────────┐     Program      ┌─────────────┐     TypeChecker    ┌─────────────┐
│  tsconfig   │ ───────────────→ │  SourceFile │ ────────────────→ │  Type Info  │
│  + source   │                  │    (AST)    │                  │  Symbol等   │
└─────────────┘                  └─────────────┘                  └─────────────┘
```

### 2. Compiler API 核心对象速览

| 对象 | 作用 | 常用场景 |
|------|------|----------|
| `ts.createProgram` | 从 tsconfig 创建编译上下文 | 获取整个项目的类型检查能力 |
| `Program` | 代表一次编译会话 | 拿 SourceFile、TypeChecker、Emit 结果 |
| `SourceFile` | 单个文件的 AST | 遍历节点、读取源码位置 |
| `TypeChecker` | 类型推导与符号解析 | 获取变量类型、查找符号、判断兼容性 |
| `Node` / `Symbol` / `Type` | AST 节点、符号、类型对象 | 精细化类型分析 |
| `Transformer` / `Visitor` | AST 转换 | 写自定义 Babel/TS 插件风格工具 |

### 3. 类型编程：从「类型体操」到「工程能力」

类型编程不是炫技，而是把约束和推导能力前置到编译期：

- **泛型 + 条件类型**：`T extends U ? X : Y`，实现分支推导。
- **映射类型**：`{ [K in keyof T]: ... }` 批量转换结构。
- **模板字面量类型**：从字符串中解析出路径、事件名、CSS 变量。
- **infer 推断**：从复杂类型中提取子类型，如 `ReturnType<T>`、参数类型。
- **类型守卫 + 收窄**：把运行时判断和编译期类型关联起来。

> 高级前端工程师的视角：类型编程最有价值的地方不是做出多复杂的类型，而是**让 API 的错误在写代码时就暴露出来**。

### 4. ts-morph：Compiler API 的友好封装

直接使用原生 Compiler API 比较繁琐，ts-morph 提供了类似 jQuery 的链式 API：

```ts
import { Project } from 'ts-morph';

const project = new Project({ tsConfigFilePath: './tsconfig.json' });
const sourceFile = project.getSourceFile('src/Button.tsx');

// 查找所有接口声明
const interfaces = sourceFile.getInterfaces();
interfaces.forEach((i) => console.log(i.getName()));
```

当你的目标是快速写一个内部工具而不是写 TS 编译器插件时，ts-morph 往往是更好的选择。

## 二、代码实践：用 Compiler API 提取 React 组件 props 类型（约 18 分钟）

### 目标

编写一个脚本，读取 `Button.tsx`，自动提取组件 `Props` 接口的每个字段名、类型和可选性，并输出为 JSON。

### 环境准备

```bash
mkdir ts-compiler-demo && cd ts-compiler-demo
npm init -y
npm install typescript @types/node
```

### 示例组件

**`src/Button.tsx`**

```tsx
import React from 'react';

export interface ButtonProps {
  /** 按钮文字 */
  label: string;
  /** 是否禁用 */
  disabled?: boolean;
  /** 点击回调 */
  onClick?: () => void;
  /** 按钮类型 */
  variant?: 'primary' | 'secondary';
}

export const Button: React.FC<ButtonProps> = ({ label, disabled, onClick, variant = 'primary' }) => {
  return (
    <button disabled={disabled} onClick={onClick} className={`btn btn-${variant}`}>
      {label}
    </button>
  );
};
```

### 提取 props 的脚本

**`scripts/extract-props.ts`**

```ts
import * as ts from 'typescript';
import * as path from 'path';
import * as fs from 'fs';

const filePath = path.resolve(__dirname, '../src/Button.tsx');

// 1. 创建 Program
const program = ts.createProgram([filePath], {
  jsx: ts.JsxEmit.React,
  target: ts.ScriptTarget.ES2020,
  module: ts.ModuleKind.CommonJS,
  esModuleInterop: true,
});

const checker = program.getTypeChecker();
const sourceFile = program.getSourceFile(filePath)!;

interface PropField {
  name: string;
  type: string;
  optional: boolean;
  doc?: string;
}

const props: PropField[] = [];

// 2. 遍历 AST，找到 interface ButtonProps
ts.forEachChild(sourceFile, (node) => {
  if (ts.isInterfaceDeclaration(node) && node.name.text === 'ButtonProps') {
    const symbol = checker.getSymbolAtLocation(node.name);
    if (!symbol) return;

    const type = checker.getDeclaredTypeOfSymbol(symbol);
    const properties = checker.getPropertiesOfType(type);

    properties.forEach((prop) => {
      const propType = checker.getTypeOfSymbolAtLocation(prop, prop.valueDeclaration!);
      const optional = (prop.getFlags() & ts.SymbolFlags.Optional) !== 0;
      const jsDocTags = prop.getDocumentationComment(checker);
      const doc = jsDocTags.map((c) => c.text).join('').trim() || undefined;

      props.push({
        name: prop.getName(),
        type: checker.typeToString(propType),
        optional,
        doc,
      });
    });
  }
});

console.log(JSON.stringify(props, null, 2));
```

### 运行

```bash
npx ts-node scripts/extract-props.ts
```

**预期输出**

```json
[
  { "name": "label", "type": "string", "optional": false, "doc": "按钮文字" },
  { "name": "disabled", "type": "boolean", "optional": true, "doc": "是否禁用" },
  { "name": "onClick", "type": "(() => void) | undefined", "optional": true, "doc": "点击回调" },
  { "name": "variant", "type": "\"primary\" | \"secondary\" | undefined", "optional": true, "doc": "按钮类型" }
]
```

### 进阶：用类型体操实现一个智能事件名类型

```ts
type EventMap = {
  'user:login': { userId: string; timestamp: number };
  'user:logout': { userId: string };
  'order:created': { orderId: string; amount: number };
};

// 提取事件名前缀
 type EventNamespace<T extends string> = T extends `${infer N}:${string}` ? N : never;

// 使用
type Namespaces = EventNamespace<keyof EventMap>; // "user" | "order"
```

> 这个技巧在事件总线、埋点系统、WebSocket 消息路由里非常实用。

## 三、思考题

1. **Compiler API 的边界**：TypeScript Compiler API 适合替代 ESLint 做代码规范检查吗？它和 ESLint/AST 工具（如 Babel parser）的分工边界是什么？
2. **类型安全 vs 编译开销**：复杂的泛型和条件类型会增加类型检查时间。你在什么情况下会选择把一部分推导从编译期移到运行期？
3. **工程化价值**：如果你负责一个组件库，会如何用 Compiler API 自动生成文档、类型声明或变更检测？
4. **模板字面量类型的局限**：`infer` 和模板字面量类型能否处理任意嵌套路径（如 `a.b.c`）？实际工程中如何处理递归类型导致的性能问题？
5. **ts-morph vs 原生 API**：什么时候必须直接用原生 Compiler API，什么时候 ts-morph 足够？

## 今日小结

- TypeScript 不仅是类型系统，它的 Compiler API 是一个可被代码驱动的编译平台。
- 核心三件套：`Program`（编译上下文）、`SourceFile`（AST）、`TypeChecker`（类型推导）。
- 类型编程的价值在于把约束前置，让错误在写代码时就暴露。
- ts-morph 大幅降低了 AST 操作门槛，内部工具首选；原生 API 适合对性能和定制化要求更高的场景。
