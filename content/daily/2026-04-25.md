## 【今日主题】（1 分钟阅读）

昨天我们搭建了一个 MCP Server，理解了三层架构如何协作。但 Server 本身不能独立运行——它需要一个 **Client** 来发现能力、构造请求、处理响应。今天角色反转：我们站在调用方视角，编写一个完整的 MCP Client，连接昨天写的 `frontend-helper-server`。

为什么前端开发者需要关心 Client？因为当你把 MCP 集成到自己的产品（IDE 插件、内部工作台、AI 聊天界面）时，**你就是 Client 的开发者**。理解 Client 的工作机制，才能正确管理 Server 生命周期、处理错误、优化用户体验。

## 【核心概念】（5 分钟精读）

### 1. MCP Client 的四个职责

Client 不只是"发请求、收响应"。它承担四个独立职责：

| 职责 | 说明 | 对应代码 |
|------|------|----------|
| **生命周期管理** | 启动 Server 子进程、建立连接、优雅关闭 | `StdioClientTransport` + `client.connect()` |
| **能力发现** | 查询 Server 支持哪些 Tool / Resource / Prompt | `client.listTools()` |
| **请求构造** | 将用户意图翻译为符合 Schema 的 callTool 调用 | `client.callTool({ name, arguments })` |
| **结果呈现** | 解析 Server 返回的 `content[]`，渲染到 UI | 你的前端代码 |

前两项是 SDK 帮你做的，后两项是你需要自己写的。理解这个边界很重要：**SDK 管通信，你管交互**。

### 2. 连接生命周期：从 spawn 到 close

stdio 模式下，Client 与 Server 的关系是父子进程：

```
Client (父进程)
  ├── spawn Server (子进程)
  ├── stdin → JSON-RPC Request → Server
  ├── stdout ← JSON-RPC Response ← Server
  └── client.close() → 终止子进程
```

关键细节：
- `StdioClientTransport` 内部用 `child_process.spawn` 启动 Server
- `connect()` 会触发 `initialize` 握手：Client 发送 `initialize` 请求，Server 返回 capabilities，Client 回复 `initialized` 通知
- `close()` 会发送 `notifications/cancelled` 然后终止子进程
- 如果 Server 崩溃（非零退出码），Transport 会触发 `onerror` / `onclose` 回调

### 3. 能力发现：Client 的"菜单加载"

连接建立后，Client 第一件事是调用 `listTools()`。这不只是获取工具列表——它决定了 UI 中展示哪些交互入口。

```typescript
const { tools } = await client.listTools();
// tools = [
//   { name: "analyze_deps", description: "...", inputSchema: {...} },
//   { name: "check_outdated", description: "...", inputSchema: {...} },
//   { name: "suggest_component_path", description: "...", inputSchema: {...} }
// ]
```

`inputSchema` 是 JSON Schema 格式，Client 可以用它：
- **动态生成表单**：根据 properties 渲染输入框、下拉选择、数字滑条
- **客户端校验**：在发送请求前验证参数类型和必填项
- **传给 LLM**：作为 Function Calling 的工具定义，让 LLM 生成合法参数

### 4. 错误处理的三个层次

MCP Client 需要处理三种不同性质的错误：

| 层次 | 来源 | 示例 | 处理策略 |
|------|------|------|----------|
| **Transport 错误** | 连接断开、子进程崩溃 | Server OOM 被杀 | 重连或提示用户重启 |
| **Protocol 错误** | JSON-RPC 解析失败、超时 | 响应 ID 不匹配 | 记录日志，重试请求 |
| **Tool 执行错误** | Server Handler 抛异常 | 文件不存在、命令执行失败 | 显示 `isError: true` 的消息给用户 |

关键区分：`callTool` 的返回值中 `isError: true` 表示**业务错误**（Tool 执行失败但 Server 还活着），而 Transport 层抛出的异常表示**连接级错误**（Server 可能已经挂了）。

### 完整代码：`smart-client.ts`

以下 Client 连接 Day 2 的 `frontend-helper-server`，依次执行能力发现、参数校验、工具调用、错误处理全流程。

```typescript
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";
import path from "path";

// ========== 1. 配置 ==========
// serverPath 指向 Day 2 的 MCP Server
const SERVER_PATH = path.resolve(
  import.meta.dirname,
  "../day2-mcp-server/frontend-helper-server.ts"
);
const PROJECT_ROOT = path.resolve(import.meta.dirname, "../..");

// ========== 2. 建立连接 ==========
async function createClient(): Promise<Client> {
  // Transport 层：启动 Server 子进程，通过 stdin/stdout 通信
  const transport = new StdioClientTransport({
    command: "npx",
    args: ["tsx", SERVER_PATH],
    cwd: PROJECT_ROOT,
  });

  const client = new Client({
    name: "smart-client",
    version: "1.0.0",
  });

  // 监听连接级事件（Server 崩溃、异常断开）
  transport.onerror = (err) => {
    console.error("⚠️  Transport 错误:", err.message);
  };
  transport.onclose = () => {
    console.log("🔌 Transport 连接已关闭");
  };

  // connect() 内部完成 initialize 握手
  await client.connect(transport);
  console.log("✓ Client 已连接\n");
  return client;
}

// ========== 3. 能力发现 ==========
async function discoverCapabilities(client: Client) {
  console.log("── 能力发现 ──");

  const { tools } = await client.listTools();
  console.log(`发现 ${tools.length} 个 Tool:\n`);

  for (const tool of tools) {
    const schema = tool.inputSchema as any;
    const params = Object.entries(schema.properties || {}).map(
      ([name, def]: [string, any]) => {
        const required = schema.required?.includes(name) ? "*" : "?";
        return `    ${required} ${name}: ${def.type}${def.enum ? ` (${def.enum.join("|")})` : ""}`;
      }
    );
    console.log(`  ${tool.name}`);
    console.log(`  ${tool.description}`);
    params.forEach((p) => console.log(p));
    console.log();
  }

  return tools;
}

// ========== 4. 调用工具（带重试） ==========
async function callToolWithRetry(
  client: Client,
  name: string,
  args: Record<string, any>,
  maxRetries = 1
): Promise<any> {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      console.log(`→ 调用 ${name}(${JSON.stringify(args)})`);
      const result = await client.callTool({ name, arguments: args });

      if (result.isError) {
        const errMsg = (result.content as any[])[0]?.text || "未知错误";
        console.log(`  ✗ 业务错误: ${errMsg}`);
        return null;
      }

      const data = JSON.parse((result.content as any[])[0].text);
      console.log(`  ✓ 成功`);
      return data;
    } catch (err: any) {
      console.log(`  ⚠️  连接错误 (attempt ${attempt + 1}): ${err.message}`);
      if (attempt === maxRetries) throw err;
    }
  }
}

// ========== 5. 主流程 ==========
async function main() {
  console.log("=== Day 3: MCP Client 开发实战 ===\n");

  const client = await createClient();

  // Step 1: 能力发现
  await discoverCapabilities(client);

  // Step 2: 调用 analyze_deps
  console.log("── Tool: analyze_deps ──");
  const deps = await callToolWithRetry(client, "analyze_deps", {
    packageJsonPath: path.join(PROJECT_ROOT, "package.json"),
    depth: 1,
  });
  if (deps) {
    console.log(`  总依赖: ${deps.totalDirect}, 生产: ${deps.prodCount}, 开发: ${deps.devCount}`);
  }
  console.log();

  // Step 3: 调用 check_outdated
  console.log("── Tool: check_outdated ──");
  const outdated = await callToolWithRetry(client, "check_outdated", {
    cwd: PROJECT_ROOT,
  });
  if (outdated) {
    console.log(`  过时依赖: ${outdated.outdatedCount} 个`);
    outdated.packages?.slice(0, 3).forEach((p: any) => {
      console.log(`  ${p.severity === "major" ? "🔴" : "🟡"} ${p.package}: ${p.current} → ${p.latest}`);
    });
  }
  console.log();

  // Step 4: 调用 suggest_component_path
  console.log("── Tool: suggest_component_path ──");
  const pathResult = await callToolWithRetry(client, "suggest_component_path", {
    componentName: "Dashboard",
    framework: "react",
    feature: "admin",
  });
  if (pathResult) {
    console.log(`  推荐路径: ${pathResult.component}`);
    console.log(`  理由: ${pathResult.rationale}`);
  }
  console.log();

  // Step 5: 测试错误处理
  console.log("── 错误处理演示 ──");
  await callToolWithRetry(client, "analyze_deps", {
    packageJsonPath: "/nonexistent/package.json",
  });
  console.log();

  // Step 6: 优雅关闭
  console.log("── 关闭连接 ──");
  await client.close();
  console.log("✓ Client 已断开，子进程已终止");
}

main().catch(console.error);
```

### 关键设计解读

**为什么 `StdioClientTransport` 用 `npx tsx` 而不是 `node`？**

因为 Server 是 `.ts` 文件，需要 tsx 做即时转译。生产环境你应该预编译为 `.js`，然后用 `node` 启动（避免每次调用都编译一次）。

**`callTool` 的返回值结构是什么？**

```typescript
{
  content: [{ type: "text", text: "..." }],  // Server 返回的内容数组
  isError?: boolean,  // 业务级错误标记
}
```

`content` 是数组设计，因为 MCP 支持多模态返回（文本 + 图片 + 嵌入资源），虽然大多数 Tool 只返回一个文本项。

**`client.close()` vs 直接 `process.exit()`**

`close()` 会发送 `notifications/cancelled` 通知 Server，让 Server 有机会做清理工作（关闭文件句柄、取消正在执行的异步任务）。直接 `process.exit()` 会强制杀死子进程，Server 的 `onclose` 回调来不及执行。

## 【进阶：多 Server 管理】（5 分钟）

真实场景中，一个 Client 通常连接多个 Server（文件操作、Git、数据库、CI/CD……）。管理多个连接需要关注：

```typescript
// 并行连接多个 Server
const connections = await Promise.all([
  createClientFor("file-system-server"),
  createClientFor("git-server"),
  createClientFor("frontend-helper-server"),
]);

// 合并所有 Server 的工具列表
const allTools = (await Promise.all(
  connections.map(c => c.listTools())
)).flatMap(r => r.tools);

// 关闭时逐个断开
await Promise.all(connections.map(c => c.close()));
```

注意事项：
- 每个 Server 是独立子进程，互不影响
- 工具名全局唯一：如果两个 Server 都声明了 `read_file`，Client 需要加前缀区分
- 并行 `callTool` 时注意超时：某个 Server 卡住不应阻塞其他调用
