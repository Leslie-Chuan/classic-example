## 今日主题

**相似度搜索算法基础（Similarity Search Algorithms）**

RAG 系统将文档转成向量后，真正的挑战是：如何在大规模向量中快速找到与用户问题最相似的 Top-K 个片段？这就需要相似度搜索算法。今天我们将理解向量距离度量、暴力搜索的局限，以及工业界常用的近似最近邻（ANN）算法。

---

## 核心概念（15分钟阅读与理解）

### 1. 向量距离与相似度度量

两个向量越「接近」，代表它们语义越相似。常用的度量方式有三种：

| 度量方式 | 公式/说明 | 适用场景 |
|---------|----------|---------|
| **余弦相似度（Cosine Similarity）** | 计算两向量夹角余弦，值域 [-1, 1] | 文本Embedding最常用，关注方向而非绝对长度 |
| **欧氏距离（Euclidean Distance）** | 向量端点直线距离 | 关注绝对数值差异，如图像特征 |
| **点积（Dot Product）** | 两向量对应分量乘积之和 | 带模长信息的相似度，部分向量库默认使用 |

> 💡 对前端 RAG 来说，**余弦相似度**通常是默认选择，因为 Embedding 向量经过归一化后，余弦相似度与点积结果一致。

### 2. 暴力搜索 vs 近似最近邻（ANN）

**暴力搜索（Flat / Exact Search）**：
- 计算查询向量与库中所有向量的距离
- 结果准确，但时间复杂度 O(N)
- 适合数据量小（万级以下）或离线场景

**近似最近邻（Approximate Nearest Neighbor, ANN）**：
- 牺牲少量精度换取大幅速度提升
- 时间复杂度可降至 O(log N) 甚至更低
- 是百万、亿级向量库的工业标准

### 3. 常见 ANN 算法


### 4. HNSW 的工作原理（重点理解）

HNSW（Hierarchical Navigable Small World）是目前向量数据库中最主流的索引算法之一：

1. **分层图结构**：底层包含所有向量节点，上层是稀疏的「高速公路」节点
2. **搜索时**：从顶层稀疏图开始，快速定位到目标附近区域
3. **逐层下沉**：在更稠密的层中精细化搜索
4. **局部贪心**：每层内从最近邻居出发，向查询点逐步靠近

> 💡 想象成地图导航：先走高速接近目的地，再下匝道走普通道路精确到达。

### 5. IVF 的工作原理

IVF（倒排文件索引）是另一种高效索引：

1. **训练阶段**：用 K-Means 将向量空间划分为 K 个簇（voronoi cells）
2. **存储阶段**：每个向量归属到最近的簇中心
3. **查询阶段**：先找最近的几个簇中心，只在这些簇内部做精确搜索

参数 `nprobe` 控制查询时搜索多少个簇，越大越准但越慢。

### 6. 前端开发者需要关注的指标

| 指标 | 含义 | 选型建议 |
|------|------|---------|
| **Recall@K** | 前 K 结果中包含真正最近邻的比例 | 通常要求 > 95% |
| **Query Latency** | 单次查询耗时 | 在线应用通常要求 < 100ms |
| **Index Size** | 索引占用的内存/磁盘 | 影响部署成本 |
| **Build Time** | 构建索引所需时间 | 频繁更新数据时需关注 |

## 代码实践（10分钟动手）

### 实践任务：用 TypeScript 实现余弦相似度 + 暴力 Top-K 搜索

```typescript
// === 相似度搜索最小实现 ===

type Vector = number[];
interface Document {
  id: string;
  text: string;
  vector: Vector;
}

// 1. 余弦相似度
function cosineSimilarity(a: Vector, b: Vector): number {
  if (a.length !== b.length) {
    throw new Error('Vectors must have the same dimension');
  }

  let dot = 0;
  let normA = 0;
  let normB = 0;

  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }

  return dot / (Math.sqrt(normA) * Math.sqrt(normB));
}

// 2. 暴力 Top-K 搜索（Exact Search）
function bruteForceSearch(
  query: Vector,
  docs: Document[],
  topK: number = 3
): Array<Document & { score: number }> {
  return docs
    .map(doc => ({ ...doc, score: cosineSimilarity(query, doc.vector) }))
    .sort((a, b) => b.score - a.score)
    .slice(0, topK);
}

// 3. 使用示例
const docs: Document[] = [
  {
    id: '1',
    text: 'React 使用虚拟 DOM 提高渲染效率',
    vector: [0.9, 0.1, 0.3, 0.05],
  },
  {
    id: '2',
    text: 'Vue 的响应式系统基于 Proxy 实现',
    vector: [0.1, 0.85, 0.2, 0.1],
  },
  {
    id: '3',
    text: 'TypeScript 提供了静态类型检查',
    vector: [0.2, 0.2, 0.9, 0.1],
  },
  {
    id: '4',
    text: 'Webpack 是前端模块打包工具',
    vector: [0.3, 0.1, 0.1, 0.9],
  },
];

const queryVector: Vector = [0.85, 0.15, 0.25, 0.1]; // 语义接近 React
const results = bruteForceSearch(queryVector, docs, 2);

console.log('Top-K 搜索结果：');
results.forEach(r => {
  console.log(`[${r.score.toFixed(4)}] ${r.text}`);
});

// 输出：
// [0.9903] React 使用虚拟 DOM 提高渲染效率
// [0.7351] Vue 的响应式系统基于 Proxy 实现
```
