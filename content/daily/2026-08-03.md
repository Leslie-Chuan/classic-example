## 一、核心概念（约 12 分钟）

### 1. Module Federation 解决了什么问题？

在大型前端工程里，我们经常面对两种撕裂：

- **巨石应用**：构建慢、发布耦合、团队边界模糊。
- **简单微前端**：iframe 体验割裂；qiankun/single-spa 等方案依赖运行时加载完整 JS Bundle，共享依赖困难、版本冲突频发。

Module Federation（MF）提供了一种**运行时模块共享**机制：多个独立构建的应用可以在浏览器运行时互相暴露和消费模块，就像它们来自同一个构建产物。

```text
┌─────────────┐      exposes "Button"       ┌─────────────┐
│   Remote    │ ───────────────────────────→│    Host     │
│  (组件库)    │                             │  (业务应用)  │
└─────────────┘      consumes "Button"       └─────────────┘
```

### 2. 从 MF 1.0 到 MF 2.0 的关键升级

MF 1.0 随 Webpack 5 发布，核心能力包括 `exposes` / `remotes` / `shared`。MF 2.0（由 Module Federation 独立组织推进，支持 Webpack、Rspack、Vite 等多构建工具）重点补足了工程化短板：

| 能力 | MF 1.0 | MF 2.0 |
|------|--------|--------|
| 构建工具支持 | 主要 Webpack | Webpack / Rspack / Vite / Rollup 等 |
| 类型安全 | 弱，依赖人工同步 d.ts | **原生 TypeScript 类型联邦** |
| 运行时插件 | 有限 | 完整的 **Runtime Plugin API** |
| 错误处理 / 加载失败回退 | 基础 | 更完善的 fallback 与重试机制 |
| 版本策略与共享依赖 | 较粗粒度 | 更精细的 shared scope 与 semver 匹配 |
| 调试与监控 | 难 | 增强的 manifest / stats / devtools 支持 |

### 3. 核心术语速览

- **Host（消费方）**：运行时加载远程模块的应用。
- **Remote（提供方）**：独立构建并暴露模块的应用。
- **Exposed Module**：Remote 通过 `exposes` 声明对外暴露的模块。
- **Remote Entry**：Remote 启动时加载的入口文件，包含模块清单与运行时信息。
- **Shared Dependencies**：多个应用之间共享的依赖（如 React、Vue、lodash），避免重复加载和版本冲突。
- **Runtime Plugin**：MF 2.0 提供的扩展点，可在模块解析、加载、错误处理等生命周期插入自定义逻辑。

### 4. 微前端架构中的三种集成模式

| 模式 | 说明 | 适合场景 |
|------|------|----------|
| **组件级联邦** | 共享 UI 组件 / 业务组件 | 设计系统、组件库跨团队复用 |
| **页面级联邦** | 整个页面或路由由 Remote 提供 | 业务线独立部署、主应用做编排 |
| **能力级联邦** | 共享工具函数、 hooks、服务逻辑 | 跨应用共享非 UI 能力 |

> 高级前端工程师选型的关键不是「用不用 MF」，而是「在哪个粒度做联邦」以及「失败时如何优雅降级」。

## 二、代码实践：一个双应用 Module Federation 2.0 最小示例（约 18 分钟）

### 目标

搭建一个 `remote`（暴露按钮组件）和一个 `host`（消费该组件）的最小 MF 2.0 示例，体验运行时模块共享。

### 环境准备

```bash
mkdir mf2-demo && cd mf2-demo
npm init -y
npm install webpack webpack-cli webpack-dev-server html-webpack-plugin @module-federation/enhanced
```

> 提示：MF 2.0 推荐使用 `@module-federation/enhanced` 包，它在 Webpack 5 之上提供统一增强 API。

### Remote 应用

**`remote/webpack.config.js`**

```js
const HtmlWebpackPlugin = require('html-webpack-plugin');
const { ModuleFederationPlugin } = require('@module-federation/enhanced/webpack');

module.exports = {
  entry: './src/index',
  mode: 'development',
  devServer: { port: 3001 },
  output: { publicPath: 'http://localhost:3001/' },
  plugins: [
    new ModuleFederationPlugin({
      name: 'remote',
      filename: 'remoteEntry.js',
      exposes: {
        './Button': './src/Button',
      },
      shared: {
        react: { singleton: true, eager: true, requiredVersion: '^18.0.0' },
        'react-dom': { singleton: true, eager: true, requiredVersion: '^18.0.0' },
      },
    }),
    new HtmlWebpackPlugin({ template: './public/index.html' }),
  ],
};
```

**`remote/src/Button.jsx`**

```jsx
import React from 'react';

export default function Button({ onClick, children }) {
  return (
    <button onClick={onClick} style={{ padding: '8px 16px', borderRadius: 6 }}>
      {children}
    </button>
  );
}
```

### Host 应用

**`host/webpack.config.js`**

```js
const HtmlWebpackPlugin = require('html-webpack-plugin');
const { ModuleFederationPlugin } = require('@module-federation/enhanced/webpack');

module.exports = {
  entry: './src/index',
  mode: 'development',
  devServer: { port: 3002 },
  output: { publicPath: 'http://localhost:3002/' },
  plugins: [
    new ModuleFederationPlugin({
      name: 'host',
      remotes: {
        remote: 'remote@http://localhost:3001/remoteEntry.js',
      },
      shared: {
        react: { singleton: true, eager: true, requiredVersion: '^18.0.0' },
        'react-dom': { singleton: true, eager: true, requiredVersion: '^18.0.0' },
      },
    }),
    new HtmlWebpackPlugin({ template: './public/index.html' }), // host 通常不需要展示自身 UI
  ],
};
```

**`host/src/App.jsx`**

```jsx
import React, { Suspense, lazy } from 'react';

// 懒加载远程模块
const RemoteButton = lazy(() => import('remote/Button'));

export default function App() {
  return (
    <div>
      <h1>Host Application</h1>
      <Suspense fallback={<span>Loading remote button...</span>}>
        <RemoteButton onClick={() => alert('来自 Remote 的响应')}>
          点我（Remote 组件）
        </RemoteButton>
      </Suspense>
    </div>
  );
}
```

### 运行验证

```bash
# 终端 1
cd remote && npx webpack serve

# 终端 2
cd host && npx webpack serve
```

打开 `http://localhost:3002`，你应该能看到 Host 页面渲染出由 Remote 提供的按钮。

### 进阶：MF 2.0 Runtime Plugin 做加载失败降级

```js
// host/src/fallback-plugin.js
const FallbackPlugin = () => ({
  name: 'fallback-plugin',
  async errorLoadRemote({ id, error, from, origin }) {
    console.warn(`加载远程模块 ${id} 失败：`, error);
    // 返回一个本地兜底组件
    return () => import('./components/PlaceholderButton');
  },
});

export default FallbackPlugin;
```

在 `host/src/index.js` 中注册：

```js
import { registerRemotes, init } from '@module-federation/enhanced/runtime';
import FallbackPlugin from './fallback-plugin';

init({
  name: 'host',
  remotes: [{ name: 'remote', entry: 'http://localhost:3001/remoteEntry.js' }],
  plugins: [FallbackPlugin()],
});
```

> 这个插件能力在 MF 1.0 里很难干净实现，是 MF 2.0 真正工程化落地的标志之一。

## 三、思考题

1. **共享依赖的边界**：为什么 `shared` 中通常把 React 声明为 `singleton: true`？如果不声明，两个 Remote 分别依赖不同 React 版本会发生什么？
2. **版本策略**：`requiredVersion` 与 Remote 实际提供的版本不匹配时，MF 会如何处理？这对 CI/CD 发布节奏有什么要求？
3. **MF vs 包管理**：如果你的团队只是在多个仓库间共享组件，「发布 npm 包」和「Module Federation」各自的适用边界是什么？
4. **类型联邦**：MF 2.0 的 TypeScript 联邦如何避免 `import('remote/Button')` 报类型找不到？尝试思考 `.d.ts` 如何随构建产物自动同步。
5. **架构反思**：微前端的真正成本往往不在技术，而在组织。什么样的团队结构最适合用 MF 做页面级联邦？
