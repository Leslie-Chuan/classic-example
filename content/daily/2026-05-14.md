**Prompt版本管理与A/B测试**

随着AI工程化深入，Prompt不再是随手写的字符串，而是需要版本控制、性能度量和持续优化的"代码资产"。今天我们将学习如何像管理代码一样管理Prompt，以及如何通过A/B测试找到最优提示策略。

## 核心概念（12分钟）

### 1. 为什么Prompt需要版本管理

生产环境中的Prompt一旦变动，可能带来不可预期的输出漂移。核心痛点包括：
- **回滚困难**：改了Prompt发现效果变差，无法快速恢复
- **协作冲突**：团队成员各自优化，没有统一基准
- **效果归因**：无法判断某次输出问题是模型变化还是Prompt变化

### 2. Prompt版本管理的三层模型

| 层级 | 作用 | 示例 |
|------|------|------|
| **V1 - 内容版本** | Prompt文本本身的迭代 | v1.2 加入Few-shot示例 |
| **V2 - 参数版本** | temperature、top_p、max_tokens等 | temperature 0.3 -> 0.7 |
| **V3 - 模型版本** | 底层模型切换 | gpt-4 -> gpt-4-turbo |

> 最佳实践：三层版本独立管理，组合成"Prompt配置快照"。

### 3. A/B测试在Prompt优化中的应用

与传统前端A/B测试不同，Prompt A/B测试关注：
- **质量指标**：输出正确率、格式合规率、幻觉率
- **效率指标**：Token消耗、响应延迟、重试次数
- **业务指标**：用户满意度、任务完成率

测试设计要点：
1. **控制变量**：每次只改一个Prompt元素（System/User/Few-shot）
2. **样本充足**：至少100次调用才能得出统计显著结论
3. **盲测机制**：评估者不知道输出来自哪个版本

### 4. Prompt Diff与回归测试

建立Prompt回归测试套件：
- 准备50-100个代表性输入用例（覆盖边界情况）
- 每次修改Prompt后，全量运行用例并比对输出
- 使用LLM-as-a-Judge自动评分（需设计稳定评估Prompt）

### 实践：构建一个Prompt版本管理器

以下是一个基于JSON文件 + Git的版本管理方案，适合前端团队快速落地：

```typescript

  "version": "1.3.0",
  "model": "claude-3-5-sonnet-20241022",
  "parameters": {
    "temperature": 0.2,
    "max_tokens": 4000
  },
  "prompts": {
    "system": "你是一位资深前端代码审查员，擅长React/TypeScript...",
    "user_template": "请审查以下代码：\n\n```{lang}\n{code}\n```\n\n关注：1)性能 2)可维护性 3)类型安全"
  },
  "few_shot_examples": [

      "input": "...",
      "output": "..."
    }
  ],

    "avg_tokens": 1200,
    "accuracy_score": 0.87,
    "format_compliance": 0.94
  }
```

```typescript
// lib/prompt-registry.ts
import { readdirSync, readFileSync } from 'fs';
import { join } from 'path';

interface PromptVersion {
  version: string;
  model: string;
  parameters: Record<string, number>;
  prompts: { system: string; user_template: string };
  metrics_baseline?: Record<string, number>;
}

class PromptRegistry {
  private versions: Map<string, PromptVersion[]> = new Map();

  loadFromDir(promptName: string, dir: string): void {
    const files = readdirSync(dir)
      .filter(f => f.endsWith('.json'))
      .sort(); // v1.0.0, v1.1.0, ...
    
    this.versions.set(
      promptName,
      files.map(f => JSON.parse(readFileSync(join(dir, f), 'utf-8')))
    );
  }

  get(promptName: string, version?: string): PromptVersion {
    const list = this.versions.get(promptName) ?? [];
    if (!version) return list[list.length - 1]; // 最新版
    const found = list.find(v => v.version === version);
    if (!found) throw new Error(`Prompt ${promptName}@${version} not found`);
    return found;
  }

  // A/B测试：随机返回两个版本之一
  abTest(promptName: string, versions: [string, string]): PromptVersion {
    const [vA, vB] = versions;
    return Math.random() < 0.5 
      ? this.get(promptName, vA) 
      : this.get(promptName, vB);
  }
}

export const registry = new PromptRegistry();
```

```typescript
// lib/prompt-ab-test.ts
interface ABTestResult {
  versionA: string;
  versionB: string;
  samplesA: number;
  samplesB: number;
  metricDiffs: Record<string, { a: number; b: number; winner: string }>;
}

async function runABTest(
  promptName: string,
  versionA: string,
  versionB: string,
  testCases: string[],
  evaluate: (output: string) => Promise<number>
): Promise<ABTestResult> {
  const results: { version: string; scores: number[] }[] = [
    { version: versionA, scores: [] },
    { version: versionB, scores: [] }
  ];

  for (const testCase of testCases) {
    const version = Math.random() < 0.5 ? versionA : versionB;
    const prompt = registry.get(promptName, version);
    const output = await callLLM(prompt, testCase);
    const score = await evaluate(output);
    
    const target = results.find(r => r.version === version)!;
    target.scores.push(score);
  }

  return computeWinner(results);
}
```
