## 【今日主题】（1 分钟阅读）

组件库的文档通常停留在“按字母排序 + 关键词搜索”：开发者必须记得组件叫什么、Props 怎么拼，才能找到正确用法。而 RAG（Retrieval-Augmented Generation）能让文档从“查找工具”进化为“语义助手”——开发者用自然语言描述交互意图，系统召回最相关的组件、API 和示例，再交给 LLM 组织成可执行的答案。

今天的主题是：**为前端组件文档搭建一个可运行的轻量 RAG 系统**，覆盖文档分块、本地嵌入、语义检索和混合排序。代码基于 Node.js + `@xenova/transformers`（本地嵌入模型）+ Express + React，无需 OpenAI API Key 即可跑通。

---

## 【核心概念】（5 分钟精读）

### 1. 组件文档 RAG 与通用文档 RAG 的差异

通用 RAG 通常把长文档按固定长度切片，追求的是“不漏信息”。但组件文档有强烈的结构化特征：

- **组件边界优先**：一个组件的 `Overview`、`Props`、`Example` 应该被拆成独立块，而不是被截断。
- **API 名称是关键锚点**：用户query中的“弹窗”“加载中”需要映射到 `Modal`、`Button loading` 这类语义。
- **示例代码价值高**：相比大段说明，可运行的示例更容易被 LLM 直接用于生成业务代码。

因此，组件文档的 Chunking 策略建议采用 **“结构分块 + 语义增强”**：每个块附带 `title` 和 `section` 元数据，检索阶段可做人为主观权重调整。

### 2. 三阶段架构：Ingest → Embed → Retrieve

```
组件 Markdown
    │
    ▼
[Ingest]  按组件结构拆块（overview / props / example）
    │
    ▼
[Embed]   用 Embedding 模型把文本转成向量
    │
    ▼
[Store]   向量 + 元数据写入向量库
    │
    ▼
[Query]   用户自然语言 → 向量 → 相似度排序 → Top-K 召回
```

### 3. 混合检索：向量相似度 + 元数据加权

纯向量检索在以下场景会失效：

- 用户明确说“我要看 Button 的 Props”——此时应优先召回 `section: props` 的块。
- 用户输入组件名 `Modal`——应做关键词匹配兜底，避免 Embedding 把同义词排错。

所以生产级 RAG 一般走 **“召回（向量 + 关键词）→ 重排（元数据加权 + 交叉编码器）”** 两阶段。今天的示例在重排阶段加入 `section` 权重，让高级开发者理解这个设计空间。

### 4. 上下文窗口经济学

组件文档检索不是召回越多越好。LLM 的上下文有限，应该把 **“最相关的 API + 一个可运行示例”** 喂给它。通常 `topK=3` 比 `topK=10` 效果更好：过多的相似块会让模型注意力分散，产生“张冠李戴”的幻觉。

### 3. ingest.mjs：文档分块与本地嵌入

```javascript
// ingest.mjs
import fs from 'fs/promises';
import path from 'path';
import { pipeline } from '@xenova/transformers';

const DOCS_DIR = './docs';
const DB_PATH = './vector-db.json';

/**
 * 按组件结构拆块：overview / props / example
 * 保证每个块语义完整，避免固定长度切片截断 API 表格。
 */
function parseComponentDoc(raw, fileName) {
  const lines = raw.split('\n');
  const titleLine = lines.find(l => l.startsWith('# '));
  const title = titleLine ? titleLine.replace('# ', '').trim() : path.basename(fileName, '.md');

  const propsIndex = lines.findIndex(l => l.trim().startsWith('## Props'));
  const exampleIndex = lines.findIndex(l => l.trim().startsWith('## Example'));
  const descStart = lines.findIndex(l => l.startsWith('# ')) + 1;
  const descEnd = propsIndex > -1 ? propsIndex : lines.length;
  const description = lines.slice(descStart, descEnd).join('\n').trim();

  const chunks = [
    {
      id: `${title}-overview`,
      text: `${title}\n${description}`,
      meta: { title, section: 'overview', source: fileName }
    }
  ];

  if (propsIndex > -1) {
    const propsEnd = exampleIndex > -1 ? exampleIndex : lines.length;
    chunks.push({
      id: `${title}-props`,
      text: `${title} Props\n${lines.slice(propsIndex, propsEnd).join('\n')}`,
      meta: { title, section: 'props', source: fileName }
    });
  }

  if (exampleIndex > -1) {
    chunks.push({
      id: `${title}-example`,
      text: `${title} Example\n${lines.slice(exampleIndex).join('\n')}`,
      meta: { title, section: 'example', source: fileName }
    });
  }

  return chunks;
}

async function main() {
  const files = await fs.readdir(DOCS_DIR);
  const mdFiles = files.filter(f => f.endsWith('.md'));

  // 本地嵌入模型，首次运行会自动下载到 ~/.cache/transformers
  console.log('Loading embedding model...');
  const embedder = await pipeline('feature-extraction', 'Xenova/all-MiniLM-L6-v2');

  const db = [];

  for (const file of mdFiles) {
    const raw = await fs.readFile(path.join(DOCS_DIR, file), 'utf-8');
    const chunks = parseComponentDoc(raw, file);

    for (const chunk of chunks) {
      const output = await embedder(chunk.text, {
        pooling: 'mean',
        normalize: true
      });
      const vector = Array.from(output.data);
      db.push({ ...chunk, vector });
    }
  }

  await fs.writeFile(DB_PATH, JSON.stringify(db, null, 2));
  console.log(`✅ Ingested ${db.length} chunks from ${mdFiles.length} components`);
}

main().catch(console.error);
```

### 4. server.mjs：语义检索 + 混合排序

```javascript
// server.mjs
import express from 'express';
import cors from 'cors';
import fs from 'fs/promises';
import { pipeline } from '@xenova/transformers';

const app = express();
app.use(cors());
app.use(express.json());

const db = JSON.parse(await fs.readFile('./vector-db.json', 'utf-8'));
const embedder = await pipeline('feature-extraction', 'Xenova/all-MiniLM-L6-v2');

function cosineSimilarity(a, b) {
  let dot = 0;
  let normA = 0;
  let normB = 0;
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  return dot / (Math.sqrt(normA) * Math.sqrt(normB));
}

app.post('/api/search', async (req, res) => {
  const { query, topK = 3, section } = req.body;

  if (!query) {
    return res.status(400).json({ error: 'query is required' });
  }

  // 1. 对 query 做嵌入
  const qOutput = await embedder(query, { pooling: 'mean', normalize: true });
  const qVector = Array.from(qOutput.data);

  // 2. 向量召回 + 元数据加权
  let results = db.map(item => ({
    id: item.id,
    text: item.text,
    meta: item.meta,
    score: cosineSimilarity(qVector, item.vector)
  }));

  // 混合排序：如果用户指定 section，提升该 section 的权重
  if (section) {
    results = results.map(r => ({
      ...r,
      score: r.meta.section === section ? r.score * 1.25 : r.score
    }));
  }

  results.sort((a, b) => b.score - a.score);

  res.json(results.slice(0, topK));
});

app.listen(3001, () => {
  console.log('🔍 RAG server running at http://localhost:3001');
});
```

启动服务：

```bash
npm run server
```

### 5. App.jsx：React 搜索界面

```jsx
// App.jsx
import { useState } from 'react';

function App() {
  const [query, setQuery] = useState('怎么弹出一个确认对话框？');
  const [section, setSection] = useState('');
  const [results, setResults] = useState([]);
  const [loading, setLoading] = useState(false);

  const search = async () => {
    setLoading(true);
    try {
      const res = await fetch('http://localhost:3001/api/search', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          query,
          topK: 3,
          // 可选：强制优先返回 props / example 块
          section: section || undefined
        })
      });
      const data = await res.json();
      setResults(data);
    } finally {
      setLoading(false);
    }
  };

  return (
    <div style={{ maxWidth: 760, margin: '48px auto', fontFamily: 'system-ui, sans-serif' }}>
      <h1>组件文档语义搜索</h1>
      <p style={{ color: '#666' }}>
        用自然语言描述你想实现的交互，系统会从组件文档中召回最相关的 API 和示例。
      </p>

      <input
        value={query}
        onChange={e => setQuery(e.target.value)}
        placeholder="例如：提交时显示加载状态"
        style={{ width: '100%', padding: 12, fontSize: 16, borderRadius: 6, border: '1px solid #ccc' }}
      />

      <div style={{ marginTop: 12 }}>
        <label style={{ marginRight: 12 }}>优先返回：</label>
        <select value={section} onChange={e => setSection(e.target.value)}>
          <option value="">自动</option>
          <option value="overview">概述</option>
          <option value="props">Props</option>
          <option value="example">示例</option>
        </select>
        <button onClick={search} disabled={loading} style={{ marginLeft: 12 }}>
          {loading ? '检索中...' : '搜索'}
        </button>
      </div>

      {results.map(r => (
        <div
          key={r.id}
          style={{
            marginTop: 24,
            padding: 16,
            background: '#f8f9fa',
            borderRadius: 8,
            borderLeft: '4px solid #0d6efd'
          }}
        >
          <div style={{ display: 'flex', justifyContent: 'space-between', marginBottom: 8 }}>
            <strong>{r.meta.title} · {r.meta.section}</strong>
            <span style={{ color: '#0d6efd' }}>{(r.score * 100).toFixed(1)}%</span>
          </div>
          <pre style={{ whiteSpace: 'pre-wrap', margin: 0, fontSize: 13 }}>{r.text}</pre>
        </div>
      ))}
    </div>
  );
}

export default App;
```

> 提示：思考 TypeScript 类型信息如何嵌入检索块、运行时校验（Zod）与生成后静态检查（tsc/eslint）的组合策略，以及“可执行示例”与“API 文档”在 Prompt 中的配比。

## 今日小结

今天我们完成了组件文档 RAG 的端到端实现：

- **结构分块**比固定长度切片更适合组件文档；
- **本地嵌入模型**让原型无需依赖外部 API；
- **向量召回 + section 元数据加权**展示了混合检索的最小可行实现；
- **上下文窗口经济学**提醒我们：召回 3 个高质量块，胜过 10 个泛泛相关的块。

把这套机制接到 LLM 生成层，就能让组件库从“被动文档”变成“主动编码助手”。
