## 今日主题

**结构化Prompt设计：让AI像资深工程师一样思考**

为什么同样的模型，有人能调出惊艳的结果，有人却只能得到泛泛而谈的回答？差距往往不在模型本身，而在Prompt的结构设计。今天我们将深入**Chain of Thought（思维链）**及其衍生模式，学习如何构建能让AI进行深度推理的Prompt框架。

---

## 核心概念（15分钟）

### 1. Chain of Thought（CoT）的本质

CoT不是让AI"多说几句"，而是强制模型暴露推理路径。核心发现来自2022年Google论文：在Prompt中加入"Let's think step by step"，数学推理准确率从17.7%提升到78.7%。

**CoT生效的三个条件：**

- **任务需要多步推理**：简单问答不需要CoT，复杂分析才需要
- **模型具备基础能力**：太小的模型（<10B）即使给CoT指令也难以产生有效推理
- **推理路径可被验证**：最好有标准答案来检验中间步骤是否正确

### 2. 三种CoT变体模式

| 模式 | 适用场景 | 前端开发者案例 |
|------|----------|----------------|
| **Zero-shot CoT** | 快速探索、不确定最佳路径时 | "分析这段React组件的性能瓶颈，逐步思考" |
| **Few-shot CoT** | 有明确推理范式需要复刻时 | 给出2-3个代码审查的逐步分析示例，再让AI审查新代码 |
| **Self-Consistency CoT** | 答案可靠性要求高时 | 让AI生成3条不同的性能优化路径，投票选出最稳健的方案 |

### 3. 结构化Prompt的通用框架：RICE-F

在前端工程化场景中，推荐以下Prompt结构：

```
Role（角色）：你是一位有10年经验的前端架构师
Instruction（指令）：请分析以下组件代码的可维护性问题
Context（上下文）：项目使用React 19 + TypeScript，团队有5名开发者
Example（示例）：[可选] 提供一个你期望的分析格式示例
Format（格式）：输出为Markdown，包含：问题描述、严重程度（高/中/低）、改进建议、重构代码片段
```

**关键洞察**：RICE-F不是让你填满所有字段，而是根据任务复杂度选择必要的维度。30秒的任务只需要Role+Instruction；30分钟的架构评审则需要全部五个维度。

### 4. Tree of Thoughts：CoT的进阶形态

当一个问题存在多条可行路径时，线性CoT会陷入"一条路走到黑"。Tree of Thoughts（ToT）让AI：

1. 生成多个候选思考步骤（breadth）
2. 评估每个步骤的得分（evaluation）
3. 选择最优分支深入（search）
4. 必要时回溯（backtracking）

**前端场景**：技术选型时，让AI同时探索"用Zustand"、"用Jotai"、"用Context+Reducer"三条路径，评估后推荐最适合当前项目的方案。

## 代码实践（10分钟）

### 实践：为代码审查设计一个结构化Prompt模板

**场景**：你的团队每天需要审查大量Pull Request，你希望AI能按照统一标准输出审查意见。

**基础版Prompt（效果一般）：**

```
请审查这段代码：
[代码粘贴]
```

**结构化CoT版Prompt（效果显著提升）：**

```markdown
## 角色设定
你是一位严格但友善的资深前端代码审查员，专注于可维护性、性能和安全。

## 审查框架（请按以下顺序逐步思考）

**Step 1 - 可读性检查**
- 变量命名是否语义化？
- 函数长度是否超过50行？
- 是否有 Magic Number / Magic String？

**Step 2 - 性能检查**
- 是否存在不必要的重渲染？
- 是否有可以Memo化的计算？
- 图片/资源加载是否优化？

**Step 3 - 类型安全**
- TypeScript类型是否足够精确？
- 是否有any或隐式any？
- 边缘情况是否被类型覆盖？

**Step 4 - 工程规范**
- 是否符合团队代码风格？
- 是否有足够的错误处理？
- 是否引入了不必要的依赖？

## 待审查代码
\`\`\`tsx
[PASTE_CODE_HERE]
\`\`\`

## 输出格式
对每项检查，按以下格式输出：
- ✅ 通过 / ⚠️ 警告 / ❌ 问题
- 具体位置（行号）
- 问题描述（一句话）
- 改进建议（带代码示例）

如果全部通过，输出："代码质量优秀，可以合并 🎉"
```

**为什么这个结构有效？**

1. **角色设定**激活了模型的"专家模式"，减少泛泛而谈
2. **分步指令**强制模型按优先级检查，不会遗漏关键维度
3. **输出格式约束**让结果可直接复制到PR评论中，减少二次编辑
4. **明确评分标准**让审查意见可执行，而不是"感觉不太好"

### 快速练习

用上面的模板审查以下代码片段，观察AI的输出质量差异：

```tsx
function UserList({ users }) {
  const [filter, setFilter] = useState('');
  const filtered = users.filter(u => u.name.includes(filter));
  
  return (
    <div>
      <input onChange={e => setFilter(e.target.value)} />
      {filtered.map(u => <UserCard user={u} />)}
    </div>
  );
}
```

> 💡 提示：注意对比"直接问AI审查这段代码"和"使用结构化CoT模板"的输出差异。

## 思考题（5分钟）

1. **在你的日常工作中，哪些任务最适合应用CoT Prompt？哪些任务反而会因为CoT而变慢？**

2. **Few-shot CoT中的示例数量存在"甜蜜点"：示例太少模型学不会模式，示例太多会占用上下文窗口。对于前端代码生成任务，你认为2个示例和5个示例哪个更优？为什么？**

3. **Tree of Thoughts需要多次LLM调用（生成候选→评估→搜索），在前端开发的真实场景中，什么时候值得付出这个成本？**
