昨天了解了 MCP 协议的核心概念，今天我们动手写一个**可运行的 MCP Server**。不是照着官方示例复制粘贴，而是理解它的运行时架构：Transport 层如何承载 JSON-RPC 消息、Server 如何声明自身能力、Client 如何发现并调用这些能力。掌握这些，你就能把任何内部工具、API 或业务逻辑封装成 AI 可调用的能力单元。

---

## 【核心概念】（5 分钟精读）

### 1. MCP Server 的三层架构

运行时的 MCP Server 可以拆解为三层，理解它们的关系是排查问题的关键：

| 层级 | 职责 | 对应代码 |
|------|------|----------|
| **Transport** | 字节流的读写（stdio / SSE / WebSocket） | `StdioServerTransport` |
| **Protocol** | JSON-RPC 2.0 的序列化、请求/响应匹配、错误处理 | `Server` 类内部 |
| **Handler** | 业务逻辑：Tool 执行、Resource 读取、Prompt 渲染 | 你实现的 `callTool` 等回调 |

Transport 层与 Handler 层通过 Protocol 层解耦。这意味着**你可以在不改动业务逻辑的情况下，把 Server 从 stdio 切换到 HTTP SSE**，只需要替换 Transport 实例。这种设计让 MCP Server 既能在本地被 Claude Desktop 调用（stdio），也能部署为远程服务（SSE）。

### 2. Capabilities 声明：Server 的"自我介绍"

MCP 采用能力协商机制。Server 启动时通过 `initialize` 握手告诉 Client："我支持哪些能力"。关键字段包括：

- `tools`: 是否支持工具调用，以及是否支持列表变更通知（`listChanged`）
- `resources`: 是否支持资源读取，以及是否支持订阅变更
- `prompts`: 是否支持提示模板

Client 根据这份声明决定 UI 中显示哪些交互入口。例如，若 Server 声明了 `tools`，Claude Desktop 会在输入框旁显示可用工具列表。

### 3. Tool 的 Schema 驱动设计

每个 Tool 必须提供 JSON Schema 描述其参数结构。这不是文档装饰，而是**运行时契约**：

- Client 用 Schema 做参数校验，提前拦截非法调用
- LLM 用 Schema 生成符合格式的参数（Function Calling 的核心机制）
- Server 用 Schema 做二次校验，防御幻觉参数

Schema 的质量直接决定 LLM 调用的成功率。对于复杂参数，建议用 `description` 字段写清每个字段的业务含义和示例值。

### 4. stdio vs SSE：选型考量

| 维度 | stdio | SSE |
|------|-------|-----|
| 部署方式 | 本地子进程 | 远程 HTTP 服务 |
| 适用场景 | Claude Desktop、本地 CLI 工具 | 共享服务、Web 应用后端 |
| 生命周期 | 随 Client 启动/退出 | 独立守护，可复用连接 |
| 安全边界 | 依赖 OS 进程隔离 | 依赖网络层鉴权 |

作为前端开发者，stdio 是入门首选：它让你的 Node.js 脚本立刻被 Claude Desktop 识别为"一个可用的 MCP Server"。

### 完整代码：`frontend-helper-server.ts`

以下 Server 封装了三个前端实用工具：分析 `package.json` 依赖树、检查过时依赖、生成组件文件路径建议。代码可直接运行。

```typescript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
  Tool,
} from "@modelcontextprotocol/sdk/types.js";
import { z } from "zod";

// ========== 1. 定义 Tool 的 Schema 与类型 ==========

const AnalyzeDepsSchema = z.object({
  packageJsonPath: z.string().describe("package.json 的绝对路径，例如 /Users/alice/project/package.json"),
  depth: z.number().min(1).max(3).optional().default(2)
    .describe("依赖分析深度，1=直接依赖，2=包含子依赖，3=深层"),
});

const CheckOutdatedSchema = z.object({
  cwd: z.string().describe("执行 npm outdated 的工作目录"),
});

const SuggestComponentPathSchema = z.object({
  componentName: z.string().describe("组件名，例如 UserProfile"),
  framework: z.enum(["react", "vue", "svelte"]).describe("前端框架"),
  feature: z.string().optional().describe("所属业务域，例如 user-auth"),
});

type ToolName = "analyze_deps" | "check_outdated" | "suggest_component_path";

// ========== 2. 初始化 Server 并声明 Capabilities ==========

const server = new Server(
  {
    name: "frontend-helper-server",
    version: "1.0.0",
  },
  {
    capabilities: {
      tools: {}, // 声明本 Server 支持 Tool 调用
    },
  }
);

// ========== 3. 注册 Tool 列表处理器 ==========

server.setRequestHandler(ListToolsRequestSchema, async () => {
  const tools: Tool[] = [
    {
      name: "analyze_deps",
      description:
        "分析 package.json 的依赖结构，返回直接依赖数量、devDependencies 占比、以及是否存在已知的冗余依赖（如同时使用 moment 和 dayjs）。",
      inputSchema: {
        type: "object",
        properties: {
          packageJsonPath: { type: "string" },
          depth: { type: "number", minimum: 1, maximum: 3 },
        },
        required: ["packageJsonPath"],
      },
    },
    {
      name: "check_outdated",
      description:
        "在指定目录运行 npm outdated --json，返回可升级依赖列表及推荐版本。",
      inputSchema: {
        type: "object",
        properties: {
          cwd: { type: "string" },
        },
        required: ["cwd"],
      },
    },
    {
      name: "suggest_component_path",
      description:
        "根据组件名和框架，生成推荐的项目文件路径（遵循 Feature-Sliced Design 或官方推荐结构）。",
      inputSchema: {
        type: "object",
        properties: {
          componentName: { type: "string" },
          framework: { type: "string", enum: ["react", "vue", "svelte"] },
          feature: { type: "string" },
        },
        required: ["componentName", "framework"],
      },
    },
  ];
  return { tools };
});

// ========== 4. 注册 Tool 调用处理器 ==========

server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;

  try {
    switch (name as ToolName) {
      case "analyze_deps": {
        const { packageJsonPath, depth } = AnalyzeDepsSchema.parse(args);
        const fs = await import("fs/promises");
        const raw = await fs.readFile(packageJsonPath, "utf-8");
        const pkg = JSON.parse(raw);

        const deps = Object.keys(pkg.dependencies || {});
        const devDeps = Object.keys(pkg.devDependencies || {});
        const redundancy = detectRedundancy([...deps, ...devDeps]);

        return {
          content: [
            {
              type: "text",
              text: JSON.stringify(
                {
                  totalDirect: deps.length + devDeps.length,
                  prodRatio: deps.length / (deps.length + devDeps.length || 1),
                  devRatio: devDeps.length / (deps.length + devDeps.length || 1),
                  redundancyHints: redundancy,
                  analyzedDepth: depth,
                },
                null,
                2
              ),
            },
          ],
        };
      }

      case "check_outdated": {
        const { cwd } = CheckOutdatedSchema.parse(args);
        const { execSync } = await import("child_process");
        let stdout: string;
        try {
          stdout = execSync("npm outdated --json", {
            cwd,
            encoding: "utf-8",
            timeout: 15000,
          });
        } catch (e: any) {
          // npm outdated 以非零退出码表示有过时依赖，stdout 仍有 JSON
          stdout = e.stdout || "{}";
        }
        const outdated = JSON.parse(stdout || "{}");
        const summary = Object.entries(outdated).map(([pkg, info]: [string, any]) => ({
          package: pkg,
          current: info.current,
          wanted: info.wanted,
          latest: info.latest,
          severity: calcUpgradeSeverity(info.current, info.wanted, info.latest),
        }));

        return {
          content: [
            {
              type: "text",
              text: JSON.stringify({ outdatedCount: summary.length, packages: summary }, null, 2),
            },
          ],
        };
      }

      case "suggest_component_path": {
        const { componentName, framework, feature } = SuggestComponentPathSchema.parse(args);
        const base = feature ? `src/features/${feature}/components` : `src/components`;
        const ext = framework === "vue" ? ".vue" : framework === "svelte" ? ".svelte" : ".tsx";
        const testExt = framework === "react" ? ".test.tsx" : ".spec" + ext;

        return {
          content: [
            {
              type: "text",
              text: JSON.stringify(
                {
                  component: `${base}/${componentName}/${componentName}${ext}`,
                  test: `${base}/${componentName}/${componentName}${testExt}`,
                  index: `${base}/${componentName}/index.ts`,
                  story: framework === "react" ? `${base}/${componentName}/${componentName}.stories.tsx` : null,
                  rationale: `遵循 ${framework} 社区推荐的扁平化目录结构，将组件及其附属文件（测试、Story、入口）聚合在同一目录。`,
                },
                null,
                2
              ),
            },
          ],
        };
      }

      default:
        throw new Error(`未知工具: ${name}`);
    }
  } catch (err: any) {
    return {
      content: [{ type: "text", text: `执行失败: ${err.message}` }],
      isError: true,
    };
  }
});

// ========== 5. 辅助函数 ==========

function detectRedundancy(deps: string[]): string[] {
  const hints: string[] = [];
  const set = new Set(deps.map((d) => d.toLowerCase()));
  if (set.has("moment") && set.has("dayjs")) hints.push("moment 与 dayjs 功能重叠，建议统一为 dayjs");
  if (set.has("lodash") && set.has("underscore")) hints.push("lodash 与 underscore 功能重叠");
  if (set.has("axios") && set.has("fetch") && deps.includes("node-fetch")) hints.push("axios 与 fetch 共存，评估是否可以统一");
  return hints;
}

function calcUpgradeSeverity(current: string, wanted: string, latest: string): "patch" | "minor" | "major" {
  const cur = current.split(".").map(Number);
  const wnt = wanted.split(".").map(Number);
  const lat = latest.split(".").map(Number);
  if (cur[0] !== lat[0]) return "major";
  if (cur[1] !== lat[1]) return "minor";
  return "patch";
}

// ========== 6. 启动 stdio Transport ==========

async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
  // stdio 模式下，日志只能写到 stderr，stdout 被 JSON-RPC 独占
  console.error("Frontend Helper MCP Server running on stdio");
}

main().catch((err) => {
  console.error("Server fatal error:", err);
  process.exit(1);
});
```

### 编译与配置 Claude Desktop

```json

    "frontend-helper": {
      "command": "node",
      "args": ["/absolute/path/to/dist/frontend-helper-server.js"]
    }
  }
}
```

## 【思考题】（5 分钟）

1. **架构决策题**：你团队内部有一个用于生成页面配置的低代码平台 API。如果要把它封装成 MCP Server，你会选择 stdio 还是 SSE 作为 Transport？如果团队有 50 名前端开发者，部署和权限方案应该如何设计？

2. **边界与权衡**：上面的 `check_outdated` Tool 直接调用了 `npm outdated`，这在某些场景下可能存在安全风险（例如 `postinstall` 脚本）。如果你的 MCP Server 需要处理用户上传的任意代码仓库路径，你会如何在 Server 层设计安全沙箱，防止命令注入或敏感文件读取？
