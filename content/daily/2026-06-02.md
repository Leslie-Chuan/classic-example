## 核心概念（5分钟精读）

### 1. VS Code的AI扩展三层模型

2025年底至2026年初，VS Code逐步开放了三层AI能力，构成了现代AI编辑器扩展的基石：

| 层级 | API | 职责 | 你的扩展在哪个位置 |
|------|-----|------|------------------|
| **L1：Language Access** | `vscode.lm` API | 访问用户已配置的LLM（Copilot/Copilot Chat/其他），无需管理API Key | 你**可以**直接用，但受限于模型选择和策略 |
| **L2：Tool/Agent Layer** | MCP Client API + `lm.tools` | 将外部能力（文件系统、Git、数据库）以结构化方式注入对话流 | 你**应该**在这里做主要创新 |
| **L3：UI/UX Layer** | Webview API + Chat API | 渲染流式输出、展示diff、接收用户反馈 | 你**必须**精心设计，这是差异化的关键 |

**关键洞察**：L1正在迅速 commoditized（商品化）。真正创造价值的是L2（你连接了哪些独特的工具/数据源）和L3（用户体验是否流畅）。高级前端开发者的机会在于：利用前端工程能力（组件化、状态管理、流式UI）打造差异化的L3体验，同时用Node.js能力构建高效的L2桥接。

### 2. MCP在编辑器架构中的精确位置

很多人把MCP理解为"又一个API调用方式"，这是不准确的。在编辑器语境下，MCP解决的是一个特定问题：**如何将编辑器内部状态（当前文件、光标位置、选中范围、项目结构）以LLM可理解的格式暴露给外部工具**。

```
┌─────────────────────────────────────────────┐
│           VS Code Extension Host             │
│  ┌─────────────┐    ┌──────────────────┐   │
│  │  Extension  │◄──►│  MCP Client      │   │
│  │  (你的代码)  │    │  (@modelcontext  │   │
│  │             │    │  /protocol SDK)   │   │
│  └──────┬──────┘    └────────┬─────────┘   │
│         │                    │ stdio/sse   │
│  ┌──────▼──────┐    ┌────────▼─────────┐   │
│  │  Webview    │    │  MCP Server      │   │
│  │  (React/Vue)│    │  (分析/搜索/构建) │   │
│  └─────────────┘    └──────────────────┘   │
└─────────────────────────────────────────────┘
```

注意这个架构的**不对称性**：MCP Client在Extension Host中运行（Node.js环境），而UI在Webview中运行（隔离的浏览器环境）。两者通过`postMessage`通信。这意味着你的状态管理必须跨进程设计——这是前端开发者最容易踩坑的地方。

### 3. 流式输出的技术实质

AI编辑器的"打字机效果"不是视觉糖，而是架构决策：

- **Server-Sent Events (SSE)** 或 **JSON Lines Stream** 是传输层标准
- **增量文本渲染**需要处理Markdown解析的中断状态（一个代码块可能分10次到达）
- **取消机制**必须贯穿整条链路：用户点击Stop → Extension Host中断HTTP请求 → MCP Server感知并停止生成 → UI进入可编辑状态
- **Diff预览**是高级功能：将AI生成的代码与原始代码做结构化对比，需要基于AST的diff算法（而非简单的文本diff）

对于5年+经验的前端开发者，你应该已经熟悉React的流式渲染（Suspense + Streaming SSR）。AI编辑器的流式输出是同一范式在编辑器环境的应用，只是状态管理更复杂（跨进程、可取消、需持久化上下文）。

### 2. src/mcpClient.ts

```typescript
/**
 * MCP Client 封装层
 * 
 * 设计决策：
 * 1. 使用 stdio transport，因为MCP Server通常是本地进程（Python/Node脚本）
 * 2. 维护单一长连接，避免每次分析都spawn新进程
 * 3. 暴露 cancel() 方法，支持用户中断
 */
import { Client } from '@modelcontextprotocol/sdk/client/index.js';
import { StdioClientTransport } from '@modelcontextprotocol/sdk/client/stdio.js';
import { spawn } from 'child_process';
import * as vscode from 'vscode';

export class McpAnalyzerClient {
  private client: Client | null = null;
  private transport: StdioClientTransport | null = null;
  private abortController: AbortController | null = null;

  /**
   * 连接到MCP Server
   * 实际项目中，server路径应从配置读取，支持多server管理
   */
  async connect(serverPath: string): Promise<void> {
    // 通过stdio启动MCP Server子进程
    const childProcess = spawn('node', [serverPath], {
      stdio: ['pipe', 'pipe', 'pipe'],
      env: { ...process.env, NODE_ENV: 'production' }
    });

    this.transport = new StdioClientTransport({
      stdin: childProcess.stdin,
      stdout: childProcess.stdout,
      stderr: childProcess.stderr
    });

    this.client = new Client({ name: 'vscode-mcp-analyzer', version: '0.1.0' });
    await this.client.connect(this.transport);

    // 连接成功后，获取可用工具列表（用于调试和UI展示）
    const tools = await this.client.listTools();
    console.log('[MCP] Connected. Available tools:', tools.tools.map(t => t.name));
  }

  /**
   * 调用分析工具
   * @param code 选中的代码片段
   * @param languageId 语言标识（typescript/javascript等）
   * @param onChunk 流式回调，每收到一个token调用一次
   */
  async analyzeCode(
    code: string,
    languageId: string,
    onChunk: (chunk: string) => void
  ): Promise<void> {
    if (!this.client) {
      throw new Error('MCP client not connected. Call connect() first.');
    }

    // 每次分析新建AbortController，支持独立取消
    this.abortController = new AbortController();

    try {
      // 调用MCP Server上的 'analyze_code_complexity' 工具
      // 实际工具名和参数应根据listTools()动态获取
      const result = await this.client.callTool(
        {
          name: 'analyze_code_complexity',
          arguments: {
            code,
            language: languageId,
            stream: true  // 请求流式返回
          }
        },
        undefined,  // 非结构化结果（流式场景通常不用schema约束）
        { signal: this.abortController.signal }
      );

      // 处理流式结果：MCP的流式响应通常以多次content更新形式返回
      // 这里简化处理，实际应监听transport的事件或实现自定义协议
      if (result.content && Array.isArray(result.content)) {
        for (const item of result.content) {
          if (item.type === 'text') {
            onChunk(item.text);
          }
        }
      }
    } catch (err) {
      if ((err as Error).name === 'AbortError') {
        onChunk('\n\n[Analysis cancelled by user]');
        return;
      }
      throw err;
    }
  }

  /** 取消当前分析 */
  cancel(): void {
    this.abortController?.abort();
  }

  /** 清理资源 */
  async disconnect(): Promise<void> {
    this.cancel();
    await this.transport?.close();
    this.client = null;
    this.transport = null;
  }
}
```

### 3. src/analyzer.ts

```typescript
/**
 * 分析器协调层
 * 
 * 职责：
 * 1. 管理Webview Panel生命周期
 * 2. 处理Extension Host与Webview的双向通信
 * 3. 维护分析状态（空闲/分析中/已取消）
 */
import * as vscode from 'vscode';
import { McpAnalyzerClient } from './mcpClient';
import * as path from 'path';

export class CodeAnalyzer {
  private panel: vscode.WebviewPanel | null = null;
  private mcpClient: McpAnalyzerClient;
  private disposables: vscode.Disposable[] = [];

  constructor(private context: vscode.ExtensionContext) {
    this.mcpClient = new McpAnalyzerClient();
  }

  /**
   * 主入口：分析当前选中的代码
   */
  async analyzeSelection(): Promise<void> {
    const editor = vscode.window.activeTextEditor;
    if (!editor || editor.selection.isEmpty) {
      vscode.window.showWarningMessage('请先选中一段代码');
      return;
    }

    const selectedText = editor.document.getText(editor.selection);
    const languageId = editor.document.languageId;

    // 确保Webview面板已创建
    this.ensurePanel();

    // 发送"开始分析"信号到Webview
    this.panel!.webview.postMessage({
      type: 'analysis-start',
      payload: {
        language: languageId,
        lineCount: selectedText.split('\n').length,
        preview: selectedText.slice(0, 200) + (selectedText.length > 200 ? '...' : '')
      }
    });

    try {
      // 延迟连接MCP（按需连接，避免扩展启动时就spawn进程）
      if (!this.mcpClient) {
        const config = vscode.workspace.getConfiguration('mcpAnalyzer');
        const serverPath = config.get<string>('serverPath') || 
          path.join(this.context.extensionPath, 'server', 'index.js');
        await this.mcpClient.connect(serverPath);
      }

      // 执行流式分析
      await this.mcpClient.analyzeCode(
        selectedText,
        languageId,
        (chunk) => {
          // 每收到一个chunk，实时推送到Webview
          this.panel?.webview.postMessage({
            type: 'analysis-chunk',
            payload: { chunk }
          });
        }
      );

      // 分析完成
      this.panel!.webview.postMessage({ type: 'analysis-complete' });
    } catch (err) {
      const message = err instanceof Error ? err.message : String(err);
      this.panel!.webview.postMessage({
        type: 'analysis-error',
        payload: { message }
      });
    }
  }

  /**
   * 用户点击Stop按钮时的处理
   */
  cancelAnalysis(): void {
    this.mcpClient.cancel();
    this.panel?.webview.postMessage({ type: 'analysis-cancelled' });
  }

  private ensurePanel(): void {
    if (this.panel) {
      this.panel.reveal(vscode.ViewColumn.Beside);
      return;
    }

    this.panel = vscode.window.createWebviewPanel(
      'mcpAnalyzer',
      'MCP Code Analysis',
      vscode.ViewColumn.Beside,
      {
        enableScripts: true,
        retainContextWhenHidden: true, // 切标签页时不丢失状态
        localResourceRoots: [this.context.extensionUri]
      }
    );

    this.panel.webview.html = this.getWebviewContent();

    // 监听Webview发来的消息（如Stop按钮点击）
    this.panel.webview.onDidReceiveMessage(
      (message) => {
        switch (message.type) {
          case 'cancel':
            this.cancelAnalysis();
            break;
          case 'open-settings':
            vscode.commands.executeCommand('workbench.action.openSettings', 'mcpAnalyzer');
            break;
        }
      },
      undefined,
      this.disposables
    );

    this.panel.onDidDispose(() => {
      this.panel = null;
    }, undefined, this.disposables);
  }

  /**
   * Webview HTML内容
   * 实际项目中应将JS/CSS分离到media目录，通过webview.asWebviewUri引用
   */
  private getWebviewContent(): string {
    return `<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>MCP Code Analysis</title>
  <style>
    :root {
      --bg: var(--vscode-editor-background);
      --fg: var(--vscode-editor-foreground);
      --border: var(--vscode-panel-border);
      --accent: var(--vscode-textLink-foreground);
      --code-bg: var(--vscode-textCodeBlock-background);
    }
    * { box-sizing: border-box; }
    body {
      margin: 0; padding: 16px;
      font-family: var(--vscode-font-family);
      background: var(--bg); color: var(--fg);
      line-height: 1.6;
    }
    .header {
      display: flex; justify-content: space-between; align-items: center;
      padding-bottom: 12px; border-bottom: 1px solid var(--border);
      margin-bottom: 16px;
    }
    .status { font-size: 12px; color: var(--vscode-descriptionForeground); }
    .status.analyzing { color: var(--accent); }
    .actions { display: flex; gap: 8px; }
    button {
      background: var(--accent); color: white; border: none;
      padding: 6px 14px; border-radius: 4px; cursor: pointer;
      font-size: 12px;
    }
    button:disabled { opacity: 0.5; cursor: not-allowed; }
    button.secondary { background: transparent; color: var(--fg); border: 1px solid var(--border); }

      background: var(--code-bg); padding: 12px; border-radius: 6px;

      font-size: 12px; white-space: pre-wrap; word-break: break-all;

    }

      background: var(--code-bg); padding: 16px; border-radius: 6px;

    .error { color: var(--vscode-errorForeground); padding: 12px; }
  </style>
</head>

  <div class="header">
    <div class="status" id="status">就绪 — 请选中代码并右键分析</div>
    <div class="actions">
      <button id="stopBtn" disabled>停止</button>
      <button id="settingsBtn" class="secondary">设置</button>
    </div>
  </div>
  <div class="preview" id="preview" style="display:none"></div>
  <div class="result" id="result"></div>

  <script>
    const vscode = acquireVsCodeApi();
    const statusEl = document.getElementById('status');
    const previewEl = document.getElementById('preview');
    const resultEl = document.getElementById('result');
    const stopBtn = document.getElementById('stopBtn');

      switch (msg.type) {
        case 'analysis-start':
          isAnalyzing = true;

          previewEl.textContent = msg.payload.preview;

      if (isAnalyzing) vscode.postMessage({ type: 'cancel' });
    });

    settingsBtn.addEventListener('click', () => {
      vscode.postMessage({ type: 'open-settings' });
    });
  </script>
</body>
</html>`;
  }

  dispose(): void {
    this.mcpClient.disconnect().catch(() => {});
    this.disposables.forEach(d => d.dispose());
    this.panel?.dispose();
  }
}
```

```typescript
/**
 * 扩展入口
 * 
 * 注册命令、管理全局实例生命周期
 */
import * as vscode from 'vscode';
import { CodeAnalyzer } from './analyzer';

let analyzer: CodeAnalyzer | null = null;

export function activate(context: vscode.ExtensionContext): void {
  analyzer = new CodeAnalyzer(context);

  // 注册命令：分析选中代码
  const analyzeCmd = vscode.commands.registerCommand(
    'mcpAnalyzer.analyzeSelection',
    () => analyzer?.analyzeSelection()
  );

  // 注册命令：取消当前分析（可绑定快捷键）
  const cancelCmd = vscode.commands.registerCommand(
    'mcpAnalyzer.cancelAnalysis',
    () => analyzer?.cancelAnalysis()
  );

  context.subscriptions.push(analyzeCmd, cancelCmd);

  // 扩展停用时自动清理
  context.subscriptions.push({
    dispose: () => analyzer?.dispose()
  });
}

export function deactivate(): void {
  analyzer?.dispose();
  analyzer = null;
}
```

### 5. 配套的简易MCP Server（server/index.js）

为了让整个项目**直接可运行**，这里提供一个简易的MCP Server实现。实际生产环境中，这个Server可以替换为真正的LLM分析服务。

```javascript
/**
 * 简易MCP Server：代码复杂度分析器
 * 
 * 运行方式：node server/index.js
 * 通信方式：stdio（标准输入输出）
 */
const { Server } = require('@modelcontextprotocol/sdk/server/index.js');
const { StdioServerTransport } = require('@modelcontextprotocol/sdk/server/stdio.js');

const server = new Server(
  { name: 'code-analyzer-server', version: '1.0.0' },
  { capabilities: { tools: {} } }
);

server.setRequestHandler('tools/list', async () => {
  return {
    tools: [
      {
        name: 'analyze_code_complexity',
        description: '分析代码片段的复杂度并提供优化建议',
        inputSchema: {
          type: 'object',
          properties: {
            code: { type: 'string', description: '代码片段' },
            language: { type: 'string', description: '编程语言' },
            stream: { type: 'boolean', description: '是否流式返回' }
          },
          required: ['code', 'language']
        }
      }
    ]
  };
});

server.setRequestHandler('tools/call', async (request) => {
  if (request.params.name !== 'analyze_code_complexity') {
    throw new Error(`Unknown tool: ${request.params.name}`);
  }

  const { code, language } = request.params.arguments;
  
  // 模拟分析过程（实际应调用LLM或静态分析工具）
  const lines = code.split('\n').length;
  const functions = (code.match(/function|=>|async/g) || []).length;
  const nesting = Math.max(...code.split('\n').map(l => {
    const match = l.match(/^(\s*)/);
    return match ? match[1].length / 2 : 0;
  }));

  const report = [
    `## 代码复杂度分析报告\n`,
    `- **语言**: ${language}\n`,
    `- **行数**: ${lines}\n`,
    `- **函数/箭头表达式数**: ${functions}\n`,
    `- **最大缩进层级**: ${nesting}\n\n`,
    `### 评估\n`,
    lines > 50 ? '⚠️ 代码片段较长，建议拆分为更小的函数。\n' : '✅ 代码长度适中。\n`,
    nesting > 4 ? '⚠️ 嵌套层级较深，考虑使用早返回（early return）或提取函数。\n' : '✅ 嵌套层级合理。\n`,
    functions > 5 ? '⚠️ 单个片段内函数较多，注意单一职责原则。\n' : '✅ 函数数量合理。\n`,
    `\n*此分析由MCP Server生成，仅供参考。*`
  ].join('');

  return {
    content: [{ type: 'text', text: report }]
  };
});

// 启动stdio传输
const transport = new StdioServerTransport();
server.connect(transport).then(() => {
  console.error('Code Analyzer MCP Server running on stdio');
});
```

## 思考题（5分钟）

### 问题1：MCP Server 应该放在哪里？

在上面的示例中，MCP Server是一个本地Node进程，通过stdio与Extension通信。但实际的AI编辑器（如Cursor）通常采用更复杂的架构：

- **方案A**：Server作为独立进程，用户自行安装和维护（类似Claude Desktop的MCP配置）
- **方案B**：Server由Extension自动管理（spawn/kill），对用户透明
- **方案C**：Server运行在远程（云端LLM服务），Extension通过SSE连接
- **方案D**：根本没有独立Server，Extension直接通过`vscode.lm`调用内置模型

**如果你要设计一个面向10万+开发者的商业级VS Code AI扩展，你会选择哪种架构？或者设计一种混合架构？请从维护成本、性能、安全性和用户体验四个维度分析。**

### 问题2：跨进程状态管理的边界

示例中的Webview与Extension Host通过`postMessage`通信，这是两个独立的JavaScript运行时。假设你要实现一个更复杂的功能：**AI生成代码后，用户可以在Webview中逐行接受/拒绝修改，最终应用回编辑器**。

这涉及到三种状态：
1. 编辑器原始文本（Extension Host可读写）
2. AI生成的候选文本（MCP Server返回）
3. 用户的接受/拒绝决策（Webview UI状态）

**你会如何设计这三者之间的状态同步机制？特别地，当用户在Webview中"接受第3-5行修改"时，如何避免Extension Host和Webview之间的竞态条件？请用伪代码或状态机描述你的设计。**
