## 一、核心概念（约 10 分钟）

### 1. 为什么前端工程师要会写 Babel 插件？

Babel 插件不只是转译 ES6 的工具，它是前端工程化中「代码即数据」的最佳入口。掌握插件开发后，你可以：

- **自动埋点**：在函数入口注入 `logger.track()`，无需业务代码改动。
- **代码迁移**：批量替换废弃 API（如 `ReactDOM.render` → `createRoot`）。
- **组件库按需引入**：把 `import { Button } from 'ui-lib'` 转译为 `import Button from 'ui-lib/button'`。
- **自定义 lint**：在编译期拦截特定代码模式，比 ESLint 更轻量。
- **低代码/可视化**：根据 DSL 生成组件骨架或表单代码。

> 本质上，Babel 插件让你用代码操作代码，把重复性、规范性的工作交给编译器自动完成。

### 2. Babel 插件的极简结构

一个 Babel 插件就是一个返回 visitor 对象的函数：

```js
module.exports = function (babel) {
  const { types: t } = babel;

  return {
    name: 'my-plugin',
    visitor: {
      Identifier(path) {
        // path: 当前节点 + 在 AST 中的位置信息
        // t:    @babel/types，用于创建/判断节点
      },
    },
  };
};
```

关键概念：

| 概念 | 作用 | 类比 |
|------|------|------|
| `AST` | 源代码的树形表示 | DOM 树 |
| `Visitor` | 遍历 AST 时触发的回调集合 | DOM 事件监听 |
| `Path` | 节点 + 父子关系 + 作用域信息 | DOM 节点 + 上下文 |
| `t` (types) | 创建新节点、判断节点类型 | `document.createElement` |
| `state` | 跨节点共享数据，接收插件选项 | React state |
| `opts` | 用户传入的插件配置 | 组件 props |

### 3. 写插件时的安全边界

- **不要修改正在遍历的父节点**：用 `path.replaceWith` / `path.remove` 替代直接操作父级。
- **注意作用域冲突**：新增变量时用 `path.scope.generateUidIdentifier` 自动生成唯一名。
- **保留源码映射**：生产环境插件建议配合 `sourceMaps: true`。
- **先做纯分析型插件**：首次开发建议只读不改，降低破坏代码的风险。

## 二、代码实践：开发一个「自动错误边界包裹」插件（约 20 分钟）

### 目标

编写 Babel 插件，自动把 React 函数组件包裹进 `withErrorBoundary(Component)`，并把组件名作为 `componentName` 参数传入，便于 Sentry 等监控工具定位问题。

### 输入 → 输出示例

**转换前**

```tsx
function UserProfile({ userId }: { userId: string }) {
  return <div>{userId}</div>;
}
```

**转换后**

```tsx
import { withErrorBoundary } from '@monitor/error-boundary';

function UserProfile({ userId }: { userId: string }) {
  return <div>{userId}</div>;
}

UserProfile = withErrorBoundary(UserProfile, { componentName: 'UserProfile' });
```

```bash

npm init -y

```

### 插件代码

**`plugins/auto-error-boundary.js`**

```js
const { declare } = require('@babel/helper-plugin-utils');

module.exports = declare((api, options) => {
  api.assertVersion(7);

  const { importSource = '@monitor/error-boundary', importName = 'withErrorBoundary' } = options;

  return {
    name: 'auto-error-boundary',
    visitor: {
      Program: {
        enter(path, state) {
          state.hasWrapped = false;
        },
        exit(path, state) {
          // 如果有包裹过组件，在文件末尾统一插入 import
          if (state.hasWrapped) {
            const { types: t } = api;
            const importDecl = t.importDeclaration(
              [t.importSpecifier(t.identifier(importName), t.identifier(importName))],
              t.stringLiteral(importSource)
            );
            path.node.body.unshift(importDecl);
          }
        },
      },

      FunctionDeclaration(path, state) {
        const { types: t } = api;
        const name = path.node.id?.name;

        // 只处理以大写字母开头的函数（React 组件约定）
        if (!name || !/^[A-Z]/.test(name)) return;

        // 避免重复包裹
        if (path.node.__wrapped) return;
        path.node.__wrapped = true;

        state.hasWrapped = true;

        // 创建：ComponentName = withErrorBoundary(ComponentName, { componentName: 'ComponentName' })
        const assignment = t.expressionStatement(
          t.assignmentExpression(
            '=',
            t.identifier(name),
            t.callExpression(t.identifier(importName), [
              t.identifier(name),
              t.objectExpression([
                t.objectProperty(
                  t.identifier('componentName'),
                  t.stringLiteral(name)
                ),
              ]),
            ])
          )
        );

        // 在函数声明后插入赋值语句
        path.insertAfter(assignment);
      },
    },
  };
});
```

### 测试脚本

**`test.js`**

```js
const babel = require('@babel/core');
const plugin = require('./plugins/auto-error-boundary');

const code = `
function UserProfile({ userId }: { userId: string }) {
  return <div>{userId}</div>;
}

function helper(x) {
  return x * 2;
}
`;

const result = babel.transformSync(code, {
  plugins: [
    [plugin, { importSource: '@monitor/error-boundary', importName: 'withErrorBoundary' }],
    '@babel/plugin-syntax-jsx',
    '@babel/plugin-syntax-typescript',
  ],
  filename: 'test.tsx',
});

console.log(result.code);
```

### 进阶挑战：支持箭头函数组件

如果组件是这样定义的：

```tsx
const UserProfile = ({ userId }: { userId: string }) => {
  return <div>{userId}</div>;
};
```

你可以扩展 visitor，在 `VariableDeclarator` 中检测右侧是否为箭头函数，并进行相应替换。思考一下：这种情况下如何避免 `let` / `const` 赋值冲突？

## 三、思考题

1. **命名约定 vs 类型推断**：本示例用首字母大写判断 React 组件，这在实际工程中是否可靠？能否结合 TypeScript Compiler API 或 Babel 的 TS 类型信息做更精确判断？
2. **幂等性**：如果同一个文件被 Babel 处理两次，插件会不会重复包裹？如何在插件中保证转换的幂等性？
3. **source map 与调试**：自动注入的代码会改变行号，如何确保生产环境报错时还能映射回原始源码？
4. **与 ESLint 的分工**：哪些代码改造适合用 Babel 插件做，哪些更适合用 ESLint + codemod？举例说明。
5. **性能边界**：在一个大型 monorepo 中运行自定义 Babel 插件，如何评估它对构建时长的影响？
