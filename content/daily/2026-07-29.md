## 核心概念（约 5 分钟）

### 1. 为什么图像处理适合用 Wasm？

前端图像处理通常涉及大量逐像素计算（灰度、模糊、边缘检测），属于**计算密集型任务**。JS 虽然是 JIT 编译，但在以下场景容易遇到瓶颈：

- 大量 `for` 循环遍历 Uint8ClampedArray；
- 位运算、浮点运算密集；
- 需要稳定、可预测的 GC 行为（避免 UI 卡顿）。

Wasm 提供接近原生的执行速度、可预测的性能、以及更紧凑的字节码，适合把“热路径”下沉。

### 2. 数据如何流通？

浏览器里最常见的图像是 `<canvas>` 或 `<img>`，通过 `ctx.getImageData()` 得到 `ImageData`，其 `data` 是一个 `Uint8ClampedArray`（RGBA 四通道）。

在 Wasm 里，这块数据可以通过 `wasm-bindgen` 直接以 `&[u8]` / `&mut [u8]` 暴露给 Rust，**零拷贝**地在线性内存里修改，避免反复序列化。

```
[Canvas] --getImageData--> [Uint8ClampedArray] --.wasm memory--> [Rust function] --修改--> [ImageData]
```

### 3. 关键工具链

- `wasm-pack`：构建、打包 Rust → Wasm/npm 包。
- `wasm-bindgen`：自动生成 JS/Wasm 胶水代码，处理字符串、数组、对象传递。
- `web-sys`：Rust 里调用 Web API（可选，本项目主要用裸内存操作）。

### 4. 性能对比要注意什么？

- **首次加载**：Wasm 文件通常比 JS 大，且需要编译时间；用 `WebAssembly.instantiateStreaming` 可以缓解。
- **调用开销**：JS → Wasm 边界调用有微小开销；对单像素调用不划算，应一次性批量处理。
- **数据拷贝**：通过共享内存传递 `Uint8Array` 视图，避免在 JS 与 Wasm 之间复制数据。
- **预热效应**：JS JIT 在多次运行后也会变快，要在“热启动”后多次采样再下结论。

### 2. `src/lib.rs` — 灰度转换

```rust
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn grayscale(data: &mut [u8]) {
    for chunk in data.chunks_exact_mut(4) {
        let r = chunk[0] as f32;
        let g = chunk[1] as f32;
        let b = chunk[2] as f32;
        // 使用标准的亮度公式
        let gray = (0.299 * r + 0.587 * g + 0.114 * b) as u8;
        chunk[0] = gray;
        chunk[1] = gray;
        chunk[2] = gray;
        // Alpha 通道保持不变
    }
}
```

构建命令：

```bash
wasm-pack build --target web
```

### 3. 浏览器端调用

```html
<input type="file" id="upload" accept="image/*" />
<canvas id="canvas"></canvas>
<button id="wasmBtn">Wasm 灰度</button>
<button id="jsBtn">JS 灰度</button>

<script type="module">
  import init, { grayscale } from "./pkg/wasm_image_filter.js";

  await init();

  const canvas = document.getElementById("canvas");
  const ctx = canvas.getContext("2d");

  // 加载图片并绘制到 canvas
  async function loadImage(file) {
    const img = new Image();
    img.src = URL.createObjectURL(file);
    await new Promise((resolve) => (img.onload = resolve));
    canvas.width = img.width;
    canvas.height = img.height;
    ctx.drawImage(img, 0, 0);
  }

  function jsGrayscale(imageData) {
    const d = imageData.data;
    for (let i = 0; i < d.length; i += 4) {
      const gray = 0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2];
      d[i] = d[i + 1] = d[i + 2] = gray;
    }
    return imageData;
  }

  document.getElementById("wasmBtn").onclick = () => {
    const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
    console.time("wasm");
    grayscale(imageData.data); // 直接修改底层 Uint8ClampedArray
    console.timeEnd("wasm");
    ctx.putImageData(imageData, 0, 0);
  };

  document.getElementById("jsBtn").onclick = () => {
    const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
    console.time("js");
    jsGrayscale(imageData);
    console.timeEnd("js");
    ctx.putImageData(imageData, 0, 0);
  };
</script>
```

### 4. 性能测量小建议

```js
function bench(fn, imageData, runs = 100) {
  // 预热
  fn(structuredClone(imageData));
  const start = performance.now();
  for (let i = 0; i < runs; i++) {
    fn(structuredClone(imageData));
  }
  return (performance.now() - start) / runs;
}
```

> 提示：实际灰度转换在现代浏览器里差距可能不大，本练习的重点是掌握 **“如何把 JS 热路径搬到 Wasm”** 的完整链路。
