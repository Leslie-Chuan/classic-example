## 今日主题

理解浏览器如何把一串 HTML/CSS/JS 最终变成屏幕上的像素。重点掌握关键渲染路径（Critical Rendering Path）的五个阶段、每阶段的性能敏感点，以及前端开发者常用的优化手段（避免强制同步布局、分层、合成优化等）。

---

## 核心概念（约 10 分钟）

### 1. 关键渲染路径的五个阶段

浏览器收到响应后，会依次执行以下阶段：

| 阶段 | 输入 | 输出 | 前端需要关注的点 |
|---|---|---|---|
| **1. 解析 HTML** | 字节流 | DOM Tree | 遇到 `<script>` 会阻塞解析；`defer`/`async` 可缓解 |
| **2. 解析 CSS** | CSS 文件、`<style>` | CSSOM Tree | 选择器复杂度、@import 阻塞、Unused CSS |
| **3. 生成渲染树** | DOM + CSSOM | Render Tree | 不可见元素（`display:none`）不会进入渲染树 |
| **4. 布局（Layout / Reflow）** | Render Tree | 几何信息（盒模型、位置） | 读取布局属性再修改样式会触发强制同步布局 |
| **5. 绘制与合成** | 分层后的图层 | 像素位图 | Paint → Raster → Composite；GPU 加速在这里发力 |

这五个阶段并非每次都全部执行。滚动、动画通常只需 **Composite**，是最高效的阶段。

### 2. DOM、CSSOM、Render Tree 的关系

- **DOM Tree**：只描述文档结构，不包含样式。
- **CSSOM Tree**：只描述样式规则，不绑定具体元素。
- **Render Tree**：把 DOM 中可见节点与匹配样式合并，是布局和绘制的输入。

一个常见误区：`visibility: hidden` 的节点会进入 Render Tree（占据空间但不绘制），而 `display: none` 不会。

### 3. 布局与强制同步布局（Forced Synchronous Layout）

当 JavaScript 读取布局相关属性（如 `offsetWidth`、`getBoundingClientRect()`）后紧接着修改样式，浏览器为了返回正确值，必须立即执行一次布局。这种在下一帧之前被迫提前执行的布局就是 **Forced Synchronous Layout（FSL）**，也叫 Layout Thrashing 的前奏。

```js
// 坏味道：交替读、写布局属性
for (let el of elements) {
  const width = el.offsetWidth;        // 读 → 触发布局
  el.style.width = (width * 0.9) + 'px'; // 写 → 使布局失效
}
```

优化思路：**批量读取、批量写入**，或把写操作放到 `requestAnimationFrame` 中。

### 4. 绘制、栅格化与合成

- **Paint**：把 Render Tree 的绘制指令（draw calls）记录到图层上。
- **Raster（栅格化）**：把矢量绘制指令变成位图（tile），可在主线程或 GPU 栅格化线程完成。
- **Composite（合成）**：Compositor Thread 把多个栅格化后的图层按正确顺序叠加，生成最终帧。

为什么 `transform` 和 `opacity` 性能最好？因为它们只影响 **合成阶段**，不会触发布局和重绘。浏览器甚至可以在 Compositor Thread 直接完成动画，不阻塞主线程。

### 5. 图层（Layer）与层爆炸

浏览器会自动把某些元素提升为独立图层（如 `transform: translateZ(0)`、`will-change: transform`、`video`、`canvas`、fixed 定位等）。独立图层的好处是：修改它只需重绘/合成该图层，不用影响整个页面。

但要注意 **层爆炸（Layer Explosion）**：过多图层会占用大量 GPU 内存，反而导致合成变慢。`will-change` 应谨慎使用，动画结束后及时移除。

### 6. 渲染管线的性能预算

目标 60fps 意味着每帧只有 **16.67ms**。浏览器本身还要处理输入、合成等，留给 JavaScript + 样式 + 布局 + 绘制的时间通常只有 **10-12ms**。

常见帧预算分配：
- Scripting：尽量 < 5ms
- Style & Layout：尽量 < 3ms
- Paint & Raster：尽量 < 3ms
- Composite：通常 < 1ms

## 代码实践（约 15 分钟）

### 实践 1：用 DevTools Performance 面板观察渲染管线

1. 打开任意复杂页面（如一个带大量 DOM 的 Dashboard）。
2. 按 `Cmd/Ctrl + Shift + P`，输入 `Performance`，打开性能面板。
3. 点击录制按钮，滚动页面或点击按钮触发 UI 变化，录制 3-5 秒后停止。
4. 在火焰图中找到以下颜色区域：
   - **紫色（Rendering）**：样式计算、Layout、Layerize。
   - **绿色（Painting）**：Paint、Raster。
   - **合成（Composite）**：通常显示为 Compositor Thread 的活动。
5. 点击一个长任务，查看底部 Summary 面板中的 **Recalculate Style → Layout → Paint → Composite** 链路。

### 实践 2：观察并修复强制同步布局

创建一个简单的 HTML 文件：

```html
<!DOCTYPE html>
<html>
<head>
  <style>
    .box { width: 100px; height: 20px; margin: 4px; background: #3b82f6; }
  </style>
</head>
<body>
  <div id="container"></div>
  <button id="bad">Bad: 强制同步布局</button>
  <button id="good">Good: 批量读写</button>

  <script>
    const container = document.getElementById('container');
    for (let i = 0; i < 200; i++) {
      const div = document.createElement('div');
      div.className = 'box';
      container.appendChild(div);
    }

    document.getElementById('bad').addEventListener('click', () => {
      const boxes = document.querySelectorAll('.box');
      for (let box of boxes) {
        const w = box.offsetWidth;              // 读
        box.style.width = (w * 1.05) + 'px';    // 写
      }
    });

    document.getElementById('good').addEventListener('click', () => {
      const boxes = document.querySelectorAll('.box');
      // 先批量读取
      const widths = Array.from(boxes).map(b => b.offsetWidth);
      // 再批量写入
      requestAnimationFrame(() => {
        boxes.forEach((box, i) => {
          box.style.width = (widths[i] * 1.05) + 'px';
        });
      });
    });
  </script>
</body>
</html>
```

在 DevTools Performance 中分别点击两个按钮，对比：
- Bad 版本会出现大量 **Recalculate Style → Layout** 交替。
- Good 版本只出现一次 Layout。

### 实践 3：验证 transform 与 opacity 的合成优化

创建两个动画对比：

```html
<style>
  .anim-left { animation: moveLeft 2s infinite alternate; }
  @keyframes moveLeft {
    from { left: 0; }
    to { left: 200px; }
  }

  .anim-transform { animation: moveTransform 2s infinite alternate; }
  @keyframes moveTransform {
    from { transform: translateX(0); }
    to { transform: translateX(200px); }
  }

  .demo { position: relative; width: 50px; height: 50px; margin: 20px; }
</style>

<div class="demo anim-left" style="background:#ef4444;">left</div>
<div class="demo anim-transform" style="background:#22c55e;">transform</div>
```

在 DevTools 的 Rendering 面板中勾选 **Paint flashing**，观察：
- `left` 动画：每一帧都会触发红色闪烁（Paint + Layout）。
- `transform` 动画：几乎没有闪烁（仅 Composite）。

### 实践 4：使用 Layers 面板检查图层

1. 打开 DevTools，按 `Esc` 打开 Console Drawer。
2. 点击菜单（⋮）→ More tools → Layers。
3. 在页面上移动鼠标，查看哪些元素被提升为独立图层。
4. 尝试给一个元素添加 `will-change: transform`，观察是否新增图层；动画结束后移除，再观察图层是否消失。
