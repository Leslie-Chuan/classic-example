## 一、核心概念：AI 原生 vs AI 增强

### 1.1 两个本质区别

| 维度 | AI 增强型产品（AI-Enhanced） | AI 原生产品（AI-Native） |
|------|----------------------------|------------------------|
| AI 的位置 | 工具层、功能模块 | 产品核心、交互主轴 |
| 用户心智 | "我先用工具，再让 AI 帮我" | "我直接表达意图，产品来理解" |
| 交互范式 | 表单 + 按钮 + 菜单 | 自然语言 / 多模态输入 + 流式输出 |
| 状态模型 | 用户操作 → 状态变更 → UI 更新 | 用户意图 → AI 推理 → 协作生成 |
| 错误处理 | 报错、禁用按钮 | 不确定性成为常态，需要回退与修正 |
| 典型代表 | Notion AI、GitHub Copilot Chat | v0.dev、Bolt.new、Lovable、Claude Code |

### 1.2 AI 原生的四个设计原则

#### 原则 1：意图优先（Intent-First）

传统界面：用户必须知道功能在哪里、怎么操作。  
AI 原生界面：用户表达"我想做什么"，系统理解并执行。

例子：

- 传统：打开 Figma → 选择画板 → 拖入组件 → 调整样式 → 导出
- AI 原生："帮我做一个 SaaS 落地页，主色深蓝，带定价卡片和 CTA"

#### 原则 2：生成式界面（Generative UI）

UI 不再是固定的，而是由模型根据上下文和用户意图动态生成。

前端开发者要思考的问题：

- 如何设计"可生成的组件"？
- 如何保证生成结果的可预测性？
- 如何用类型系统约束 AI 输出？

#### 原则 3：人机协作循环（Human-in-the-Loop）

AI 原生产品不是让 AI 一次性做对，而是让人类和 AI 在多次迭代中共同推进。

关键模式：

- 提出 → 生成 → 审查 → 修正 → 确认
- 每一次循环都让用户更接近目标

#### 原则 4：不确定性工程（Uncertainty Engineering）

LLM 会出错、会幻觉、会慢。产品设计要把"不确定性"当作一等公民。

前端层面的体现：

- 流式输出 + Skeleton，降低等待焦虑
- 置信度提示："这是 AI 生成的建议，请确认"
- 一键回退 / 重新生成 / 分支对比
- 错误边界捕获异常输出

## 二、本周知识串联：一个 AI 原生产品的最小架构

假设我们要设计一个 **"AI 原生落地页生成器"**，它会用到本周所有知识点。

```
┌─────────────────────────────────────────────────────────────┐
│                     用户输入层                               │
│  自然语言 / 图片参考 / 语音描述 / 拖拽素材                     │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   意图理解 + 结构化输出                        │
│  LLM 解析需求 → 输出 JSON Schema（布局、文案、样式、交互）      │
│  用 Zod / JSON Schema 做运行时校验                            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                     生成式 UI 层                             │
│  React Server Component / 流式组件                            │
│  根据结构化输出渲染可编辑的组件                                │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   协作与状态层                               │
│  Yjs 实时协作 + AI 状态（生成中 / 待确认 / 已应用）            │
│  传统状态管理：用户手动调整的样式参数                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   推理与成本优化层                            │
│  Edge AI（WebLLM）本地推理小模型                               │
│  云端大模型处理复杂生成任务                                    │
│  Token 预算 + 智能降级（长内容分块、摘要、缓存）                │
└─────────────────────────────────────────────────────────────┘
```

### 关键设计决策

1. **输入层**：支持多模态，但给用户提供"渐进式提示"，降低表达成本。
2. **意图解析**：LLM 输出结构化 Schema，而不是直接输出 JSX。Schema 是人和 AI 之间的契约。
3. **生成式 UI**：用 Server Component 流式渲染，Skeleton 占位，逐步填充内容。
4. **协作层**：多个用户可以实时修改同一生成结果，AI 状态要可视化。
5. **推理层**：简单任务走 Edge，复杂任务走云端，同时控制 Token 成本。

## 三、代码实践：用结构化输出驱动生成式 UI

本节用 15 分钟做一个最小可运行示例：用户输入一句话，LLM 输出结构化页面描述，前端渲染预览。

### 3.1 定义页面 Schema

```typescript
// types/page-schema.ts
import { z } from 'zod';

export const SectionSchema = z.object({
  type: z.enum(['hero', 'features', 'pricing', 'cta', 'footer']),
  title: z.string(),
  subtitle: z.string().optional(),
  style: z.object({
    background: z.string().default('white'),
    align: z.enum(['left', 'center', 'right']).default('center'),
  }),
  blocks: z.array(
    z.object({
      kind: z.enum(['heading', 'text', 'button', 'card']),
      content: z.string(),
      variant: z.string().optional(),
    })
  ),
});

export const PageSchema = z.object({
  title: z.string(),
  theme: z.object({
    primaryColor: z.string().default('#2563eb'),
    fontFamily: z.string().default('sans-serif'),
  }),
  sections: z.array(SectionSchema),
});

export type PageSchemaType = z.infer<typeof PageSchema>;
```

### 3.2 提示词模板

```typescript
// prompts/page-design.ts
export function buildPageDesignPrompt(userInput: string) {
  return `
你是一名资深前端设计师。请将用户的落地页需求转换为结构化的页面描述。

用户输入："""${userInput}"""

请严格输出以下 JSON 格式，不要包含任何额外说明：

{
  "title": "页面标题",
  "theme": { "primaryColor": "#主色", "fontFamily": "sans-serif" },
  "sections": [
    {
      "type": "hero",
      "title": "主标题",
      "subtitle": "副标题",
      "style": { "background": "white", "align": "center" },
      "blocks": [
        { "kind": "heading", "content": "..." },
        { "kind": "text", "content": "..." },
        { "kind": "button", "content": "立即试用", "variant": "primary" }
      ]
    }
  ]
}

可用的 section type：hero, features, pricing, cta, footer。
可用的 block kind：heading, text, button, card。
`;
}
```

### 3.3 渲染生成式组件

```tsx
// components/GeneratedPage.tsx
import { PageSchemaType } from '../types/page-schema';

export function GeneratedPage({ page }: { page: PageSchemaType }) {
  return (
    <div style={{ fontFamily: page.theme.fontFamily }}>
      {page.sections.map((section, idx) => (
        <section
          key={idx}
          style={{
            background: section.style.background,
            textAlign: section.style.align,
            padding: '4rem 2rem',
          }}
        >
          <h2 style={{ color: page.theme.primaryColor }}>{section.title}</h2>
          {section.subtitle && <p>{section.subtitle}</p>}

          {section.blocks.map((block, bIdx) => {
            if (block.kind === 'heading') {
              return <h3 key={bIdx}>{block.content}</h3>;
            }
            if (block.kind === 'text') {
              return <p key={bIdx}>{block.content}</p>;
            }
            if (block.kind === 'button') {
              return (
                <button
                  key={bIdx}
                  style={{
                    background: page.theme.primaryColor,
                    color: 'white',
                    padding: '0.75rem 1.5rem',
                    border: 'none',
                    borderRadius: '0.5rem',
                  }}
                >
                  {block.content}
                </button>
              );
            }
            if (block.kind === 'card') {
              return (
                <div
                  key={bIdx}
                  style={{
                    border: '1px solid #e5e7eb',
                    borderRadius: '0.75rem',
                    padding: '1.5rem',
                    margin: '1rem auto',
                    maxWidth: '300px',
                  }}
                >
                  {block.content}
                </div>
              );
            }
            return null;
          })}
        </section>
      ))}
    </div>
  );
}
```

### 3.4 运行流程

```tsx
// app/page.tsx (Next.js App Router 示例)
'use client';

import { useState } from 'react';
import { buildPageDesignPrompt } from '../prompts/page-design';
import { GeneratedPage } from '../components/GeneratedPage';
import { PageSchema, PageSchemaType } from '../types/page-schema';

export default function Home() {
  const [input, setInput] = useState('');
  const [page, setPage] = useState<PageSchemaType | null>(null);
  const [loading, setLoading] = useState(false);

  async function handleGenerate() {
    setLoading(true);
    try {
      const prompt = buildPageDesignPrompt(input);
      const res = await fetch('/api/design', {
        method: 'POST',
        body: JSON.stringify({ prompt }),
      });
      const json = await res.json();

      // 运行时校验：把不确定性关在笼子里
      const parsed = PageSchema.parse(json);
      setPage(parsed);
    } catch (err) {
      console.error('生成或校验失败', err);
      alert('AI 输出不符合预期，请重试或调整描述。');
    } finally {
      setLoading(false);
    }
  }

  return (
    <main style={{ maxWidth: '800px', margin: '0 auto', padding: '2rem' }}>
      <h1>AI 原生落地页生成器</h1>
      <textarea
        value={input}
        onChange={(e) => setInput(e.target.value)}
        rows={4}
        placeholder="描述你想要的落地页..."
        style={{ width: '100%', padding: '1rem' }}
      />
      <button onClick={handleGenerate} disabled={loading}>
        {loading ? '生成中...' : '生成页面'}
      </button>

      {loading && <p>正在理解你的意图...</p>}
      {page && <GeneratedPage page={page} />}
    </main>
  );
}
```

### 3.5 实践要点

1. **Schema 是契约**：AI 输出必须可校验，不能让模型直接生成可执行代码。
2. **流式渲染**：在真实产品中，把 `loading` 替换为流式 Skeleton 和逐步填充的区块。
3. **错误边界**：用 Zod 捕获结构错误，用 React Error Boundary 捕获渲染错误。
4. **状态分离**：用户手动调整的样式存入传统状态，AI 生成结果存入 AI 状态。
