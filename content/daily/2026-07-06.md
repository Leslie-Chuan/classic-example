## 今日主题

**Edge AI：在浏览器中运行 LLM（WebLLM）**

当 AI 从云端走向终端，浏览器正在成为运行大语言模型的新战场。借助 WebGPU 和模型量化技术，我们可以在用户设备上直接运行小型 LLM，实现零服务器成本、零网络延迟、完全离线的智能体验。今天我们将理解 WebLLM 的核心原理，并动手搭建一个最小化的浏览器端聊天应用。

---

## 核心概念（15 分钟）

### 1. 为什么要把 LLM 放到浏览器里？

云端 LLM 虽然强大，但存在几个固有瓶颈：

- **隐私敏感**：用户代码、文档、聊天记录需要上传到第三方服务器。
- **网络延迟**：每次交互都需要一次或多次 API 往返，流式响应也受带宽影响。
- **成本压力**：Token 计费模式下，高频应用的服务端成本随用户增长线性上升。
- **离线可用**：无网络环境下（飞行模式、内网、边缘场景）完全无法使用。

浏览器端 LLM 的优势：

| 维度 | 浏览器端 LLM | 云端 LLM |
|------|-------------|---------|
| 隐私 | 数据不出设备 | 需上传至服务端 |
| 延迟 | 本地推理，极低 | 受网络影响 |
| 成本 | 无服务端 Token 费用 | 按 Token 计费 |
| 离线 | 可离线运行 | 必须联网 |
| 模型能力 | 受设备性能限制，通常用小模型 | 可运行最强模型 |

**关键洞察**：Edge AI 不是要替代云端大模型，而是在"敏感、低延迟、低成本、离线"场景中提供补充能力。

### 2. WebLLM 是什么？

WebLLM 是由 MLC（Machine Learning Compilation）团队推出的项目，目标是在浏览器中直接运行 LLM。它的核心技术栈包括：

- **TVM Unity**：将深度学习模型编译为高效的可执行代码。
- **WebGPU**：在浏览器中执行 GPU 计算，替代已被废弃的 WebGL 方案。
- **模型量化（Quantization）**：将 FP32/FP16 权重量化为 INT4/INT8，显著减小模型体积。
- **wasm + JS Runtime**：管理模型下载、缓存、推理调度。

### 3. WebGPU：浏览器里的 GPU 计算

WebGPU 是现代浏览器的新一代图形与计算 API，相比 WebGL：

- 专为通用计算设计（Compute Shader）。
- 更贴近底层 GPU 架构，推理效率更高。
- 支持内存映射缓冲和异步命令队列。

目前 Chrome 113+、Edge、Firefox Nightly 已支持 WebGPU。

### 4. 模型量化：让小模型能装进浏览器

量化是把模型权重从高精度浮点数映射到低精度整数的过程：

- **FP32 → INT8**：模型体积缩小到 1/4，推理速度提升。
- **FP32 → INT4**：体积缩小到 1/8，但精度损失更明显。

常用量化方案：

| 精度 | 7B 模型大小 | 适用场景 |
|------|------------|---------|
| FP16 | ~14 GB | 无法运行在消费级设备 |
| INT8 | ~7 GB | 高端设备可运行 |
| INT4 | ~3.5 GB | 主流笔记本/台式机可运行 |
| INT4 分组量化 | ~3.5 GB | 精度与速度的平衡方案 |

WebLLM 常用的预量化模型包括 Llama-3-8B、Phi-3-mini、Qwen2-7B 等。

### 5. WebLLM 的架构概览

```
┌─────────────────────────────────────┐
│           Web Application           │
│  (React/Vue/Vanilla + @mlc-ai/web-llm) │
├─────────────────────────────────────┤
│         MLCEngine / ChatModule      │
│   (模型加载、缓存、推理调度、流式输出)   │
├─────────────────────────────────────┤
│      WebGPU Compute Shader Runtime  │
│   (在 GPU 上执行矩阵运算)              │
├─────────────────────────────────────┤
│        IndexedDB / Cache Storage    │
│   (模型权重缓存，避免每次重新下载)        │
└─────────────────────────────────────┘
```

### 6. 边缘 AI 与云端 AI 的协作模式

在设计真实产品时，通常采用分层策略：

- **本地小模型**：处理敏感、高频、低复杂度任务（如自动补全、简单分类、本地摘要）。
- **云端大模型**：处理复杂推理、长上下文、需要最新知识的任务。
- **智能降级**：离线时自动切换到本地模型，联网时再恢复云端能力。

## 代码实践（12 分钟）

### 实践目标

使用 `@mlc-ai/web-llm` 在浏览器中搭建一个最简聊天应用，支持模型加载、流式输出和对话历史。

### 步骤 1：创建项目并安装依赖

```bash
npm create vite@latest web-llm-chat -- --template vanilla
cd web-llm-chat
npm install
npm install @mlc-ai/web-llm
```

### 步骤 2：准备 HTML 结构

```html
<!-- index.html -->
<div id="app">
  <h1>浏览器端 LLM 聊天</h1>
  <div id="status">正在初始化引擎...</div>
  <div id="chat"></div>
  <textarea id="input" rows="3" placeholder="输入消息..."></textarea>
  <button id="send">发送</button>
</div>
```

### 步骤 3：初始化 WebLLM 引擎

```js
// main.js
import * as webllm from '@mlc-ai/web-llm'

const initProgressCallback = (report) => {
  document.getElementById('status').textContent = report.text
}

const selectedModel = 'Llama-3.1-8B-Instruct-q4f32_1-MLC'

const engine = await webllm.CreateMLCEngine(selectedModel, {
  initProgressCallback,
})

document.getElementById('status').textContent = '模型加载完成，可以开始对话了'
```

### 步骤 4：实现流式对话

```js
const chatBox = document.getElementById('chat')
const inputEl = document.getElementById('input')
const sendBtn = document.getElementById('send')

const messages = [
  {
    role: 'system',
    content: '你是一个友好、简洁的前端开发助手。',
  },
]

function appendMessage(role, content) {
  const div = document.createElement('div')
  div.className = `message ${role}`
  div.textContent = `${role}: ${content}`
  chatBox.appendChild(div)
}

sendBtn.addEventListener('click', async () => {
  const userText = inputEl.value.trim()
  if (!userText) return

  messages.push({ role: 'user', content: userText })
  appendMessage('user', userText)
  inputEl.value = ''

  const replyEl = document.createElement('div')
  replyEl.className = 'message assistant'
  replyEl.textContent = 'assistant: '
  chatBox.appendChild(replyEl)

  const stream = await engine.chat.completions.create({
    messages,
    stream: true,
    temperature: 0.7,
  })

  let reply = ''
  for await (const chunk of stream) {
    const delta = chunk.choices[0]?.delta?.content || ''
    reply += delta
    replyEl.textContent = `assistant: ${reply}`
  }

  messages.push({ role: 'assistant', content: reply })
})
```

### 步骤 5：模型缓存与二次加载优化

WebLLM 默认会将模型权重缓存到浏览器的 Cache Storage 中。你可以通过检查 `chrome://gpu` 确认 WebGPU 是否可用，并通过 Chrome DevTools 的 Application 面板查看缓存状态。

```js
// 可选：自定义缓存配置
const engine = await webllm.CreateMLCEngine(selectedModel, {
  initProgressCallback,
  appConfig: {
    // 使用自定义模型源或 CDN
  },
})
```

### 步骤 6：添加基础样式（可选）

```css
.message {
  margin: 8px 0;
  padding: 10px;
  border-radius: 6px;
}
.message.user {
  background: #e3f2fd;
}
.message.assistant {
  background: #f3e5f5;
}

  width: 100%;
  margin-top: 12px;
}
```

运行项目：

```bash
npm run dev
```

> 注意：首次加载模型需要下载数 GB 权重文件，请确保网络稳定。后续会从缓存读取。
