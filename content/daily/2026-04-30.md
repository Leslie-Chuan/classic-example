## 今日主题（1 分钟阅读）

Claude Code 是 Anthropic 在 2025 年初发布的 AI 编码代理工具，它并非简单的"聊天式编程助手"，而是一个具备**自主决策能力**的 Agent 系统。今天我们将拆解它的核心架构，理解一个生产级 AI 编码代理的设计哲学，并动手实现一个极简版的 Agent Loop。

**关键认知转变**：从"AI 辅助写代码"到"AI 代理自主完成任务"——这不是工具维度的升级，而是**交互范式**的彻底重构。

---

## 核心概念（5 分钟精读）

### 1. Agent Loop：感知-推理-行动的闭环

Claude Code 的核心是一个永不停歇的循环，每一轮迭代包含三个步骤：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   感知      │ → │   推理      │ → │   行动      │
│ (Perceive)  │    │  (Reason)   │    │   (Act)     │
└─────────────┘    └─────────────┘    └─────────────┘
      ↑                                      │
      └──────────── 结果反馈 ←───────────────┘
```

- **感知**：读取文件系统、执行命令、获取外部环境状态
- **推理**：LLM 基于当前上下文决定下一步行动（调用哪个 Tool、如何修改代码）
- **行动**：执行 Tool 调用，产生副作用（文件写入、命令执行）

与单次 Chat Completion 的本质区别在于：**Agent 拥有记忆和状态**，能够在多轮交互中逐步逼近目标。这要求系统设计者必须解决三个难题——**上下文截断、错误恢复、无限循环防护**。

### 2. Tool Use：LLM 与物理世界的接口

Claude Code 通过 Anthropic 的 Tool Use（Function Calling）机制，将 LLM 的文本生成能力转化为对真实世界的操作。其设计精髓在于**Schema-first**：

每个 Tool 都是一个严格类型的 JSON Schema 接口，LLM 不是"猜测"该做什么，而是在约束空间内进行**结构化决策**。这种约束既降低了幻觉风险，也为安全审计提供了可拦截的边界。

Claude Code 的工具集大致分为四类：

| 类别 | 代表工具 | 设计意图 |
|------|----------|----------|
| 文件读取 | `read_file`, `read_directory` | 让 Agent"看到"代码库 |
| 文件修改 | `edit_file`, `write_file` | 精确、可回滚的代码变更 |
| 命令执行 | `execute_command` | 与构建工具、测试框架集成 |
| 交互询问 | `ask_user` | 在不确定性时寻求人类确认 |

### 3. 上下文管理：十万行代码中的精准定位

一个真实项目往往远超 LLM 的上下文窗口（Claude 3.7 Sonnet 为 200K tokens，约 15 万行代码的容量）。Claude Code 的上下文策略不是简单"全部塞进 prompt"，而是采用**动态检索 + 分层摘要**：

- **项目骨架层**：始终保留目录结构、关键配置文件（package.json、tsconfig.json）的摘要
- **工作集层**：根据当前任务动态加载相关文件（通过 AST 依赖分析或简单的 import 追踪）
- **历史层**：最近 N 轮对话的完整记录，但会对过时的 Tool 结果进行压缩摘要

这种分层策略本质上是在模拟人类开发者的工作记忆——你不会同时记住整个代码库，但知道去哪里找什么。

### 4. 安全沙箱：权限的最小化原则

Claude Code 的安全模型遵循"默认拒绝"原则：

- **命令白名单**：只能执行预定义的安全命令（如 `npm test`、`git diff`），危险操作（`rm -rf`、`curl | bash`）被拦截
- **文件边界**：Agent 只能在当前工作区内操作，跨目录访问需显式授权
- **变更确认**：对 `package.json` 修改、大规模删除等高风险操作，系统会暂停并请求用户确认

这一设计启示我们：**AI Agent 的权限模型应当参照 Unix 的 DAC（自主访问控制）向 RBAC（基于角色的访问控制）演进**，为不同任务场景分配不同的能力边界。

### 构建一个 Mini Coding Agent

下面的代码实现了一个完整的 Agent Loop，包含 Tool 定义、LLM 推理模拟、安全沙箱和文件操作。你可以直接保存为 `mini-agent.js` 并运行。

```javascript
/**
 * Mini Coding Agent —— Claude Code 核心架构的简化实现
 * 
 * 演示内容：
 * 1. Agent Loop（感知-推理-行动循环）
 * 2. Tool Use 的 Schema 定义与执行
 * 3. 安全沙箱（命令白名单、文件边界检查）
 * 4. 多轮对话的状态管理
 * 
 * 运行方式：node mini-agent.js
 */

const fs = require('fs');
const path = require('path');
const { execSync } = require('child_process');

// ============================================
// 第一部分：Tool Schema 定义
// ============================================

const TOOLS = [
  {
    name: 'read_file',
    description: '读取指定文件的内容，支持行范围截取',
    input_schema: {
      type: 'object',
      properties: {
        path: {
          type: 'string',
          description: '相对于工作区的文件路径'
        },
        offset: {
          type: 'number',
          description: '起始行号（从0开始）',
          default: 0
        },
        limit: {
          type: 'number',
          description: '最多读取行数',
          default: 50
        }
      },
      required: ['path']
    }
  },
  {
    name: 'edit_file',
    description: '用字符串替换方式编辑文件（类似 sed）',
    input_schema: {
      type: 'object',
      properties: {
        path: { type: 'string' },
        old_string: {
          type: 'string',
          description: '必须精确匹配的原文片段'
        },
        new_string: {
          type: 'string',
          description: '替换后的新内容'
        }
      },
      required: ['path', 'old_string', 'new_string']
    }
  },
  {
    name: 'execute_command',
    description: '在工作区执行 shell 命令（受白名单约束）',
    input_schema: {
      type: 'object',
      properties: {
        command: { type: 'string', description: '完整命令字符串' },
        cwd: {
          type: 'string',
          description: '工作目录，默认为当前目录',
          default: '.'
        }
      },
      required: ['command']
    }
  },
  {
    name: 'read_directory',
    description: '列出目录下的文件和子目录',
    input_schema: {
      type: 'object',
      properties: {
        path: {
          type: 'string',
          description: '目录路径',
          default: '.'
        }
      },
      required: ['path']
    }
  },
  {
    name: 'search_files',
    description: '在文件内容中搜索匹配字符串',
    input_schema: {
      type: 'object',
      properties: {
        pattern: { type: 'string', description: '要搜索的正则表达式或字符串' },
        path: { type: 'string', description: '搜索目录', default: '.' }
      },
      required: ['pattern']
    }
  }
];

// ============================================
// 第二部分：安全沙箱与 Tool 执行器
// ============================================

class SecureToolExecutor {
  constructor(workspaceRoot) {
    // 限制 Agent 只能在指定目录内操作
    this.workspaceRoot = path.resolve(workspaceRoot);
    // 命令白名单：只允许安全的只读或受控命令
    this.allowedCommands = new Set([
      'ls', 'cat', 'grep', 'find', 'head', 'tail',
      'npm', 'node', 'npx', 'git', 'echo', 'pwd',
      'wc', 'mkdir', 'touch'
    ]);
    // 危险命令黑名单（双重保险）
    this.dangerousPatterns = [
      /rm\s+-rf\s+\//,
      />\s*\/dev\/null/,
      /curl.*\|.*sh/,
      /wget.*\|.*bash/
    ];
  }

  // 确保路径在工作区内，防止目录遍历攻击
  _resolveSafePath(inputPath) {
    const resolved = path.resolve(this.workspaceRoot, inputPath);
    if (!resolved.startsWith(this.workspaceRoot)) {
      throw new Error(`路径越界：${inputPath} 不在工作区 ${this.workspaceRoot} 内`);
    }
    return resolved;
  }

  read_file({ path: filePath, offset = 0, limit = 50 }) {
    const safePath = this._resolveSafePath(filePath);
    if (!fs.existsSync(safePath)) {
      return { error: `文件不存在: ${filePath}` };
    }
    const content = fs.readFileSync(safePath, 'utf-8');
    const lines = content.split('\n');
    const slice = lines.slice(offset, offset + limit);
    return {
      path: filePath,
      content: slice.join('\n'),
      total_lines: lines.length,
      shown_lines: slice.length
    };
  }

  edit_file({ path: filePath, old_string, new_string }) {
    const safePath = this._resolveSafePath(filePath);
    if (!fs.existsSync(safePath)) {
      return { error: `文件不存在: ${filePath}` };
    }
    const content = fs.readFileSync(safePath, 'utf-8');
    // 精确匹配，防止误替换
    if (!content.includes(old_string)) {
      return {
        error: `找不到匹配字符串。建议先 read_file 确认内容。`,
        hint: `文件前200字符: ${content.slice(0, 200)}`
      };
    }
    const newContent = content.replace(old_string, new_string);
    fs.writeFileSync(safePath, newContent, 'utf-8');
    return {
      success: true,
      path: filePath,
      bytes_before: content.length,
      bytes_after: newContent.length
    };
  }

  execute_command({ command, cwd = '.' }) {
    // 安全检查 1：危险模式匹配
    for (const pattern of this.dangerousPatterns) {
      if (pattern.test(command)) {
        return { error: `命令被安全策略拦截: ${command}` };
      }
    }
    // 安全检查 2：白名单校验
    const cmdBase = command.split(' ')[0];
    if (!this.allowedCommands.has(cmdBase)) {
      return {
        error: `命令 ${cmdBase} 不在白名单中`,
        allowed: Array.from(this.allowedCommands)
      };
    }
    try {
      const safeCwd = this._resolveSafePath(cwd);
      const output = execSync(command, {
        cwd: safeCwd,
        encoding: 'utf-8',
        timeout: 30000,
        maxBuffer: 1024 * 1024 // 1MB 输出上限
      });
      return {
        command,
        output: output.slice(0, 5000), // 截断过长输出，保护上下文窗口
        exit_code: 0
      };
    } catch (err) {
      return {
        command,
        error: err.message,
        stderr: err.stderr?.slice(0, 2000),
        exit_code: err.status || 1
      };
    }
  }

  read_directory({ path: dirPath = '.' }) {
    const safePath = this._resolveSafePath(dirPath);
    if (!fs.existsSync(safePath)) {
      return { error: `目录不存在: ${dirPath}` };
    }
    const entries = fs.readdirSync(safePath, { withFileTypes: true });
    return {
      path: dirPath,
      entries: entries.map(e => ({
        name: e.name,
        type: e.isDirectory() ? 'directory' : 'file'
      }))
    };
  }

  search_files({ pattern, path: searchPath = '.' }) {
    const safePath = this._resolveSafePath(searchPath);
    const results = [];
    // 简化实现：仅搜索前 20 个文件，防止遍历过大目录
    let fileCount = 0;
    const walk = (dir) => {
      if (fileCount >= 20) return;
      const entries = fs.readdirSync(dir, { withFileTypes: true });
      for (const entry of entries) {
        if (fileCount >= 20) break;
        const fullPath = path.join(dir, entry.name);
        if (entry.isDirectory()) {
          if (!entry.name.startsWith('.') && entry.name !== 'node_modules') {
            walk(fullPath);
          }
        } else {
          fileCount++;
          try {
            const content = fs.readFileSync(fullPath, 'utf-8');
            if (content.includes(pattern)) {
              const lines = content.split('\n');
              const matches = lines
                .map((line, idx) => ({ line, idx }))
                .filter(({ line }) => line.includes(pattern))
                .slice(0, 3); // 每文件最多3行匹配
              results.push({
                file: path.relative(this.workspaceRoot, fullPath),
                matches: matches.map(m => ({ line: m.idx + 1, text: m.line.trim() }))
              });
            }
          } catch {
            // 二进制文件或不可读，跳过
          }
        }
      }
    };
    walk(safePath);
    return { pattern, results, scanned_files: fileCount };
  }
}

// 第三部分：模拟 LLM 客户端（可替换为真实 API）

class MockLLMClient {
  /**
   * 模拟 LLM 的推理过程。
   * 在生产环境中，这里应该调用 Anthropic Claude API 或 OpenAI API。
   * 
   * 真实调用示例（Claude API）：
   * const response = await anthropic.messages.create({
   *   model: 'claude-3-7-sonnet-20250219',
   *   max_tokens: 4096,
   *   tools: TOOLS,
   *   messages: conversationHistory
   * });
   */
  async callWithTools(messages, tools) {
    const lastMessage = messages[messages.length - 1];
    const userInput = lastMessage.content.toLowerCase();

    // 模拟 LLM 基于用户意图选择 Tool 的决策逻辑
    if (userInput.includes('文件') || userInput.includes('结构') || userInput.includes('目录')) {
      return {
        content: [{ type: 'text', text: '我来查看当前项目的目录结构。' }],
        tool_calls: [{
          id: 'tool_1',
          type: 'tool_use',
          name: 'read_directory',
          input: { path: '.' }
        }]
      };
    }

    if (userInput.includes('内容') || userInput.includes('代码') || userInput.includes('看看')) {
      // 先列出目录，然后读取第一个文件
      return {
        content: [{ type: 'text', text: '让我先列出文件，再读取关键文件的内容。' }],
        tool_calls: [
          {
            id: 'tool_2',
            type: 'tool_use',
            name: 'read_directory',
            input: { path: '.' }
          }
        ]
      };
    }

    if (userInput.includes('搜索') || userInput.includes('查找') || userInput.includes('在哪')) {
      const pattern = userInput.replace(/.*搜索\s*/, '').replace(/.*查找\s*/, '').trim() || 'function';
      return {
        content: [{ type: 'text', text: `正在搜索包含 "${pattern}" 的文件...` }],
        tool_calls: [{
          id: 'tool_3',
          type: 'tool_use',
          name: 'search_files',
          input: { pattern: pattern.slice(0, 30), path: '.' }
        }]
      };
    }

    if (userInput.includes('命令') || userInput.includes('运行') || userInput.includes('执行')) {
      return {
        content: [{ type: 'text', text: '我准备执行一个安全的命令来获取信息。' }],
        tool_calls: [{
          id: 'tool_4',
          type: 'tool_use',
          name: 'execute_command',
          input: { command: 'ls -la' }
        }]
      };
    }

    // 默认：无需工具，直接回答
    return {
      content: [{ type: 'text', text: '我已经分析了项目结构。这是一个基于 Node.js 的项目，包含标准的文件组织方式。如需深入了解某个特定文件，请告诉我文件名。' }],
      tool_calls: []
    };
  }
}

// ============================================
// 第四部分：Agent Loop 核心引擎
// ============================================

class CodingAgent {
  constructor(workspaceRoot = '.') {
    this.llm = new MockLLMClient();
    this.executor = new SecureToolExecutor(workspaceRoot);
    this.messages = []; // 对话历史，即上下文
    this.maxIterations = 8; // 防止无限循环的安全上限
    this.toolDefinitions = TOOLS;
  }

  async run(userInput) {
    console.log('\n' + '='.repeat(60));
    console.log('🚀 Mini Coding Agent 启动');
    console.log('='.repeat(60));
    console.log(`👤 用户: ${userInput}\n`);

    // 将用户输入加入上下文
    this.messages.push({ role: 'user', content: userInput });

    for (let i = 0; i < this.maxIterations; i++) {
      console.log(`─`.repeat(60));
      console.log(`🔄 Agent Loop 迭代 ${i + 1} / ${this.maxIterations}`);
      console.log(`💭 当前上下文长度: ${this.messages.length} 条消息`);

      // Step 1: LLM 推理（感知+决策）
      const response = await this.llm.callWithTools(this.messages, this.toolDefinitions);

      // Step 2: 处理 LLM 的文本输出
      const textParts = response.content
        .filter(c => c.type === 'text')
        .map(c => c.text)
        .join('');
      if (textParts) {
        console.log(`\n🤖 AI: ${textParts}`);
        this.messages.push({ role: 'assistant', content: textParts });
      }

      // Step 3: 处理 Tool 调用（行动）
      const toolCalls = response.tool_calls || [];
      if (toolCalls.length === 0) {
        console.log('\n✅ Agent 认为任务已完成，无需进一步操作。');
        break;
      }

      for (const call of toolCalls) {
        console.log(`\n🔧 调用 Tool: ${call.name}`);
        console.log(`   参数: ${JSON.stringify(call.input)}`);

        // 执行 Tool
        const result = this.executor[call.name](call.input);

        // 格式化结果反馈
        const resultText = JSON.stringify(result, null, 2).slice(0, 1500);
        console.log(`📊 结果: ${resultText}${resultText.length >= 1500 ? '... (已截断)' : ''}`);

        // 将结果加入上下文，供下一轮推理使用
        this.messages.push({
          role: 'user',
          content: `[Tool ${call.name} 结果] ${JSON.stringify(result)}`
        });
      }

      // 简短停顿，模拟真实交互节奏
      await this._sleep(300);
    }

    if (this.messages.length >= this.maxIterations * 2) {
      console.log('\n⚠️ 达到最大迭代次数，Agent 被强制终止。');
    }

    console.log('\n' + '='.repeat(60));
    console.log('🏁 Agent Loop 结束');
    console.log('='.repeat(60));
  }

  _sleep(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
  }
}
```

### 关键代码设计要点

- **Schema 与实现的分离**：`TOOLS` 数组只负责描述"能做什么"，`SecureToolExecutor` 负责"怎么做"，这种分离让 LLM 的决策层与执行层解耦
- **安全边界的纵深防御**：路径检查、命令白名单、危险模式正则、输出截断——四层防护确保 Agent 不会失控
- **上下文的有界增长**：每次 Tool 结果都会被截断到 1500 字符，防止长输出撑爆上下文窗口

## 思考题（5 分钟）

### 问题 1：Agent Loop 的边界与容错

在上述 Mini Agent 中，如果 LLM 连续三轮调用了同一个 Tool 并得到了相同的结果（例如反复读取同一个文件），系统会陷入无效循环。请设计一个**循环检测与中断机制**：

- 你会如何定义"无效循环"？（是完全相同的 Tool 调用？还是语义上的重复？）
- 检测到中继后，系统应该如何自我恢复？（向 LLM 注入提示词？暂停并询问用户？还是自动尝试替代策略？）
- 如果要在生产环境中部署这个 Agent，你还需要增加哪些可观测性指标（metrics/logs）来提前发现这类问题？

### 问题 2：从前端工程化视角重构 AI 工具链

假设你正在负责一个 50 人前端团队的工程化建设，计划将 AI Agent 集成到日常开发工作流中。请思考：

- **权限模型**：如何让 Agent 在"个人开发机"和"CI/CD 流水线"两种场景下拥有不同的能力边界？是否需要设计类似 Kubernetes RBAC 的细粒度权限系统？
- **上下文策略**：在大型 Monorepo（如包含 200+ 包）中，Agent 如何快速定位与当前任务相关的代码？你会考虑引入代码图谱（Code Graph）还是依赖传统的文件搜索？
- **人机协作界面**：当 Agent 建议修改 `webpack.config.js` 或 `package.json` 中的关键依赖时，如何设计交互流程才能既保持效率又确保开发者对变更有充分知情权？
