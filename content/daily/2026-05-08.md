# Day 16：代码生成Prompt优化技巧

> 日期：2026-05-08 | 预计用时：30分钟 | 模块：Prompt Engineering for Frontend

---

## 今日概览

昨天我们学习了结构化Prompt设计的思维链（Chain of Thought）方法。今天聚焦于一个更实际的问题：**如何让AI生成的代码真正可用、符合团队规范、甚至直接通过Code Review？**

代码生成Prompt的优化，本质上是把"模糊需求"转化为"精确指令"的过程。一个好的代码Prompt，能让AI从"写个大概"变成"写出生产级代码"。

---

## 核心概念（10分钟阅读）

### 1. 代码生成Prompt的「三重约束」

与通用Prompt不同，代码Prompt需要在三个维度上同时精确：

| 维度 | 说明 | 示例 |
|------|------|------|
| **功能约束** | 输入什么、输出什么、边界条件 | "接收一个ISO日期字符串，返回相对时间描述" |
| **质量约束** | 性能、可读性、错误处理 | "时间复杂度O(1)，包含null/undefined校验" |
| **风格约束** | 命名规范、TS严格程度、注释风格 | "使用camelCase，导出函数需带JSDoc，避免any" |

> **常见误区**：只描述功能，不说明质量和风格。结果AI生成的是"能跑"但"不能看"的代码。

### 2. 上下文注入：给AI一个「开发环境」

AI生成代码时，最大的障碍是它不知道你的项目上下文。优化策略：

**基础版——技术栈声明**
```
技术栈：React 19 + TypeScript 5.7 + Tailwind CSS v4
构建工具：Vite 6
测试框架：Vitest + React Testing Library
```

**进阶版——规则文件引用**
```
请遵循以下规范生成代码：
- 组件使用函数式声明，Props接口命名为 "{ComponentName}Props"
- 所有异步操作使用 TanStack Query，禁止裸用 useEffect + fetch
- 样式优先使用 Tailwind 工具类，复杂逻辑抽离到 cn() 工具函数
- 错误处理使用统一的 ErrorBoundary + toast 通知
```

**高阶版——示例驱动（Few-shot）**
在Prompt中直接给出一个你满意的代码片段，让AI模仿风格：
```
参考以下代码风格生成新组件：

// [插入你团队的最佳实践代码示例]
// 请保持相同的命名、结构、注释和类型定义风格
```

### 3. 迭代优化策略：从V0到Vn

不要期望一次Prompt就完美。推荐迭代路径：

```
V0：描述需求 → AI生成初稿
V1：指出类型问题 → "请将Props中的name改为required，并添加默认值处理"
V2：指出风格问题 → "请使用早期返回替代嵌套if，添加JSDoc说明"
V3：指出边界问题 → "请处理loading和error状态，添加空数据占位"
V4：最终审查 → "检查是否有unused imports，确保符合ESLint规则"
```

把每次迭代的要求记下来，逐渐形成你的**个人Prompt模板库**。

### 4. 前端特有的Prompt技巧

**组件生成三板斧**：
1. **原子化描述**："这是一个Button组件" → 不如 → "这是一个支持loading状态、可带前缀图标、适配dark模式的Button组件"
2. **状态枚举**：明确列出所有状态（default / hover / active / disabled / loading）
3. **可访问性声明**："需支持键盘操作，aria-label由调用方传入或基于text自动生成"

**Hooks生成关键**：
- 明确依赖项变化时是否需要重新订阅/清理
- 是否需要支持SSR（Next.js场景）
- 返回值类型是`[state, dispatch]`还是直接的对象

## 代码实践（15分钟动手）

### 练习：优化一个「通用表格组件」的生成Prompt

假设你需要让AI帮你生成一个项目中的通用表格组件。对比以下两个Prompt的质量：

**❌ 低质量Prompt**
```
写一个React表格组件，可以显示数据，支持排序和分页。
```

**✅ 高质量Prompt**
```
请生成一个React TypeScript表格组件，要求如下：

【功能】
- 接收泛型数据数组 data: T[] 和列定义 columns: ColumnDef<T>[]
- 支持服务端排序（点击表头触发onSort回调，传入{field, direction}）
- 支持分页：接收pageIndex/pageSize/total，触发onPageChange
- 支持行选择：多选模式，选中项通过onSelectionChange回传

【类型定义】
interface ColumnDef<T> {
  key: keyof T;
  title: string;
  width?: number;
  sortable?: boolean;
  render?: (value: T[keyof T], row: T) => React.ReactNode;
}

【样式要求】
- 使用Tailwind CSS
- 表头背景gray-50，文字gray-700，字号sm
- 行hover:bg-gray-50，选中行bg-blue-50
- 空数据时显示自定义Empty组件

【质量要求】
- 使用forwardRef暴露底层table DOM
- 所有事件处理函数用useCallback缓存
- 添加JSDoc注释说明每个props用途
- 组件文件命名：DataTable.tsx

【示例用法】（请在注释中展示）
```tsx
<DataTable<User>
  data={users}
  columns={[
    { key: 'name', title: '姓名', sortable: true },
    { key: 'role', title: '角色', render: (v) => <Tag>{v}</Tag> }
  ]}
  pagination={{ pageIndex: 0, pageSize: 10, total: 100 }}
  onPageChange={(p) => setPage(p)}
/>
```
```

### 动手任务

选择你最近需要的一个组件（或Hooks），尝试：
1. 用低质量Prompt让AI生成一版
2. 分析它的问题（类型缺失？边界没处理？风格不一致？）
3. 重写高质量Prompt，对比两版差异
4. 把优化后的Prompt保存到你的个人模板库中

> **今日产出**：至少1个经过优化的代码生成Prompt模板

## 思考题（5分钟）

1. **场景题**：你的团队刚刚引入了Zod做运行时校验，如何在Prompt中让AI自动为新API接口生成对应的Zod Schema？需要在Prompt中补充什么信息？

2. **反思题**：回顾过去一周你让AI生成的代码，有多少需要手动修改超过30%？问题出在Prompt的哪个维度（功能/质量/风格）？

3. **设计题**：如果要为一个大型前端团队设计一套"代码生成Prompt规范"，应该包含哪些必选项和可选项？如何确保不同成员生成的代码风格一致？
