## 二、核心概念（5分钟精读）

### 2.1 从Next-Token Prediction到Constraint-Satisfaction

传统的大模型代码补全本质上是**统计模式匹配**：根据前面的token预测最可能的下一个token。这在语法层面表现不错，但在语义层面经常出错——比如给对象补充一个不存在的方法，或者传错参数类型。

TypeScript改变这个游戏的根本方式是引入了**类型约束作为先验知识**：

```
用户输入：const result = fetchUser(

纯文本模型猜测：(id) => Promise<any>
类型感知模型推断：(id: string) => Promise<User | null>
```

背后的机制是：TypeScript Compiler在编译时构建了一张完整的类型关系图（Type Graph），包含：
- **Symbol Table**：所有命名实体（变量、函数、类、接口）的定义和引用关系
- **Type Checker**：每个表达式的推断类型、类型兼容性判断
- **Control Flow Graph**：代码执行路径与类型收窄的关联

当AI模型能访问这些信息时，代码生成就从"猜下一个词"变成了**约束满足问题**（Constraint Satisfaction Problem）：在类型系统允许的解空间内，找到最合理的实现。

### 2.2 LSP与AI的"上下文接力"

VS Code的智能补全经历了三代演进：

| 世代 | 技术 | 上下文范围 | 决策依据 |
|------|------|-----------|---------|
| 1st | 文本补全（Snippets） | 当前文件 | 前缀匹配 |
| 2nd | LSP语义补全 | 整个项目 | 类型系统 |
| 3rd | AI生成（Copilot） | 跨文件+自然语言 | 大规模训练数据 |

现在的关键趋势是**2nd与3rd的融合**：Copilot实际上在内部使用了LSP提供的类型信息来约束生成空间。具体来说：

1. **预处理阶段**：Copilot提取当前光标位置的LSP语义信息（当前作用域有哪些变量、期望的类型签名）
2. **Prompt构建**：将这些类型信息编码进系统提示（System Prompt）或上下文提示（Context Prompt）
3. **后处理阶段**：对生成的代码进行类型检查过滤，丢弃明显违背类型约束的候选

这意味着：**类型系统的完整性直接决定了AI生成代码的质量上限**。

### 2.3 类型感知提示工程（Type-Aware Prompting）

我们可以主动设计Prompt来利用类型信息。一个高质量的类型感知Prompt通常包含三层：

```
Layer 1: 类型签名（What）
  - 函数参数类型
  - 返回类型约束
  - 泛型边界条件

Layer 2: 类型关系（How）
  - 相关接口/类型的定义
  - 类型之间的继承/实现关系
  - 联合类型/交叉类型的合法取值

Layer 3: 领域语义（Why）
  - 这个类型代表的业务概念
  - 不变量（invariants）约束
  - 与外部系统（API/数据库）的契约
```

研究表明（Microsoft Research, 2024），在Prompt中加入类型签名信息可以使TypeScript代码生成的类型通过率从67%提升到91%。

### 2.4 类型压缩：大项目中的上下文瓶颈

一个现实问题：大型项目的类型图可能包含数万个节点，不可能全部塞进LLM的上下文窗口。解决思路是**类型图剪枝**（Type Graph Pruning）：

- **距离剪枝**：只保留与当前编辑位置类型距离≤N跳的类型定义
- **依赖剪枝**：通过import/export关系，只保留直接依赖的类型
- **频率剪枝**：优先保留项目中高频使用的公共类型
- **摘要剪枝**：对复杂类型生成自然语言摘要，替代完整定义

#### Step 2: 类型提取器（extractor.ts）

```typescript
/**
 * TypeScript Compiler API 类型提取器
 * 从源代码中提取函数签名的完整类型信息
 */
import * as ts from 'typescript';

export interface FunctionSignature {
  name: string;
  parameters: Array<{
    name: string;
    type: string;
    optional: boolean;
  }>;
  returnType: string;
  typeParameters?: string[];
  /** 函数所在文件中已定义的相关接口/类型 */
  relatedTypes: Array<{ name: string; definition: string }>;
}

/**
 * 从TypeScript源代码中提取所有函数签名
 * @param sourceCode TypeScript源代码字符串
 * @param fileName 虚拟文件名（用于编译器识别）
 */
export function extractFunctionSignatures(
  sourceCode: string,
  fileName: string = 'input.ts'
): FunctionSignature[] {
  // 创建内存中的TypeScript程序（无需真实文件）
  const sourceFile = ts.createSourceFile(
    fileName,
    sourceCode,
    ts.ScriptTarget.ES2020,
    true
  );

  const program = ts.createProgram(
    [fileName],
    { noEmit: true, target: ts.ScriptTarget.ES2020 },
    {
      getSourceFile: (name) => (name === fileName ? sourceFile : undefined),
      writeFile: () => {},
      getCurrentDirectory: () => process.cwd(),
      getDirectories: () => [],
      fileExists: () => true,
      readFile: () => '',
      getCanonicalFileName: (name) => name,
      useCaseSensitiveFileNames: () => true,
      getNewLine: () => '\n',
    }
  );

  const checker = program.getTypeChecker();
  const signatures: FunctionSignature[] = [];
  const relatedTypeMap = new Map<string, string>();

  // 第一遍扫描：收集所有类型定义（接口、类型别名、枚举）
  function collectTypes(node: ts.Node) {
    if (
      ts.isInterfaceDeclaration(node) ||
      ts.isTypeAliasDeclaration(node) ||
      ts.isEnumDeclaration(node)
    ) {
      const name = node.name.text;
      const definition = sourceCode.substring(node.pos, node.end).trim();
      relatedTypeMap.set(name, definition);
    }
    ts.forEachChild(node, collectTypes);
  }
  collectTypes(sourceFile);

  // 第二遍扫描：提取函数签名
  function visit(node: ts.Node) {
    if (
      ts.isFunctionDeclaration(node) &&
      node.name &&
      !node.body // 只提取声明（无实现的函数）
    ) {
      const symbol = checker.getSymbolAtLocation(node.name);
      if (!symbol) return;

      const funcType = checker.getTypeOfSymbolAtLocation(symbol, node.name);
      const callSignatures = funcType.getCallSignatures();

      callSignatures.forEach((sig) => {
        const params = sig.getParameters().map((param) => {
          const decl = param.getDeclarations()?.[0];
          const paramType = checker.getTypeOfSymbolAtLocation(
            param,
            decl || node
          );
          return {
            name: param.getName(),
            type: checker.typeToString(paramType),
            optional: !!(decl && ts.isParameter(decl) && decl.questionToken),
          };
        });

        const retType = sig.getReturnType();

        // 找出与函数签名相关的类型（参数类型或返回类型中引用的类型）
        const usedTypeNames = new Set<string>();
        const typeString =
          params.map((p) => p.type).join(' ') +
          ' ' +
          checker.typeToString(retType);

        // 简单启发式：检查类型字符串中是否包含已收集的类型名
        relatedTypeMap.forEach((_, name) => {
          // 使用单词边界匹配，避免部分匹配（如 "User" 匹配 "UserSettings"）
          const regex = new RegExp(`\\b${name}\\b`);
          if (regex.test(typeString)) {
            usedTypeNames.add(name);
          }
        });

        signatures.push({
          name: node.name!.text,
          parameters: params,
          returnType: checker.typeToString(retType),
          typeParameters: node.typeParameters?.map((tp) => tp.name.text),
          relatedTypes: Array.from(usedTypeNames).map((name) => ({
            name,
            definition: relatedTypeMap.get(name)!,
          })),
        });
      });
    }
    ts.forEachChild(node, visit);
  }
  visit(sourceFile);

  return signatures;
}

// 简易CLI测试入口
if (require.main === module) {
  const sampleCode = `
```

#### Step 3: Prompt构建器（prompt-builder.ts）

```typescript
/**
 * 类型感知Prompt构建器
 * 将TypeScript类型信息编码为LLM可理解的结构化提示
 */
import { FunctionSignature } from './extractor';

export interface TypeAwarePrompt {
  systemPrompt: string;
  userPrompt: string;
  /** 估计的token消耗（粗略估计） */
  estimatedTokens: number;
}

/**
 * 构建类型感知的代码生成Prompt
 */
export function buildTypeAwarePrompt(
  signature: FunctionSignature,
  options: {
    /** 是否包含类型关系的自然语言解释 */
    includeSemanticLayer?: boolean;
    /** 代码风格偏好 */
    style?: 'functional' | 'oop' | 'mixed';
  } = {}
): TypeAwarePrompt {
  const { includeSemanticLayer = true, style = 'functional' } = options;

  // 系统提示：定义AI的角色和约束
  const systemPrompt = `You are a TypeScript expert code generator. Your task is to implement functions based on their type signatures.

Rules:
1. The implementation MUST satisfy the given TypeScript types exactly.
2. Use type-safe patterns. Avoid 'any' unless explicitly required.
3. Prefer ${style === 'functional' ? 'pure functions and immutable data' : style === 'oop' ? 'class-based OOP patterns' : 'appropriate patterns for the context'}.
4. Include JSDoc comments explaining the implementation logic.
5. If a return type is Promise<T>, always use async/await.
6. Handle edge cases (null, empty arrays, invalid inputs) gracefully.`;

  // 构建类型定义块
  const typeDefinitions = signature.relatedTypes
    .map(
      (t) => `// Type: ${t.name}
${t.definition}`
    )
    .join('\n\n');

  // 构建函数签名描述
  const paramsDesc = signature.parameters
    .map(
      (p) =>
        `- ${p.name}${p.optional ? '?' : ''}: ${p.type}${p.optional ? ' (optional)' : ''}`
    )
    .join('\n');

  // 语义层：解释类型背后的业务含义
  const semanticLayer = includeSemanticLayer
    ? generateSemanticHints(signature)
    : '';

  // 用户提示：具体的实现请求
  const userPrompt = `Please implement the following TypeScript function.

## Related Types
${typeDefinitions || '(No additional types defined)'}

## Function to Implement

\`\`\`typescript
function ${signature.name}(${signature.parameters.map((p) => `${p.name}${p.optional ? '?' : ''}: ${p.type}`).join(', ')})${signature.typeParameters ? `<${signature.typeParameters.join(', ')}>` : ''}: ${signature.returnType};
\`\`\`

### Parameter Details
${paramsDesc}

### Return Type
${signature.returnType}

${semanticLayer ? `### Semantic Context\n${semanticLayer}\n` : ''}

Please provide ONLY the complete implementation (including the function signature), wrapped in a TypeScript code block.`;

  // 粗略的token估算（英文约1token/字符，中文约2token/字符）
  const estimatedTokens = Math.ceil(
    (systemPrompt.length + userPrompt.length) / 3.5
  );

  return { systemPrompt, userPrompt, estimatedTokens };
}

/**
 * 根据类型签名生成语义提示（模拟对类型业务的理解）
 */
function generateSemanticHints(signature: FunctionSignature): string {
  const hints: string[] = [];

  // 启发式规则：根据命名模式推断语义
  const nameLower = signature.name.toLowerCase();

  if (nameLower.includes('fetch') || nameLower.includes('get')) {
    hints.push('- This is a data retrieval function. Consider caching, error handling for network failures, and response validation.');
  }
  if (nameLower.includes('update') || nameLower.includes('set')) {
    hints.push('- This is a mutation function. Consider optimistic updates, rollback strategies, and input sanitization.');
  }
  if (signature.returnType.includes('Promise')) {
    hints.push('- This function is asynchronous. Ensure proper error propagation and consider timeout handling.');
  }
  if (signature.parameters.some((p) => p.type.includes('role') || p.type.includes('permission'))) {
    hints.push('- This function involves authorization. Ensure the implementation validates permissions before executing.');
  }

  // 基于返回类型的提示
  if (signature.returnType.includes('ApiResponse')) {
    hints.push('- The function wraps its result in an ApiResponse. Ensure both success and error cases follow the ApiResponse structure.');
  }

  return hints.join('\n');
}
```

```typescript
/**
 * LLM代码生成器
 * 支持模拟模式（无需API Key）和真实OpenAI API调用
 */
import { TypeAwarePrompt } from './prompt-builder';

export interface GenerationResult {
  code: string;
  model: string;
  usage?: { promptTokens: number; completionTokens: number };
  /** 是否通过了类型验证 */
  typeCheckPassed?: boolean;
}

/**
 * 模拟LLM生成（无需API Key，用于快速测试）
 * 根据类型签名生成合理的模板代码
 */
export function generateMockImplementation(
  prompt: TypeAwarePrompt
): GenerationResult {
  // 从userPrompt中提取函数签名信息（简化解析）
  const signatureMatch = prompt.userPrompt.match(
    /function\s+(\w+)\s*\(([^)]*)\)\s*:?\s*([^{;]+)/
  );

  if (!signatureMatch) {
    return {
      code: '// Error: Could not parse function signature from prompt',
      model: 'mock-parser',
    };
  }

  const [, funcName, paramsStr, returnType] = signatureMatch;

  // 解析参数
  const params = paramsStr
    .split(',')
    .map((p) => p.trim())
    .filter(Boolean)
    .map((p) => {
      const parts = p.split(':');
      return { name: parts[0].replace('?', '').trim(), optional: p.includes('?') };
    });

  // 根据返回类型生成模板体
  let body = '';
  const rt = returnType.trim();

  if (rt.includes('Promise<ApiResponse')) {
    const innerMatch = rt.match(/Promise<ApiResponse<(.+?)>>/);
    const innerType = innerMatch ? innerMatch[1].trim() : 'any';

    if (innerType === 'void') {
      body = `  // TODO: Implement the actual API call
  await new Promise(resolve => setTimeout(resolve, 100));
  return {
    data: undefined,
    success: true
  };`;
    } else {
      body = `  // TODO: Implement the actual API call
  const response = await fetch(\`/api/${funcName.replace(/([A-Z])/g, '-$1').toLowerCase()}\`);
  if (!response.ok) {
    return {
      data: null as any,
      success: false,
      message: \`Failed to ${funcName}: \${response.statusText}\`
    };
  }
  const data = await response.json();
  return {
    data,
    success: true
  };`;
    }
  } else if (rt.includes('Promise')) {
    body = `  // TODO: Implement async logic
  return new Promise((resolve) => {
    setTimeout(() => resolve(null as any), 100);
  });`;
  } else {
    body = `  // TODO: Implement synchronous logic
  return null as any;`;
  }

  const paramList = params.map((p) => p.name).join(', ');
  const code = `/**
 * Auto-generated implementation for ${funcName}
 * Generated with type-aware constraints
 */
async function ${funcName}(${paramsStr}): ${rt} {
${body}
}`;

  return {
    code,
    model: 'mock-template-engine',
    usage: {
      promptTokens: prompt.estimatedTokens,
      completionTokens: Math.ceil(code.length / 3.5),
    },
  };
}

/**
 * 真实OpenAI API调用（需要OPENAI_API_KEY环境变量）
 */
export async function generateWithOpenAI(
  prompt: TypeAwarePrompt,
  apiKey?: string
): Promise<GenerationResult> {
  const key = apiKey || process.env.OPENAI_API_KEY;

  if (!key) {
    console.warn('⚠️ OPENAI_API_KEY not found. Falling back to mock mode.');
    return generateMockImplementation(prompt);
  }

  const response = await fetch('https://api.openai.com/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${key}`,
    },
    body: JSON.stringify({
      model: 'gpt-4-turbo-preview',
      messages: [
        { role: 'system', content: prompt.systemPrompt },
        { role: 'user', content: prompt.userPrompt },
      ],
      temperature: 0.2, // 低温度，更遵循类型约束
      max_tokens: 1500,
    }),
  });

  if (!response.ok) {
    throw new Error(`OpenAI API error: ${response.status} ${await response.text()}`);
  }

  const data = await response.json();
  const content = data.choices[0]?.message?.content || '';

  // 从markdown代码块中提取代码
  const codeMatch = content.match(/```typescript\n?([\s\S]*?)```/);
  const code = codeMatch ? codeMatch[1].trim() : content;

  return {
    code,
    model: data.model,
    usage: {
      promptTokens: data.usage?.prompt_tokens || 0,
      completionTokens: data.usage?.completion_tokens || 0,
    },
  };
}
```

#### Step 5: 类型验证器（validator.ts）

```typescript
/**
 * TypeScript类型验证器
 * 验证生成的代码是否能通过类型检查
 */
import * as ts from 'typescript';

export interface ValidationResult {
  passed: boolean;
  errors: Array<{ message: string; line?: number }>;
  diagnostics: ts.Diagnostic[];
}

/**
 * 将原始代码与生成的实现合并，进行类型检查
 * @param originalCode 原始文件（包含类型定义和函数声明）
 * @param implementation 生成的实现代码
 * @param functionName 要实现的函数名
 */
export function validateImplementation(
  originalCode: string,
  implementation: string,
  functionName: string
): ValidationResult {
  // 将原始代码中的函数声明替换为实现
  // 策略：找到 "function name(...): ReturnType;" 声明并替换为完整实现
  const declarationRegex = new RegExp(
    `function\\s+${functionName}\\s*\\([^)]*\\)\\s*:[^;]*;`,
    'g'
  );

  const mergedCode = originalCode.replace(declarationRegex, implementation);

  // 创建内存编译环境
  const fileName = 'validation.ts';
  const sourceFile = ts.createSourceFile(
    fileName,
    mergedCode,
    ts.ScriptTarget.ES2020,
    true
  );

  const compilerOptions: ts.CompilerOptions = {
    noEmit: true,
    strict: true,
    target: ts.ScriptTarget.ES2020,
    module: ts.ModuleKind.CommonJS,
    lib: ['lib.es2020.d.ts'],
  };

  const host = ts.createCompilerHost(compilerOptions);
  const originalGetSourceFile = host.getSourceFile;

  host.getSourceFile = (name, languageVersion) => {
    if (name === fileName) return sourceFile;
    return originalGetSourceFile(name, languageVersion);
  };

  host.fileExists = (name) =>
    name === fileName || ts.sys.fileExists(name);
  host.readFile = (name) =>
    name === fileName ? mergedCode : ts.sys.readFile(name);

  const program = ts.createProgram([fileName], compilerOptions, host);
  const diagnostics = ts.getPreEmitDiagnostics(program);

  const errors = diagnostics.map((d) => {
    const message = ts.flattenDiagnosticMessageText(d.messageText, '\n');
    const line = d.file && d.start !== undefined
      ? d.file.getLineAndCharacterOfPosition(d.start).line + 1
      : undefined;
    return { message, line };
  });

  return {
    passed: errors.length === 0,
    errors,
    diagnostics,
  };
}
```

### 实践要点总结

1. **TypeScript Compiler API**是这座桥梁的地基。`getTypeChecker()`提供的能力远超`.d.ts`文件解析——它能给出推断类型、泛型实例化、类型兼容性判断。

2. **Prompt是约束的载体**。将类型信息编码进Prompt时，要注意token效率：完整的类型定义 > 类型名称引用 > 无类型信息。

3. **验证闭环**必不可少。生成代码后必须跑一遍类型检查，因为LLM可能生成"看起来对但类型不匹配"的代码（如上面的`timestamp`缺失）。

4. **这个项目可以演进的方向**：接入真实LLM、增加类型图剪枝、做成VS Code插件、支持批量生成整个API层。

## 四、思考题（5分钟）

### 问题1：上下文窗口的"类型爆炸"困境

假设你在一个大型微前端项目中，有一个工具函数`formatCurrency(amount: Money, locale: Locale, options?: FormatOptions): string`，其中`Money`、`Locale`、`FormatOptions`各自依赖3-5个其他类型，而这些类型又继续依赖更多类型。如果要将完整的类型上下文提供给LLM，很容易超出上下文窗口限制。

**你的任务**：设计一个"类型图剪枝算法"，在保留必要约束的前提下，将类型上下文压缩到不超过2000个token。请描述你的剪枝策略（如距离剪枝、频率剪枝、抽象摘要等），并讨论每种策略可能丢失什么信息、在什么场景下是安全的。

### 问题2：当类型通过但逻辑错误时

TypeScript的类型系统能捕获很多错误，但以下代码完全通过类型检查，逻辑却是错的：

```typescript
function calculateDiscount(price: number, couponCode: string): number {
  // BUG: 使用了错误的比较逻辑，但类型完全正确
  if (couponCode === 'VIP50') {
    return price * 0.5;
  }
  if (couponCode === 'SAVE20') {
    return price * 0.2; // 应该是 price * 0.8 (打8折)，但写成了0.2
  }
  return price;
}
```

**你的任务**：讨论类型系统应该如何进化（或如何借助AI）来捕获这类"语义层面的业务逻辑错误"。可以参考的方向包括：依赖类型（Dependent Types）、契约式编程（Contracts）、基于测试用例的AI验证、或者让类型承载更多业务语义（如`type DiscountRate = Brand<number, 'DiscountRate'>` vs `type Multiplier = Brand<number, 'Multiplier'>`）。
