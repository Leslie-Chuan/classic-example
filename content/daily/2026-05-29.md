## 二、核心概念（15分钟阅读）

### 2.1 MCP生态的5月爆发

**关键数据与事件**
- GitHub `modelcontextprotocol/servers` 仓库Star数在5月翻倍，社区Server突破1000+
- 主流平台纷纷接入：Notion、Figma、Slack、GitHub、Linear等均推出官方MCP Server
- 云服务商跟进：AWS、GCP、Azure均提供MCP托管服务
- **前端领域的特殊机会**：浏览器MCP Client、Chrome Extension作为MCP宿主、前端工具链MCP化

**从协议到生态的跃迁**
```
4月：MCP是"一个协议规范"
5月：MCP是"一个应用商店"（Server Registry）
6月趋势预判：MCP将成为"操作系统级"的AI集成层
```

**对前端开发者的意义**
- 你写的组件可以成为MCP Resource
- 你的构建工具可以暴露为MCP Tool
- 你的设计系统可以通过MCP Prompt被AI理解

### 2.2 AI Builder三强对比

| 维度 | v0.dev (Vercel) | Bolt.new (StackBlitz) | Lovable.dev |
|------|-----------------|----------------------|-------------|
| **核心定位** | 组件/页面生成器 | 全栈应用生成器 | 产品级应用生成器 |
| **技术栈** | React + Next.js + Tailwind | 任意（基于WebContainer） | React + Supabase |
| **输出可控性** | 高（可精细调整） | 中（代码可导出） | 中（偏向黑盒） |
| **部署能力** | Vercel一键部署 | 任意平台 | 内置托管 |
| **适合场景** | 落地页、组件库 | 原型验证、全栈Demo | MVP快速验证 |
| **前端开发者价值** | 学习AI组件设计模式 | 学习AI全栈架构 | 学习AI产品思维 |

**共同技术底座**
- 均基于大型语言模型（Claude 3.5/4、GPT-4o等）
- 均使用**结构化生成**（非简单文本补全）
- 均内置**错误修复循环**（生成→运行→修复→验证）
- 均支持**流式UI**展示生成过程

### 2.3 "Vibe Coding"对前端职业的影响

**Vibe Coding = 用自然语言描述意图，AI负责实现细节**

这对高级前端开发者意味着：
1. **低价值编码工作加速贬值** —— 简单页面、CRUD界面、表单等
2. **高价值能力更加稀缺** —— 架构设计、性能优化、用户体验、AI编排
3. **新技能成为必须** —— Prompt工程、AI工具链集成、质量把控

**前端开发者的转型方向**
```
传统路径：需求 → 设计稿 → 手写代码 → 测试 → 部署
新路径：   需求 → AI生成初稿 → 人工审核调优 → AI辅助测试 → 一键部署
         ↑_________________________________________↑
              前端开发者的核心工作区间发生了转移
```

## 三、代码实践（10分钟动手）

### 实践：用Bolt.new的公开API理念，设计一个AI组件生成Prompt模板

虽然Bolt.new没有公开API，但我们可以学习它的**提示工程策略**，设计一个可在Claude/ChatGPT中使用的组件生成模板：

```markdown
## AI组件生成器 Prompt 模板

你是一个高级前端开发专家。请根据以下需求生成一个React组件。

### 需求描述
[在此描述组件功能，例如："一个带搜索过滤的商品卡片列表，支持价格排序"]

### 技术要求
- 框架：React 19 + TypeScript
- 样式：Tailwind CSS
- 图标：lucide-react
- 状态管理：React hooks（不使用外部库）
- 响应式：移动端优先

### 输出格式
1. 完整可运行的组件代码（单一文件）
2. Props接口定义（使用JSDoc注释）
3. 使用示例（展示如何传入数据）
4. 可访问性考虑（aria标签、键盘导航）

### 质量要求
- 代码需通过TypeScript严格模式检查
- 避免使用 any 类型
- 处理边界情况（空状态、加载状态、错误状态）
- 性能考虑：使用 useMemo/useCallback 避免不必要的重渲染

请开始生成。
```

**练习建议**：
1. 将上述模板复制到你的AI工具中
2. 填入一个真实业务需求（比如你正在做的项目中的某个组件）
3. 对比AI生成结果与你手写代码的差异
4. 记录：AI在哪些地方做得好？哪些地方需要人工修正？
