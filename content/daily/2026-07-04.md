## 今日主题

**实时协作+AI：Yjs 与 AI 编辑器的结合**

当 AI 开始参与内容创作（代码、文档、设计稿），编辑器不再只是“一个人打字”的工具，而是**多人 + 多 Agent 共同编辑的空间**。今天我们将学习 CRDT 库 Yjs 的核心原理，并思考如何把 AI 的生成/改写能力安全地接入协作文档，避免冲突、丢失和“AI 覆盖人类修改”的尴尬。

## 核心概念（15 分钟）

### 1. 为什么实时协作是 AI 原生应用的基础能力？

传统 AI 工具是“单用户会话”模式：用户输入 → AI 返回 → 用户决定是否采纳。而在团队场景中，AI 的产出需要被多人审阅、修改、追溯。

AI 原生编辑器需要同时解决三类问题：

- **并发编辑**：多人同时修改同一段内容，结果不能乱。
- **AI 参与度**：AI 的修改应该像另一个协作者一样，可被撤销、可被评论、可被合并。
- **意图可解释**：人类需要知道“这段文字/代码是 AI 改的，还是人改的”。

### 2. CRDT 与 Yjs 简介

CRDT（Conflict-free Replicated Data Type，无冲突复制数据类型）是一种数据结构，允许多个副本独立更新，最终自动达成一致，无需中心服务器强同步。

**Yjs 是目前前端最流行的 CRDT 实现**，特点：

| 特性 | 说明 |
|------|------|
| 基于文档模型 | 以 `Y.Doc` 为根，内部维护共享类型（`Y.Array`、`Y.Map`、`Y.Text`） |
| 二进制更新 | 所有变更编码为高效的二进制 `update`，便于网络传输和存储 |
| 无中心依赖 | 支持 WebSocket、WebRTC、IndexedDB 等多种 provider |
| 与编辑器绑定 | 提供 Quill、Monaco、ProseMirror、Slate 等绑定 |
| awareness | 内置光标、选区、用户状态同步 |

### 3. Yjs 的核心类型

```js
import * as Y from 'yjs'

const doc = new Y.Doc()

// 富文本协作最常用的类型
const ytext = doc.getText('content')
ytext.insert(0, 'Hello, ')
ytext.insert(7, 'collaborative AI!')

// 结构化数据
const ymap = doc.getMap('meta')
ymap.set('author', 'AI Assistant')
ymap.set('version', 1)

// 数组类型（适合块级文档）
const yarray = doc.getArray('blocks')
yarray.push(['heading', 'paragraph'])
```

### 4. AI 修改如何接入 Yjs？

把 AI 当作一个**虚拟协作者**，它的每次改写都通过 Yjs 的 transaction 提交：

```js
const applyAIEdit = (ytext, oldText, newText, reason = 'AI rewrite') => {
  const current = ytext.toString()
  if (!current.includes(oldText)) {
    throw new Error('AI 改写的原文已被人类修改，无法安全应用')
  }

  doc.transact(() => {
    const start = current.indexOf(oldText)
    ytext.delete(start, oldText.length)
    ytext.insert(start, newText)
  }, reason)
}
```

> ⚠️ 关键原则：**AI 不应该直接覆盖整篇文档**，而应该基于“原文片段”做最小替换，并在冲突时优雅降级。

### 5. AI 协作的三种安全策略

1. **Diff-and-Patch（差异补丁）**  
   AI 输出 `diff`，前端用类似 `diff-match-patch` 的算法定位修改位置，再转成 Yjs transaction。

2. **Suggestion Mode（建议模式）**  
   AI 的修改先作为“建议”插入，用户逐条接受/拒绝，不直接写入主文档。

3. **Snapshot + Branch（快照分支）**  
   AI 在文档快照上生成完整版本，用户选择合并到主分支，类似 Git 工作流。

### 6. 为什么 AI 编辑器需要 Awareness？

`awareness` 不仅同步光标，还可以：

- 显示“AI 正在编辑此段落”
- 标记 AI 建议的范围
- 显示其他用户对 AI 建议的反应（接受/拒绝/评论）

```js
provider.awareness.setLocalStateField('user', {
  name: 'AI Assistant',
  color: '#9b59b6',
  isAI: true,
})
```

## 代码实践（12 分钟）

### 实践目标

搭建一个最小化的 Yjs + Quill 协作编辑器，并模拟“AI 协作者”安全插入建议。

### 步骤 1：初始化 Yjs 文档与 Quill 绑定

```bash
npm install yjs y-quill y-websocket quill
```

```js
import * as Y from 'yjs'
import { QuillBinding } from 'y-quill'
import { WebsocketProvider } from 'y-websocket'
import Quill from 'quill'
import QuillCursors from 'quill-cursors'

const doc = new Y.Doc()
const provider = new WebsocketProvider(
  'wss://your-collab-server.example.com',
  'room-ai-editor',
  doc
)

const ytext = doc.getText('content')

const quill = new Quill('#editor', {
  modules: {
    cursors: true,
    toolbar: [
      [{ header: [1, 2, false] }],
      ['bold', 'italic', 'underline'],
      ['link'],
    ],
  },
  placeholder: '多人 + AI 一起编辑...',
  theme: 'snow',
})

const binding = new QuillBinding(ytext, quill, provider.awareness)
```

### 步骤 2：模拟 AI 协作者插入建议

```js
// 用 awareness 标记 AI 正在工作
provider.awareness.setLocalStateField('user', {
  name: 'AI 写作助手',
  color: '#8e44ad',
  isAI: true,
})

// AI 建议：把选中的句子改得更简洁
async function aiRewriteSelection() {
  const range = quill.getSelection()
  if (!range || range.length === 0) return

  const selectedText = quill.getText(range.index, range.length)

  // 模拟 AI 调用
  const rewritten = await callAI(`请简化以下句子：${selectedText}`)

  // 方案 A：直接应用（适合单人场景，高风险）
  // doc.transact(() => {
  //   ytext.delete(range.index, range.length)
  //   ytext.insert(range.index, rewritten)
  // })

  // 方案 B：作为建议插入（推荐）
  insertAISuggestion(range.index, range.length, rewritten)
}

function insertAISuggestion(index, length, suggestion) {
  // 用 Delta 保留原文并插入建议标记
  quill.formatText(index, length, {
    background: '#f5eef8',
    'ai-suggestion': suggestion,
  })

  // 在实际产品中，建议应存储到独立的 Y.Map 或 Y.Array，
  // 这样接受/拒绝/评论都能被所有客户端同步。
  const suggestions = doc.getArray('ai-suggestions')
  suggestions.push([{
    id: crypto.randomUUID(),
    index,
    length,
    original: quill.getText(index, length),
    suggestion,
    status: 'pending', // pending | accepted | rejected
    createdAt: Date.now(),
  }])
}
```

### 步骤 3：监听建议状态并同步

```js
const suggestions = doc.getArray('ai-suggestions')

suggestions.observe(() => {
  renderSuggestionList(suggestions.toArray())
})

function acceptSuggestion(id) {
  const item = suggestions.toArray().find(s => s.id === id)
  if (!item) return

  doc.transact(() => {
    ytext.delete(item.index, item.length)
    ytext.insert(item.index, item.suggestion)
  }, 'accept-ai-suggestion')

  item.status = 'accepted'
}

function rejectSuggestion(id) {
  const item = suggestions.toArray().find(s => s.id === id)
  if (!item) return
  item.status = 'rejected'
}
```

## 思考题（3 分钟）

1. 如果两个用户同时接受了同一条 AI 建议，Yjs 的 transaction 会如何表现？是否需要额外幂等处理？
2. AI 的改写粒度应该多大？是按段落、按句子，还是按字符？不同粒度对协作体验有什么影响？
3. 在 AI 原生编辑器中，如何设计“撤销”？应该撤销人类的输入、AI 的建议，还是整个 transaction？
4. 如果 AI 在后台持续生成内容，awareness 状态应该如何设计，才能既不打扰用户，又让他人知道 AI 在参与？
