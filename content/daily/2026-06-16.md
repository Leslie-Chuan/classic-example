## 核心概念（15分钟阅读与回忆）

### 1. MCP协议：AI与工具之间的「通用语言」

- **核心定位**：Model Context Protocol 是 AI 应用与外部工具/数据源之间的标准通信协议
- **三种能力模型**：
  - **Tool**：AI 主动调用的函数（如执行命令、查询天气）
  - **Resource**：AI 只读访问的数据源（如代码文件、文档）
  - **Prompt**：可复用的提示词模板
- **安全设计**：权限粒度控制、沙箱执行、用户确认机制

> 💡 回忆一下：你当时搭建的第一个 MCP Server 是什么功能？如果现在重写，会有什么不同？

### 2. AI Coding Agent 的架构本质

- **Agent Loop**：感知(Perception) → 思考(Reasoning) → 行动(Action) → 观察(Observation)
- **Tool Use 机制**：LLM 通过结构化输出（如 JSON/Function Call）触发外部工具
- **上下文管理**：滑动窗口、摘要压缩、RAG 增强、长对话策略
- **安全沙箱**：文件操作隔离、命令执行白名单、超时与资源限制

### 3. Prompt Engineering 的工程化思维

- **结构化 Prompt**：Chain of Thought、ReAct、Self-Consistency
- **前端场景专用**：组件描述模板、代码审查 Prompt、System Prompt 角色设计
- **工程化管理**：版本控制、A/B 测试、Prompt 库建设

### 4. AI辅助代码质量工作流

- **代码审查**：自动化坏味道识别、安全漏洞扫描
- **测试生成**：单元测试 + E2E 的 AI 辅助编写
- **重构建议**：基于 AST 的智能重构方案
- **文档维护**：代码变更自动同步文档

### 5. AI时代的开发工作流重构

- **人机协作模式**：从「人写代码」到「人设计 + AI 实现 + 人审查」
- **工具链整合**：Cursor / Copilot / Claude Code / WindSurf 的差异化定位
- **新角色认知**：开发者从「实现者」向「架构师 + 质量守门人」转变

#### A. MCP 开发能力
```typescript
// 自检题：下面这段代码是一个 MCP Server 的 tool 定义，请指出潜在的安全问题
const tools = [{
  name: "execute_command",
  description: "执行系统命令",
  inputSchema: {
    type: "object",
    properties: {
      command: { type: "string", description: "要执行的命令" }
    },
    required: ["command"]
  }
}];
```

**参考答案要点**：
- 没有命令白名单限制（`rm -rf /` 可以直接执行）
- 没有超时控制（可能导致无限挂起）
- 没有用户确认机制（AI 可以直接执行危险操作）
- 没有输出长度限制（可能导致上下文爆炸）
